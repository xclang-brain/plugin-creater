# 手順を直したのに古いまま働いている人を、まとめ役が名前で見つけられる

## 誰に、どんなメリットがあるか

社内で助手の手順を配っているまとめ役が、直した手順がまだ届いていない社員を、聞いて回らずに名前で見つけられ、社員は古い手順で仕事を進める失敗を避けられる。

## 誰が、どの場面で、何に困っているか

「助手」は、社員の仕事を手伝う人工知能のソフトです。「手順の束」は、助手に仕事の進め方を教える説明をひとまとめにしたものです。

まとめ役は、社内の束の置き場（共有フォルダのようなもの）から、全員に束を配っています。束を書いて直す「作り手」は、まとめ役本人のことも、別の人のこともあります。

ここでは3つの言葉を分けて使います。「配り直す」は、作り手が直した束を置き場に置き直すことです。「入れ替える」は、社員の手元の古い束を新しい束に替えることです。「届く」は、新しい束を社員の助手が実際に使い始めることです。

困るのは、直した中身が届いたかが分からないことです。助手は、新しい束を取り込むかどうかを、中身ではなく束に付いた版の番号で決めます。作り手が番号を新しくし忘れると、中身を直しても届きません。置き場から自動で入れ替える設定は、初めは止まっています（オフ）。

さらに、番号を新しくしても届かない不具合が、別々に何件も報告されています。助手の画面には新しい版と出るのに、助手が実際に使うのは古い中身のままで、警告も出ません。まとめ役は届いたと思い込み、社員も古い手順で資料などを作っていることに気づきません。

## このアイデアで何が良くなるか

これはまだアイデアで、作って使ったものではありません。

今は、まとめ役が全員に「直した手順になっていますか」と聞くか、信じるしかありません。でも本人も古いと気づいていないので、聞いても正しい答えは返りません。

このアイデアが形になれば、束を配り直した日に、古いままの人の名前が一覧で分かります。その後も毎週、同じ確かめが続きます。まとめ役は、その人にだけ声をかければ済みます。社員には「何を、なぜ直したか」が一文で届くので、入れ替える意味が分かり、自分から入れ替えられます。

## どう動くか

1. 配る束の中身から「目印」を作ります。目印は短い文字の並びで、中身が1文字でも変われば別の並びになります。違う中身で偶然同じになることは、ほぼありません。
2. 各社員のパソコンで、助手が実際に使っている束からも同じ作り方で目印を作り、まとめ役のところへ集めます。
3. 配った目印と比べ、目印が違う人と、名簿に載っているのに束が入っていない人を、名前つきで示します。
4. 目印が違う人には、何をなぜ直したかを一文で添えて、入れ替えを頼みます。

版の番号は見ません。中身を比べるので、番号の新しくし忘れも、届かない不具合も見逃しません。

## 似たものとの違い

- パソコン管理ソフトの「フリート」（会社が社員のパソコンの中身を調べて一覧にするソフト）は、助手の束を集めて目印も取れます。ただ、公式の説明には、古い人を示す働きも、本人に直した理由を知らせる働きも書かれていません。
- 「エンドア・ラボ」の一覧の機能は、パソコンで使われている束を、名前や安全面の危うさで並べます。中身の目印は扱いません。
- 助手を作る会社の集計の機能は、人ごとにどの束を何回使ったかを数えます。数えるのは回数で、中身ではありません。
- 束を入れるときに、置き場から運ばれるあいだに書き換えられていないかを目印で確かめる仕組みもあります。ただ、一人のパソコンの中だけの確かめで、全員の分を比べません。
- 会社のブラウザ（インターネットを見るソフト）の追加機能が人ごとにどの版で入っているかを見る報告もあります。見るのは版の番号です。

全員の束の目印を集めて、配った目印と比べ、違う人に理由を添えて知らせる。この形をすべて持つものは、調べた範囲では見つかっていません。

## よくある質問

**作り手が版の番号を必ず新しくすれば、済むのではありませんか。**
番号を新しくしても届かず、警告も出ないという報告があります。心がけだけでは、誰の助手が何を使っているかは分かりません。

**不具合が直れば、要らなくなりますか。**
番号で決める仕組みと、自動の入れ替えが初めは止まっていることは、不具合ではなく決まった作りです。不具合の報告も、一件は「対応しない」で閉じられ、一件は直っていません。

**一覧は、どこで誰が見ますか。目印はどう集めますか。**
まとめ役が見る形を考えていますが、見る場所と集め方はまだ決めていません。会社のパソコン管理ソフトで集めれば社員の操作は要らない見込みですが、情報システムの部署の手を借りるかもしれません。

**手元で書き足した人と、本当に古い人を見分けられますか。**
今の形では見分けられず、どちらも「違う」と出ます。見分け方は、まだ決めていません。

**毎週の知らせは、うるさくありませんか。**
知らせが行くのは、目印が違う人だけです。入れ替えれば止まります。入れ替えない人に何度送るかは、まだ決めていません。

**「何をなぜ直したか」の一文は、誰が書きますか。**
作り手が、配り直すときに書く形を考えています。書き忘れたときの扱いは、まだ決めていません。

**監視のように受け取られませんか。**
集めるのは束の目印だけで、社員の資料や仕事の中身は集めません。社員への説明と了解の取り方は、まだ決めていません。

**会社のパソコン管理ソフトを組み合わせれば、同じことができませんか。**
目印が違うパソコンを数えることは、できる見込みがあります。ただし、そのソフトの係の人が、束が直るたびに正しい目印を打ち込み直す必要があり、理由を本人に届ける部分もありません。

**なぜ直した理由まで添えるのですか。**
別の分野（病院の手術のチェック表）の報告ですが、理由が分からないまま入った決まりは形だけになりやすいとされています。

- 助手：Claude Code（クロード・コード）。手順の束：plugin（プラグイン）。置き場：marketplace（束の配布場所）。版の番号：plugin.json（束の設定ファイル）の version（版）。目印：ハッシュ（中身から作る要約の文字列）。
