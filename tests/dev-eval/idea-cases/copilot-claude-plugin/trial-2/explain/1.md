# 新人を教える先輩が、新人の分かっていない所から教え始められる

## 誰に、どんなメリットがあるか
人工知能の助手を使って仕事をする新人を教える先輩の開発者が、新人の分かっていない所を一つずつ聞き出さなくても、その所だけを教えられるようになります。

もう一つのメリットとして、新人は、助手に任せきりにせず、自分で理由を考える癖がつきます。

## 誰が、どの場面で、何に困っているか
新人の開発者は、助手に頼んでプログラムを書くことが増えました。
新人は、そのプログラムを先輩に見せて、確かめてもらいます。
このとき、新人が、なぜそう書いたのかを分かっていないことがよくあります。
新人を教える人の約8割が、負担が増えたと答えています。
いちばん多い悩みは、新人がプログラムの仕組みや理由を分かっていないことで、約6割が挙げています。
理由を助手に任せきりにする新人も、半数近くいます。
新人の理解は完全だと思える先輩は、2割に届きません。
そこで先輩は、「ここはなぜこうしたの」と一つずつ聞いて確かめており、時間がかかります。

## このアイデアで何が良くなるか
今は、先輩が新人と話しながら、分かっていない所を探しています。
この仕組みを使うと、先輩には、新人の理由が助手の理由と食い違う所と、新人が理由を書けなかった所だけが知らされます。
先輩は、探す手間をかけずに、そこから教え始められます。
先輩が書いた注意はファイルに残り、新人の助手が次の作業で読みます。
このため、先輩は同じ注意を何度もくり返さずに済みます。
新人は、自分で理由を書かなければ、先輩に確かめを頼めません。
このため、新人は自分で考える癖がつきます。
教える側は、新人にまず自分で調べさせることを望んでおり、この形はその望みに合います。

## どう動くか
1. 新人が助手と作業すると、助手は、なぜそのやり方を選んだかを書き残します。プログラムのどこについての理由かと、日付も書きます。書く先は、特定の製品がなくても開ける、文字だけのファイルです。
2. 先輩に見せる前に、新人は、新しく書いた所と直した所のうち主な所ごとに、自分の言葉で理由を書きます。この仕組みは、書き終えるまで助手の理由を新人に示しません。
3. この仕組みが、新人の理由と助手の理由を比べます。やり方やわけが違えば「食い違い」とし、言い方が違うだけなら食い違いとしません。
4. 食い違う所と書けなかった所だけが、先輩がプログラムを確かめる画面の、その行の横に出ます。この画面は、書き換えの一覧を見ながら行ごとに意見を書ける画面です。
5. 先輩は、そこについて新人に教え、注意を書きます。注意は、どこについてかといっしょにファイルに残り、新人の助手が次から読みます。文字だけなので、チームで助手の製品をそろえる必要がありません。

助手の理由が、実際に選んだ理由ではなく、あとから作った説明（後付け）のこともあります。
その場合も食い違いとして先輩の目に入り、先輩が見るべき所であることは変わりません。

## 似たものとの違い
- 新人に問題を出す製品がいくつもあります。新人が自分の書き換えを分かっているかを確かめます。これらは、合格か不合格かを本人に返すだけで、先輩に教える所を示しません。
- 助手の理由を見せたり、ファイルに残したりする製品もあります。これらは、新人の言葉と比べません。
- プログラムの確かめだけをする人工知能の製品には、先輩の指摘を覚えるものがあります。指摘を読むのはその製品だけで、新人の作業を手伝う助手は読みません。
- 学ぶ人の説明を手本と比べて採点する研究や、助手の答えを隠して先に考えさせる研究もあります。これらは先輩に食い違いを示したり、注意を残したりしません。
- 助手の説明を見たあとで自分の言葉で書き直そうと勧める記事は、順番が逆で、比べる仕組みもありません。
- 「先に自分で書く」「食い違いだけを示す」「注意を残して助手が読む」の三つをそろえたものは、見つかっていません。

## よくある質問
- 問：比べるのは人工知能ですか。
  答：言い方の違いを見分ける必要があるため、文の意味を読める人工知能で比べることを考えています。細かい作りは決まっていません。
- 問：外れの知らせが多いと、先輩の手間がかえって増えませんか。
  答：増えます。外れの割合を確かめるまで、時間が減るとは言えません。
- 問：本当に先輩の時間は減りますか。
  答：まだ確かめていません。新人の手間は増えるので、差し引きで得かも確かめる必要があります。
- 問：新人は助手の理由を見てしまいませんか。
  答：会話の中で助手が理由を話すことや、ファイルを開くことは防げません。新人が助手に理由を書かせることも防げません。
- 問：新人と助手が同じように間違っていたら。
  答：食い違いが出ないので、見逃します。
- 問：「主な所」の大きさと、書けなかった所の決め方は。
  答：空欄は書けなかった所に含みます。大きさと、中身が薄い所の扱いは決まっていません。
- 問：古い注意や間違った注意は、だれが整理しますか。
  答：決まっていません。
- 問：作る費用、期間、作り手は。社内向けですか、売る製品ですか。
  答：どれもまだ決まっていません。
- 問：書いた理由が新人の評価に使われませんか。
  答：決めていません。試すときに確かめます。

## 言葉と出典
- 助手：人の頼みを受けて、プログラムを書いたり直したりする人工知能。
- この仕組み：このアイデアで作るもの。既存の製品とは別です。
- 文字だけのファイル：特定の製品でなくても開けるので、ほかの会社の助手にも読ませやすいファイル。
- 後付け：助手が実際に選んだ理由ではなく、あとから作ったもっともらしい説明。
- 約8割、約6割、半数近く、自分で調べさせる望み：教える人1,004人への調査。負担が「大幅に増加した」26.1%と「やや増加した」51.8%。仕組みや根拠を本人が理解していない61.4%（いちばん多い悩み）。根拠を人工知能に丸投げする45.8%。研修への期待「まずは自力で調べさせる」38.6%。
- 2割に届かない：先輩の開発者への調査「Only 16% of senior developers say junior engineers fully understand the AI-generated code they submit.」（訳：新人が出す人工知能の書いたプログラムを、新人が完全に理解していると答えた先輩は16%だけ）。
- 二つの調査の正式な名前と所在は、元の資料で確かめる必要があります。
- 似たもの：
  - 新人に問題を出す製品：PR Guard、Commit Comprehension Gate、sphinx-ci、quiz-gate、branch-quiz、understando。
  - 理由を見せる・残す製品：Claude Code という助手の、理由を説明しながら作業する設定（Explanatory。理由は会話にだけ出ます）、Decision-Linked Development、SpecStory（助手との会話を保存）、git-ai（助手が書いた所を記録）。
  - 確かめ専用の人工知能の製品：CodeRabbit の、指摘を覚える機能（Learnings）。
  - 研究（論文の公開場所 arXiv の番号）：Oli ほか 2501.10365、Lekshmi-Narayanan ほか 2605.21614、Kazemitabaar ほか 2410.08922、From Junior to Senior 2602.00496。
  - 記事：AI Coding Tip 021（https://maxicontieri.substack.com/p/ai-coding-tip-021-avoid-comprehension）。
- まだ確かめていないこと：食い違いを見分ける正しさ、外れの割合、先輩の教える時間が減ること、書く所を絞る基準、比べる仕組みの細かい作り。同じ考えの特許があるかは、一部の資料が開けず確かめきれていません。
