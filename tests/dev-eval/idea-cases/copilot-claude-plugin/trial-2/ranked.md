# 通った案の比べ

まとめ方：組をまたいで、同じ人に同じメリットを同じ仕組みで生む案を探した。重なる案はなかった。近いのは次の二組だが、まとめなかった。
- c07-9 と c08-4：どちらも先輩と若手の案である。ただし、c07-9 は新人に教える時間の話で、c08-4 は先輩が自分の変更の分かりにくい所を知る話である。メリットが違う。
- c09-6 と c10-5：どちらも持ち主が変わった道具の案である。ただし、c09-6 は知らない人の手に渡った道具を止める話で、c10-5 は引き継いだ同僚が直せるようになる話である。メリットも仕組みも違う。

並べ方：二人の判定がともに3つを認め、困っている人の多さと重さの両方に出典がある案を上にした。価値を「条件つき」「弱い」「ぎりぎり」とした判定がある案を下にした。

まとめた後の案の数：10

## 1 c07-9 新人が自分の言葉で書いた理由と助手の理由の食い違いだけを、先輩が見られる
- 誰にどんなメリットがあるか：新人を教える先輩は、分かっていない所を一つずつ聞き出さずに、食い違う所だけに教える時間を使え、新人は自分で理由を言葉にする癖がつく。
- 新しさ：書いた人に問うて合否を出す道具はあるが、先輩の画面に食い違う箇所を出し、指摘を残す形はどこにもない。
- 役立つか：先輩の負担が増え、新人が助手の書いたものの根拠を分かっていないことに、大きな調査の出典がある。
- 価値：教える人の約8割が負担が増えたと答え、いちばん多い悩みは約6割にのぼる。困る人が多く、重い。
- いちばん近い先行例：PR Guard https://www.producthunt.com/products/pr-guard/reviews
- 根拠：c07 judge-1-r3、judge-2-r3 の案9（329 の 1,004人、51.8%と26.1%、61.4%、45.8%。330 の 16%）。prior-r3-4。

## 2 c05-5 まとめ役が、直した手順の束が全員の手元で入れ替わったかを、版の名前に頼らずに確かめられる
- 誰にどんなメリットがあるか：手順の束を配るまとめ役は、古い手順のまま働く人を名指しで見つけて直せ、社員は直す前の手順で結果を出す失敗を防げる。
- 新しさ：中身の目印を作る道具はあるが、比べるのは置き場の中か手元だけで、人ごとの手元の中身を集めて配った中身と比べるものはない。
- 役立つか：今の道具は中身でなく版の名前で比べ、社内の置き場の自動の更新は初めから切れている。このことに出典がある。
- 価値：画面は新しい版なのに古い中身が動くという報告が、別々に何件も出ており、束を配るどのチームにも起こりうる。
- いちばん近い先行例：AgentSkills CLI の lock の形 https://mysticmind.github.io/agentskills-cli/reference/lock-files
- 根拠：c05 judge-1-r3、judge-2-r3 の案5（research deep-18 の 190、#39202、#39751、#90420、#44276）。prior-r3-3（Hermes、plugin_loaded）。古い結果による被害の大きさは仮説。

## 3 c08-7 係の人が、初めての参加者がくり返しつまずく決まりを、手で探さずに知れる
- 誰にどんなメリットがあるか：参加の手引きを管理する係の人は、初めての参加者が何度も止められる決まりを観察せずに知れ、手引きの直す所をすぐ選べる。
- 新しさ：決まり全体の破られ方を数える画面はあるが、決まりごとに初めての人と慣れた人を比べ、手引きの箇所と結ぶものはない。
- 役立つか：係の人が同じ説明をくり返して時間を失い、つまずきを手で探して手引きを直していることに出典がある。
- 価値：手引きと実際の流れが大きくずれるプロジェクトは約68%あり、新しい参加者の壁は広く調べられた困りごとである。
- いちばん近い先行例：Qodo の Review Standards の分析画面 https://docs.qodo.ai/governance/rule-enforcement/analytics.md
- 根拠：c08 judge-1-r3、judge-2-r3 の案7（Zephyr のコミット 2023、salsa-ci !476、Elazhary ほか 2019、Steinmacher ほか 2014、Rebouças ほか）。往復が減る幅は仮説。

## 4 c04-4 効いていない書き足しを見つけて、手順書を短くできる
- 誰にどんなメリットがあるか：書き足しで手順書が長くなった専門家は、出来を落とさずに、短く読みやすく、助手を動かす費用も少ない手順書にできる。
- 新しさ：役に立った回数を数える研究や「外せ」と勧める道具はあるが、記録で外す候補を絞り、点で確かめてから外す手段はない。
- 役立つか：書き足すと出来が下がる例と、出来を保って費用を約5分の1にした例に出典がある。
- 価値：書き足しで正しくできる割合が72%から22%に下がった例があり、良くなる幅が大きい。困っている人の多さは仮説である。
- いちばん近い先行例：ACE https://arxiv.org/html/2510.04618
- 根拠：c04 judge-1-r1、judge-2-r1 の案4（E18 の 176、180）。prior-r1（skill-creator、loki-mode、tianpan の記事）。

## 5 c08-4 先輩が、自分の変更の「読んで分からない箇所」を、遠慮なしに知れる
- 誰にどんなメリットがあるか：変更を若手に読んでもらう先輩は、若手が面と向かって言いにくい分からない箇所を名前なしで受け取り、自分しか分からない所に早く説明を書き足せる。
- 新しさ：答えられなかった問いを書き手に返す仕組みは文書にはあるが、変更について名前なしで作者に返すものはない。
- 役立つか：若手が先輩のコードを確かめにくいこと、機械になら気兼ねなく頼めることに出典がある。
- 価値：知識が一人に偏ると、その人が抜けたときに失われる。分かりやすさを求める指摘は83.9%が取り込まれ、届けば直される見込みが高い。
- いちばん近い先行例：kapa.ai の Coverage Gaps https://docs.kapa.ai/analytics/coverage-gaps
- 根拠：c08 judge-1-r3、judge-2-r3 の案4（SSW Rules、341、Hajari ほか 2023、Oliveira ほか 2024）。prior-r3（CodeAnt）。書かれる箇所が増える幅は仮説。

## 6 c01-2 電話での許しを自分の決まりに頼らず、道具が守ってくれる
- 誰にどんなメリットがあるか：外出先から電話で助手に答える開発者は、急いでいても見きれない重い変更を許してしまうことがなくなり、見きれる変更はその場で通せる。
- 新しさ：電話で許せる道具はどれも危ない操作でも同じボタンを出し、中身が収まらないときに「進める」を出さない道具はない。人が守る決まりを道具が守る点が中心である。
- 役立つか：電話では30行ほどしか見られないこと、縮めた表示で判断が悪くなること、確かめられる形を求める要望など、別々の出典が重なる。
- 価値：取り返せない操作は重く、電話で答える道具が多く出ている。ただし、防げる失敗の数は仮説で、一人の判定は条件つきで認めた。
- いちばん近い先行例：claude-ntfy-hook https://adrian-gomez.github.io/claude-ntfy-hook/
- 根拠：c01 judge-1-r3、judge-2-r3 の案2（Codex Goes Mobile、Verdent、要望 #101792、Fink と Papismedov）。prior-r3（CodeVibe）。

## 7 c10-5 持ち主がいなくなった道具を、引き継いだ同僚が捨てずに直し続けられる
- 誰にどんなメリットがあるか：同僚が作った小さな道具を引き継ぐ、プログラムを書かない社員は、道具を捨てずに使い続けられ、壊れたときに前の担当者を探さずに自分で直せる。
- 新しさ：去る人に問うて知識を残す製品や、持ち主の名前を付け替える仕組みはあるが、引き継ぐ人に本当の用事で一度直させ、直せる人を生む形はない。
- 役立つか：人の作った表を読む人が当て推量をし、あきらめ、作った人に戻るという観察と、詳しい人の案内で理解が上がる数に出典がある。
- 価値：社員の自作の道具が1社で13,000件を超える例がある。捨てられる数は仮説で、一人の判定は価値を弱いとした。
- いちばん近い先行例：Sensay AI Offboarding https://blog.sensay.io/how-sensay-ai-offboarding-works
- 根拠：c10 judge-1-r2、judge-2-r2 の案5（Ragavan ほか CHI 2021、LACY の 83%と57%、Hermans ほか 2011、146、292）。prior-r1（CoE Starter Kit）。

## 8 c05-1 まとめ役が、ふつうの文章で書いた決まりが一人ひとりの助手に本当に読まれているかを知れる
- 誰にどんなメリットがあるか：チームの決まりを配るまとめ役は、決まりが手元に出ていない人を一人ずつ聞かずに見つけて直せ、社員は決まりのない助手で知らずに働くことがなくなる。
- 新しさ：人ごとに読み込まれた決まりの文を、配った文と比べる先行例はない。近い要望は「実装しない」で閉じられている。
- 役立つか：チームの決まりが仲間の画面に出ないという声と、読み飛ばしても知らせが出ないことに出典がある。
- 価値：決まりが欠けても誰も気づかないという重さには出典があるが、困っている人の多さの根拠は声1件と要望1件にとどまる。
- いちばん近い先行例：InstructionsLoaded に中身の要約値を足す要望 #30897 https://claudeissues.com/issue/30897-feature-request-instructionsloaded-hook-batch-event-content-hashes-and-context-i
- 根拠：c05 judge-1-r3、judge-2-r3 の案1（E25 の 269、Cursor の議論）。prior-r3（Fleet、AI Security Gateway）。

## 9 c10-4 困りごとの伝え方が身につき、一度で合う道具ができる
- 誰にどんなメリットがあるか：何をどう頼めばよいか分からない、プログラムを書かない人は、頼み直しが減り、次の困りごとでは一度の頼みで合う道具を作れるようになる。
- 新しさ：作る前に問い返す製品は一回目の出来を良くするだけで、伝える力を本人に残す形はない。
- 役立つか：道具作りの詰まりは困りごとを言葉にする力だ、という作品の声に出典がある。
- 価値：困りごとの重さには根拠があるが、困っている人の多さと頼み直しが減る幅は仮説である。
- いちばん近い先行例：v0 の確認の質問 https://www.createwith.com/tool/v0/updates/v0-adds-clarifying-questions-before-generating-web-apps
- 根拠：c10 judge-1-r1、judge-2-r1 の案4（E11 の 144、166、arXiv 2304.06597）。prior-r1（Promptly）。

## 10 c09-6 持ち主が変わった道具を、選んだ人が読み直すまで止めておける
- 誰にどんなメリットがあるか：一覧の道具を使うチームは、知らない人の手に渡った道具を、気づかないまま使い続けずに済む。
- 新しさ：持ち主の変化を見張る先行例は知らせるだけで、選んだ人が読み直すまで今の版のまま止めるものはない。
- 役立つか：放っておかれた置き場の道具が乗っ取られた実例の報告に出典がある。
- 価値：乗っ取られた道具は入れた人と同じ権限で動くので重いが、助手の道具での件数はなく、一人の判定は価値を弱いとした。
- いちばん近い先行例：Socket の Unstable Ownership の警告 https://socket.dev/alerts/unstableOwnership
- 根拠：c09 judge-1-r1、judge-2-r1 の案6（Holzbauer ほか、E57 の 378、E58 の 390、Zahan ほか）。prior-r1-2（Under New Management）。持ち主が変わる頻度は仮説。
