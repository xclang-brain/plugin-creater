# 3回目の試行の結果（GitHub Copilot CLI と Claude Code で使えるプラグイン）

「誰にどんなメリットがあるか」を軸に直した make-idea（柱3でどの作品にも「誰にとって恩恵があるのか」を問う、本質と案を「誰に・どんなメリットが」で書く、通った案を固める、説明の最初にメリットを1文で書く）を、既定の設定で最後まで動かした結果である（2026-10-29、Claude Code の置き換えた版、メインは claude-opus-5-5、ユーザー役は claude-sonnet-5-5）。ユーザーの答えは、ユーザー役の AI が出した。止まらずに1回で最後まで進んだ。

## 結果

- 壁打ちした100案のうち、通ったのは10案（2回目の試行は1案）。ユーザー役が3つを選び、説明を書いた（`explain/1.md`〜`3.md`）。
- 別のセッションの AI による良さの判定（`review.json`。設計 7.2）：
  - `explain/1.md`「新人を教える先輩が、新人の分かっていない所から教え始められる」：合格（新しさ、役立つか、価値、誰にどんなメリットか、人が読んで分かる日本語の5つとも満たす）。
  - `explain/2.md`「手順を直したのに古いまま働いている人を、まとめ役が名前で見つけられる」：不合格（ほぼ同じ既存の製品がある、価値の大きさに根拠がない、本文に分からない言葉と詰めすぎた文がある）。
  - `explain/3.md`「先輩が、若手の言えない『ここが分からない』を、気まずさなしに受け取れる」：不合格（新しさの中心が、読み手が1人の場面で成り立たない、価値の大きさに根拠がない）。
- プロセスの中身の判定（同じ `review.json`）：6項目（なぜなぜ分析、掘り下げ、壁打ちの判定、先行例の調べ、誰にどんなメリットか、通った案の固め）をすべて満たす。
- 流れの試験の採点（`grade.json`。設計 7.1）：53項目のうち50項目が合格。不合格は次の3つ。
  - 掘り下げた306件のうち13件で、読んだ情報源が2つ（決まりは3つ）。
  - なぜなぜ分析の1つのまとまりの観点（c04 の a2）の14の節で、要望の報告などに、最初の問いを「なぜ求められているのか」と言い換えていた。
  - 柱3から後の2つの役（案を直す、振り返り）が、頼みの文にない `restriction.md` を読んだ。頼みの文に回のフォルダの場所があり、そこから読んだ。
- 採点は、入口が出した結果のあと、`combine` に `cd` してから `log.md` に書いた記録を読めるように採点を直して、採点し直したものである（直す前は、組を選んだ理由を判定の前に書いたかの項目が、6つの組で不合格と出た）。
