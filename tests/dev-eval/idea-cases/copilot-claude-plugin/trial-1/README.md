## 結果

- できたアイデア：「AI の申し送りを入れる前に、『AI なしの良い形』と並べて3つの形を比べる」（`explain/1.md`）。壁打ちした100案のうち、通ったのはこの1案だけだった。
- 別のセッションの AI による良さの判定（`review.json`。設計 7.2）：不合格。新しさは認めたが、役立つか（比べ方の要が決まっておらず、すぐ使える手順になっていない）と価値（中心の心配に根拠がない）を認めなかった。
- プロセスの中身の判定（同じ `review.json`）：なぜなぜ分析、掘り下げ、壁打ちの判定は満たす。先行例の調べは、特許を当たった組が少なく、満たさない（その後、先行例の記録に種類ごとの行を書かせ、採点に特許の項目を足した）。
- 流れの試験の採点（`grade.json`。設計 7.1）：46項目のうち44項目が合格。不合格は、形の外の本質1つに「なぜ」の連なりがないこと（E69）と、事件の記事や課題の報告などの16の節で、最初の問いを「なぜ評価（注目）されたのか」と言い換えていたこと。

## 途中で直したことと、続け方

- 柱2の後で止め、柱3を30件ずつのまとまりに分ける形に直してから続けた（掘り下げが多く、1体では読みきれないため）。
- 柱4の1組目の途中で止め、組を4組ずつの波で同時に試す形に直してから続けた（1組に約50分かかり、10組で8時間を超えるため）。
- クラウドの容器の再起動で2回止まり、そのたびに続きの回で続けた。続きはすべて make-idea の続き（REQ-075）で進んだ。
- 止まった回の呼び出しの記録は残らなかったので、`grade.json` は、5つの回の会話の記録から呼び出しを作り直して採点した。その後、入口は記録を途中でも書くようにした。
- 費用は、最後の回の分（約11ドル）しか記録に残っていない。
