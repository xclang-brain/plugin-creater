# 試験部門の Excel 結果から、最初に台へ戻す NG を1つ選ぶ

## ひとことで言うと
試験結果の Excel と試験仕様書の Word を読み、数十件の NG（不合格の項目）を「仕様書の上で同じ機能を見ている項目」ごとにまとめ（以下「束」）、最初に実機の台で再現させる候補1項目と理由1行を出す道具です。決めるのは担当者です。

## 誰が・どの場面で・何に困っているか
- 誰が：週1回ほど試験部門から結果の .xlsx（数百項目）を受け取る組み込みファームウェア（FW、機器の中で動くソフト）の担当。
- 場面：NG が数十件あり、どれから台で再現させるか決めるとき。
- 困りごと：項目 ID だけでは、別々に見える NG が同じ機能の不具合か分かりません。仕様書と1件ずつ照らす間は直し始められません（かかる時間はまだ測っていません）。

## 何が良くなるか
同じ機能の NG がまとまって見え、最も大きい束から始めれば、1回の再現で多くの NG の原因に近づける見込みです（仮説。まだ試していません）。

## どう動くか
担当者が自分の PC の端末（文字で命令する画面）で AI の道具を呼び出します。道具は GitHub Copilot CLI（GitHub 社）か Claude Code（Anthropic 社）のうち、会社が契約している方を1つ使います。
1. 初回だけ、AI が列の意味を推定し、担当者が確かめて設定ファイルに保存する。Excel は「項目 ID」「項目名」「判定」、Word の表は「項目 ID」「機能」「前提条件」の列。
2. AI が、NG の各項目をどの束に入れるかの案を一覧で出す。仕様書では同じ機能が「UART 受信」「UART受信処理」のように別の書き方になることがあり、それを1つの束名にそろえる。
3. 担当者が一覧（数十行）を全部見て、違うものを直す。直した後で、スクリプト（決まった計算をする小さなプログラム）が数える。
4. AI が候補と理由を出し、担当者が決める。

入力の見本（.xlsx の一部）
| 項目 ID | 項目名 | 判定 |
| --- | --- | --- |
| T-0412 | UART 連続受信 | NG |
| T-0415 | UART 1バイト受信 | NG |
| T-0733 | 電源断後の UART 再開 | NG |

出力の見本と分担
| 出力の項目 | 見本 | 誰が |
| --- | --- | --- |
| 束の案 | T-0412、T-0415 →「UART 受信」 | AI が案、担当者が全部確かめる |
| 束ね方があいまいな項目 | T-0733（仕様書で2つの機能） | AI が印、担当者が束を決める。決まるまで「未決」で、どの束にも足さない |
| 束ごとの件数 | 「UART 受信」12 件、「電源断の復帰」7 件 ほか（NG 計 34 件） | スクリプト |
| 候補と理由 | T-0415：最大の束「UART 受信」で、前提条件が2つ（常温、1回送信）と最も少ない | AI |
| 台に戻す項目 | （人が入れる） | 担当者 |

選び方の決まり（設定ファイルに書き、担当チームが話し合って変える）
- 最も大きい束：担当者が確かめた後の件数が最も多い束。
- 前提条件の数：仕様書の表の「前提条件」の欄に書かれた条件を1つずつ数える。「常温」も1つ、手順は1ステップを1つ。
- 同じ件数の束、同じ数の項目が2つ以上なら AI は並べて出し、担当者が選ぶ。台が空かないなどの事情があるときも担当者が選ぶ。

今の案の限界
- 機能をまたぐ共通の原因（ドライバ、割り込み、電源）は見えにくくなります。
- 新しく出た NG か、備考の現象メモは使いません。前から残る NG で最大の束がいつも同じになるおそれがあります。
- 条件の数が少なくても再現しにくいことがあります（例：-40℃）。条件ごとの重みを設定で付けられるようにするかは、試作で決めます。

## 似たものとの違い
HIL（実機をつないだ自動試験）の失敗をまとめる研究（Golagha ら、2019年）、試験管理の製品（Testomat.io、UiPath Autopilot）、Trunk（開発ツールの会社）の Claude Code 用追加機能は、どれも失敗のログや文面の似かたでまとめます。この案は仕様書が書く「どの機能を見ているか」でまとめます。

## 管理職にお願いしたいこと（順番どおり）
1. 試作の前に、データ送信の可否を情報システム部門（必要なら法務）に確かめてください。送られるのは NG の項目 ID・項目名と、仕様書の表の行（機能・前提条件の文、製品名や数値を含み得る）で、使う道具を通じて提供元へ届きます。確かめる点は、社内規程で出してよいか、提供元との契約で保存・学習に使われるか、今の契約で追加費用が要るか。伏せる仕組みは今の案にありません。
2. 送ってよい範囲が決まったら、試作の承認をお願いします。今お願いするのは試作までで、本番は試作の結果を見て改めて相談します。試作は社外に出してよい過去の結果か、製品名・数値を手で伏せた写しで行えます。担当者1人の日数の上限は課長に決めていただき、超えたら止めます。
3. 送れないと決まったら、作るのをやめます。残るのは NG を数えることだけで、Excel のフィルタで足ります。

試作で測ること
- 今の負担：担当者が2〜3週、選ぶのにかかった時間を記録。
- 当たり：過去2〜3週の結果で、AI の候補の束と担当者が実際に選んだ項目の束それぞれで、次の週に OK に変わった NG の数を数える。AI の側が同じか多ければ「当たり」。数えるのは担当者、基準を直すのはチーム。
- 作る工数と、様式が変わったときの手入れの時間。

そのほか：試験部門には、結果の列の名前をなるべく変えず、変えるときは連絡してもらう合意が要ります（誰から申し入れるかを決めてください）。

## 技術の補足
- 形：SKILL.md（AI の道具が読んで、そのとおりに手順を進める説明ファイル）と Python のスクリプト（openpyxl、python-docx を使い Office なしで読み書き）。業務 PC に入れる手続きの確認が要ります。
- SKILL.md と設定ファイル（テキスト）はチームの共有フォルダに置き、担当が替わっても直せるようにします。
- AI には全行でなく、必要な表の行だけを渡します。元のファイルは変えず、件数表は写しの新しいシートに書きます（Excel で開けます）。
- 同じ入力でも候補が回で変わり得ます（仮説）。両方の道具で同じに動くか、端末以外（Zed など）から使えるか、結合セル・複数シートは未確認です。
