# README の書き方

## 最大の目的

- README を読んだユーザーが、プラグインの概要と使い方をすぐに理解できること。
- 2026年10月、開発者からクリエイターの README が読みづらいと言われ、この目的で一から作り直した。それまでの README の中身は次のとおりだった。
  - 使い方の前に、インストールと準備（試験的機能、読み込みの確認の4つの選択肢と意味）の長い説明があった。
  - 何ができるかは、初めの2文だけで、具体的な例がなかった。

## 書く順番

1. できること：何を伝えると、何ができあがるか。具体的な例を1つ添える（クリエイターでは、週報のプラグインの例と、会話例へのリンク）。
2. 使い方：番号付きの手順で書く。初めに「使う前に準備を1回行う」ことだけを書き、準備の中身は後に回す。
3. 使うために要る準備、知っておくこと（答えが来ないとき、記録の置き場所など）、うまく始まらないとき。

- 生成プラグインの README も、初めの2つの節を「できること」と「使い方」にしている（仕様 REQ-050）。
- 仕様書が README に書くと決めている内容は、順番を変えても消さない。

## 言葉

- チャットでユーザーに話す言葉（`skills/make-plugin/references/words.md` の表）にそろえる。README を読んでからチャットで話すので、同じものを同じ言葉で呼ぶ。
- 呼び名は、初めて出るところで説明する。文の書き方と点検は、[人間と AI のコミュニケーション](communication.md) の「書くときの型と、送る前の点検」を当てはめる。
