# ナレッジ索引

- [AI エンジニアリングの5分類](ai-engineering.md) — プロンプト／コンテキスト／ハーネス／ループ／グラフ。提唱された順と、互いの関係
- [ハーネスエンジニアリングの目的と人間の役割](harness-purpose.md) — 目的はヒューマン・オン・ザ・ループ。監督のためエージェントの振る舞いを可視化する。ハーネスは AI が知らないことを人間が対話を通じて作る。Web管理画面は性能の低いモデルでは失敗しやすいので、クリエイターが土台を用意し、作り込みを支援する
- [スキル（GitHub Copilot CLI）](skills.md) — 本質は description（公式は「何をするか」と「いつ使うか」を書くよう勧める）。Markdown・スクリプト・アセット・リファレンスで構成し、推論の要否で Markdown とスクリプトに分ける。フロントマターの決まりは2つあり、Copilot 固有の項目は Agent Skills の参照実装で不合格になる。コマンドは `/<プラグイン>:<スキル>` で、`-p` では展開されない。読むとスキルのフォルダの全ファイルが Related files として届く（1.0.102 の実測）
- [MCP](mcp.md) — 外部システムと安全にデータをやり取りする役割に特化。ローカルの操作はスキルへ移行
- [カスタムエージェント（GitHub Copilot CLI）](custom-agents.md) — マルチエージェント構成の1エージェントを定義。必須は description だけ。権限は tools の別名（read、edit、execute など）で絞り、別名はモデルの族でツール名が変わる。Copilot CLI ではサブエージェントのツールが親の tools に絞られる（Claude Code は絞られない）。tools に skill を書かなければ、サブエージェントに skill は載らない（1.0.102 の実測）。プラグインからメインのエージェントのモデルは決められず、Auto だとサブエージェントのモデル指定も効かない。model のリストは 1.0.102 で効いたが、公式の models との食い違いは残る。サブエージェントは ask_user を持たず、指示ファイルも include-custom-instructions なしでは受け取らない。システムプロンプトはモデルの族ごとに分かれ、聞き取りと逆向きの指示もある。退役したモデルの事実に頼らない。ツールが1つもないエージェントは Claude Code が起動を断る（todo の置き換え先の TodoWrite がない）。Claude Code は、サブエージェントが名前の頭が ANALYSIS・REPORT・SUMMARY・FINDINGS の .md を書くのを断る
- [マルチエージェントの強み](multi-agent.md) — コンテキストウィンドウの最適化、処理速度、AI クレジットの最適化。並列で動かすと利用枠の上限に当たるので、メモを残して中断に備える。変異の試験は写しで行い、読ませないフォルダは git の出力からも外す。Workflow は、AI が止めたときは resumeFromRunId で続きから進められた（指示を変えていないエージェントの結果を使い回す。ほかの止まり方は未確認）。途中の結果は journal.jsonl で読める。見直しは観点ごとに分け、指摘は別のエージェントに反証させる（37件中12件が外れた）
- [ハーネスの置き場所](harness-placement.md) — 決められた場所に置くことで効果を発揮。GitHub リポジトリでは `.github` 内
- [プラグイン](plugins.md) — ハーネス群の配布・インストールの仕様。Agent Plugins 1.0.0 はスキルと MCP のみ、Copilot CLI はそれ以外も同梱できる。Copilot CLI 固有の部品（エージェント、コマンド、ルール、フック、LSP、エクステンション）は `com.github.copilot/` に置けば Agent Plugins と両立する。`$schema` は完全一致で形式が決まり、書き間違えると黙って以前の形式になる。mcp.json は閉じた形で type が必須。マーケットプレイスを通した手元のフォルダは live で入る（1.0.102 の実測）
- [画面と Copilot CLI のつなぎ方](dashboard-integration.md) — Web管理画面とつなぐ候補はフック、MCP サーバー、エクステンション。フックで状態を受け取り、ツールを拒み、エージェントを止められる。時間切れは素通りになる。エクステンションは試験的で、`--experimental` で起動する。読み込みのときに確認が出て、`-p` では答える人がいないので許可の指定が要る。エージェントの起動・取り消し、モデルの上書き、フック、許可の求めは 1.0.102 の実機で動いた。ツールの処理が投げた例外の理由はモデルに届かない（失敗の結果で返す）。サンドボックスを有効にすると、Linux では中で起動した画面にブラウザーからつながらない見込み（実装の読み取り。実機では未確認）。設計ではエクステンションでつなぐ
- [ハーネスの調達](harness-sourcing.md) — 標準機能 → OSS（Awesome Copilot など）→ 自作 の順に検討。ユーザーの既存資産も対話で引き出して流用する。既存のプラグインは、まるごと生成プラグインの形に作り直すこともある
- [実例：組み込み機器のプリントデバッグ](example-embedded-print-debug.md) — クロスコンパイル・デプロイ・ログ取得をスキル化し、ヒューマン・オン・ザ・ループにする
- [自己改善](self-improvement.md) — （大事な考え）実行中にログを残し、実行後に振り返って改善提案し、自分のリポジトリへ Issue を発行する
- [AI の思考サイクル（PDS）](pds-cycle.md) — （大事な考え）闇雲に実行を繰り返さず、必ず計画・実行・評価のサイクルを回す
- [ソフトウェア工学の知識体系を参考にする](software-engineering-knowledge.md) — （大事な考え）推測だけでなく、SWEBOK など人間が蓄積してきた知識体系を取り入れる
- [プラグインを作るプラグイン（ハーネスの作り方）](plugin-creator-rationale.md) — （プロジェクトの根幹）プラグインには共通部分があるので、レベルの高いプラグインを再現性高く作るプラグインで質とスピードを上げる。クリエイターの中心は、人間からナレッジを引き出すこと。その質問は性能に直結するので、試験や利用の結果をもとに改善し続ける
- [ナレッジの重要性](knowledge-importance.md) — （大事な考え）人間が蓄積したナレッジを取り込み、対話で得たナレッジもセッションをまたいで残す。索引を直したら、リンクと載せ漏れを確かめる
- [人間と AI のコミュニケーション](communication.md) — （大事な考え）正しさより分かりやすさ。簡潔に、伝わる用語で書き、聞かれたことだけに答えて補足しない。自分で作った呼び名を説明せずに使わず、比べた結果は何と何を比べたかを書く。質問・状況報告・比べた結果には型があり、送る前に点検する（呼び名の定義、指す先、抜けた主語、確かめていないこと）。相談には長い報告で返さず、短く答えて1つ聞き返す。指摘は文言ではなく目的に沿って直す（検証役の AI の修正文もそのまま使わない）。質問は、決めないと何が困るかを最初に書く。まとめた言葉で聞かず、何のことかを先に示す。分からないと言われたら、定義や言い換えではなく具体的な出来事の順で言い直す。場面を問うときは、初めから具体的な例の出来事で書く。選択肢の説明に前提・数字・内部の仕組みを詰め込まない。長い比較や調査は HTML のページで見せる。比喩で言い換えず正確な技術用語で聞く（操作も「入れ直す」でなく実際のコマンドで書く）、手順を問うときはだれがいつ何をする話かを先に書く、問いが伝わらないうちは作業を進めない、選択肢に確かめていないことを事実として書かない、1つの言葉を2つの意味で使わない、事実で決まることは問いにしない。作業の途中で足された指示は原文のままサブエージェントに渡し、食い違えば新しい方に従って違いを伝える。音声入力や変換の誤りとみられる言葉は読み替え、読み替えたことを伝える
- [README の書き方](readme.md) — 最大の目的は、読んだユーザーが概要と使い方をすぐに理解できること。読む人（クリエイターは Copilot CLI の利用者）と、初めに書くこと（できることと始め方）を先に決め、初めの部分の下書きを見てもらってから全文を書く。本筋だけを書き、補足・例・比喩を減らす。コマンドはスラッシュコマンドだけ。書く前にナレッジをすべて読む
- [リファクタリング](refactoring.md) — 振る舞いを変えずに構造を整える。機能の変更と混ぜず、小さな手順で確かめる。SKILL.md も対象で、description の変更は振る舞いの変更として扱う
- [人からナレッジを引き出す手法](knowledge-elicitation.md) — SWEBOK の要求の引き出し（V3 は7つ、V4 は一覧が違う）。当たり前のことは話されにくい。文字のチャットで使えた手法：実際の1件をたどる（CDM）、見分け方をたどる（laddering）。はい・いいえの確認は「はい」に偏る。決まりではないと答えたことに聞く側が案を作らず、「違うところはない」を足したことにしない。記録の抜き書きは原文のまま写す。試験の採点が聞き漏らしだけを見ると、聞く決まりだけが足されて聞きすぎが残る。聞いてはいけない問いを決めて聞きすぎも見る（問いの数では落とさない）
- [KISS](kiss.md) — （大事な考え）必要なものだけを、できるだけ単純に作る。AI で作るとリポジトリは肥大化しやすい。リファクタリングはあとから整え、KISS は最初から足さない
- [Copilot CLI の試験機能](copilot-cli-testing.md) — EVAL 専用のコマンドはない。`-p`・`--plugin-dir`・実行記録で組める。トークンなしでもプラグインとスキルの読み込みは確かめられるが、カスタムエージェントは確かめられず、`mcp list` はプラグインの MCP を出さない。ログインせずに、オフラインのモードで偽物のモデルにつなげば、本物の Copilot CLI を動かせる。送られたリクエストを記録すればシステムプロンプトやツールの定義が分かる。版を決めて動かすときは、キャッシュの新しい版が動く落とし穴と、`COPILOT_HOME` は絶対パスだけを渡すことに注意する。Copilot SDK でプラグインを読み込み、質問に答え、イベントで採点できる。エクステンションの読み込みには `requestExtensions` に加えて `extensionSdkPath` と `extensionLaunchProvider` が要る（SDK 1.0.25）。許可の求めは答える仕組みを登録したすべての相手に届き、先の答えが使われる。AI クレジットの数え方。ドキュメントで分からないことは、npm パッケージの中身（更新履歴、スキーマ、組み込みの定義）で確かめる
- [Claude Code の EVAL の仕組み](claude-plugin-eval.md) — 課題をプラグインあり・なしで3回ずつ実行し、スコアを比べる。採点の種類。プログラムでの採点はなく、ユーザー役が答える仕組みも見当たらない
- [Agent SDK で EVAL を動かすときの注意](agent-sdk-eval.md) — 環境変数は必要なものだけ渡す。コマンドはサンドボックスに閉じ込め、Web 画面の操作だけ外に出す。許可を求めるのは質問だけにする。サンドボックスは、コマンドの始まりのフォルダの保護するファイルを中身のない装置のファイルで重ねる。MCP のツールは alwaysLoad で載せ、agent の本文を効かせるには claude_code のプリセットが要り、Agent は既定で裏で動く（0.3.310）。Linux のサンドボックスの中からは localhost に直接つなげず、プロキシを通した HTTP の1ポートだけを許す（allowLocalBinding は Linux で効かない）。同時に起動した Agent は別々のメッセージ（同じ message.id）で届く
- [Anthropic の skill-creator](skill-creator.md) — 軽く作り、試して直すことに重きを置く。結果を見る画面で感想を集めて直す、紛らわしい依頼で呼ばれ方を試して説明文を直す、採点者が試験の弱さも指摘する。集計のフォルダの食い違い、費用の見込みを出さないことに注意
- [ユーザー役の AI で人を模擬するときの注意](user-simulation.md) — 模擬したユーザーは人の代わりにならない。使う前にユーザー役だけを試験し、モデルと指示を固定する。対照のクリエイターと別の分野の模擬ユーザーで、試験が正しく働くかも確かめる。会話例は点数だけで選ばず、クリエイターの AI に読ませない。ユーザー役には質問の前の文も渡し、急ぐ合図は試験の仕組みが足す。不自然な答えは、指示・渡した情報・模擬ユーザーの知識・クリエイターの問い方のどれが原因かを分けて直す。偽の API のはずが本物のモデルに届いた事故は、呼ぶ前に止める守りで防ぐ。新しい模擬ユーザーで問題が出たら、クリエイターの弱さと決める前に markers と volunteer の誤りを疑う（test-ng-pick では4つのうち3つがそれだった）
- [クラウドのセッションで長い試験を動かすときの注意](cloud-long-runs.md) — 作業プロセスの再起動で、切り離して動かした試験も止まる（スクラッチパッドは残る）。Bash の裏の実行は2時間で止まるので setsid nohup で切り離す。長い試験は状態をファイルに残し、続きから始められるように作る（outer.mjs --resume。途中で直したら --converted で前の置き換えた版を使う）。Bash が断られる間は、ファイルのツールと send_later で続ける。容器の Playwright のブラウザーの版が合わないときの対処。試験の一時フォルダが残ってディスクがあふれ、環境の失敗を不具合と取り違えた（長い試験の前に空きを見る）
- [既存のプラグインを作り直すときに分かった弱いところ](rebuild-weaknesses.md) — coverity-triage の作り直しの試験で、承認の後に初めて断られて止まる不具合が3つあった（直した）。生成プラグインでは、試験に通すために流用した部品が書き換えられて元の設定が消えた、作業の画面の作業エージェントがプラグインの場所を知れない、汎用のエージェントの名前が元の配置の仕組みに拾われた、人に聞けない役に聞く決まりが渡った、確かめていない振る舞いが入った
- [AI が作ったと分かる画面の特徴](ai-looking-ui.md) — Anthropic が公式に挙げる癖：Inter や OS 標準のフォント、紫のグラデーション、全部同じ角丸と影、同じ形のカード、リンクの後ろの「→」、小さな札の等幅フォント。Claude だけの癖はクリーム色・明朝風の見出し・赤茶。見本の画像は、使うフォントを同梱して撮る
- [AI にチャットへ書かせるコツ](agent-instruction-placement.md) — ツールの結果で書かせたい文は先頭に置き、直後に「ほかのツールを呼ぶ前に書く」と頼む。間に別の手順を挟まない。一般の決まりより、手順の文の中に置いた例の文が効く。1回の結果で決めず、3回以上の割合で見る
- [Claude Code の禁止のルールでフォルダを読めなくするときの注意](claude-code-deny-rules.md) — リポジトリを2つつないだクラウドのセッションでは、リポジトリの `.claude/settings.json` が読まれず、コンテナのユーザーの設定なら効いた。Read のルールのパスは作業フォルダから照らし合わされるとみられ、`**/<フォルダ名>/**` か絶対パスで書く。前後に `*` を付けた Bash のルールは、パスを書いただけのコマンドも断る
- [アイデア創出（6つの柱）](idea-creation.md) — （大事な考え）アイデア創出の本質は6つの柱（制限の決定、徹底的な事前調査、本質の見極め、本質の掛け合わせ、アイデアの説明、知識・経験の蓄積）。承認なしに変えない。本質はたくさん用意して2〜4個ずつ掛け合わせ、だめなら組を変える。良いアイデアは誰かの生活や仕事を豊かに・便利にするもので、本質の時点から「誰にどんなメリットがあるか」を持つ。本質・案・説明は人が読んで分かる日本語で書く分析・壁打ち・説明の読み手は2者以上。柱の中の数はパラメーター。知識・経験はログにせず洗練して残し、すべての柱で使う。制限は事前調査の取っかかりにすぎず、壁打ちと選択では使わない。良さは新しさ・役立つか・価値で判定する。事前調査はディープリサーチの形。試験はプロセスどおりかと、アイデアが素晴らしいかの2つを見る
- [CLI のディープリサーチと、スキルからの調べ方](deep-research.md) — Copilot CLI の /research と Claude Code の /deep-research は、スキルから呼べない（公式に方法がない）ので、同じ形を手順とサブエージェントで組む。Claude Code の WebSearch はセッションで200回まで（環境変数で上げる）。判定役の別のモデルは、Copilot の Auto では効かず、Claude Code では他社のモデルを選べない
- [アイデア創出スキルの流れの試験の注意](idea-eval.md) — 費用（量を減らした設定で約29ドル分、既定で約118ドル分・約2時間。今の形の既定では約925ドル分・約7時間40分。Agent SDK の見積もり）。--data-from と --params default では前の回の設定のまま動く。量を減らした設定で通っても、既定の設定で1回は通す。容器の再起動や手順の直しで止まったら、--data-from と --expect-resume で止まったところから続ける。壁打ちで通った案は固め、直して判定し直さない（直して落とした案が2つあった）
- [試験で見つかったクリエイターの弱いところ](creator-weaknesses.md) — まだ直していない弱さの一覧。会話の後半で聞き出した決まり（恒温槽）が、エージェントには入ったが EVAL の合否の基準に入らなかった
- [生成プラグインを plugin-market-place に登録するとき](marketplace-registration.md) — Git で管理しているファイルだけを git archive で写す。写した先でテストを通し、手元のパスが残っていないかを見る。README に AI が演じたユーザーと作ったことを書く
- [憲章の条・要件（REQ）・版の番号](numbering.md) — 通し番号なので、新しい条は後ろに足す。長いセッションの間に main とぶつかるので、番号や版を付ける前と PR の前に main を取り込む。付け直すときはテストの関数名や用語の表の参照も直す
