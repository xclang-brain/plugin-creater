# アイデア創出スキルの流れの試験の注意

アイデア創出スキル（make-idea）を、本物のモデルで最後まで動かす流れの試験（`tests/dev-eval/runner/idea.mjs`）で分かったこと（2026年10月、Claude Code の置き換えた版、Agent SDK 0.3.310）。

## 費用

- 試験の仕組みが記録した費用は、Agent SDK の `total_cost_usd` を足した値である。API の定価で計算した見積もりで、実際の請求額とは違うことがある。
- 量を減らした設定（idea.mjs の `--params small`。集める作品 100→12、本質 30→6、壁打ちする案の総数 100→6、説明するアイデア 3→1 など）でも、1回約29ドル分・ツールの呼び出し約320〜390回かかった。
- 既定の設定（`skills/make-idea/assets/params.json`）では、約118ドル分・呼び出し1,220回・約2時間かかった。
- 柱5から続ける試験は、約7ドル分だった。
- 小さな設定でも安くないので、回す前に、どの試験を何回回すかと費用の見込みを示す。

## 前の回のデータを写して始めるとき

- idea.mjs は、`--params default` のとき params.json を置かない。そのため、`--data-from` で写した前の回の params.json がそのまま使われる（2回目の実行で、量を減らした設定のまま動いた）。
- 既定の設定で動かすときは、`--params skills/make-idea/assets/params.json` とファイルを渡す。始めた直後に、データの置き場所の params.json の値を見て確かめる。
- 入口のコードは直していない。

## 量を減らした設定で通っても、既定の設定で1回は通す

量を減らした設定で合格した採点の項目が、既定の設定で初めて不合格になった。どちらも、採点のしかたと手順書の書き足りなさだった。

- 量が増えると、エージェントはファイルの大きさの上限（20,000 バイト未満）に合わせて、本質の一覧を分けて書いた（index.md と index-2.md）。採点が1つ目だけを数えていた。
- 知識・経験の候補で外すものがないとき、エージェントは「外した番号：なし」を、決まりのファイル（candidates.md）ではなく state.md にだけ書いた。
- 採点は分けて書かれたファイルもまとめて読むようにし、手順書（accumulate.md）には空のときの1行の形まで示した。

## ディープリサーチの形にしてからの量（2026-10-28）

- 事前調査をディープリサーチの形（計画、調べ直し、評価ありの全件の掘り下げ）にしてから、集める役は目標の数を下限として扱い、目標より多く集める。量を減らした設定（集める作品12件、1切り口の目標2件）でも、計画が切り口を6つ立て、1回目と調べ直しで133件を集め、評価ありは88件になった（約30分）。
- 掘り下げる件数を決めない（評価ありはすべて掘り下げる）ので、量を減らした設定でも掘り下げの起動が多くなる。量を減らした設定は、流れを短く通す目的には向かなくなった。柱3から後を試すときは、柱2の後で止めた回のデータ（`--data-from`）から続ける。
- 既定の設定での2回目の試行（制限：GitHub Copilot CLI と Claude Code で使えるプラグイン）では、柱2に2時間46分かかった（集めた385件、評価あり306件をすべて掘り下げ、読んだページ2,204）。
- 掘り下げが306件（記録 約960KB）になると、1体のなぜなぜ分析では読みきれない。柱3を30件ずつのまとまりに分け、集約を2段にした（11のまとまり × 2観点、柱3は約63分、本質72個）。
- 柱4で組を1つずつ試すと、先行例の調べ（約10分）と判定・直しの3往復で、1つの組に約50分かかった。10組で8時間を超えるので、4組ずつの波で同時に試すようにした。
- 手順を途中で直したときは、柱の変わり目でプロセスを止め（state.md の「今の柱」を見て止める）、`--data-from <前の実行の data> --expect-resume` で新しい会話から続けた。make-idea の続き（REQ-075）が働き、止まった柱から進んだ。続きの回に、新しいパラメーターのファイルを `--params` で渡す（足した項目がないと、始まりの確かめで止まるため）。
- クラウドの作業環境（コンテナ）の再起動で、裏で動かしていた試験が柱4の途中で2回止まった（2026-10-28 の23時ごろと23時20分ごろ。その前の約6時間は止まらなかった）。2回とも、手動で止めたときと同じ `--data-from <止まった回の data> --expect-resume` で新しい回を始めると、止まった手順（例：c10 の案を直す）から続き、最後まで進んだ。止まった回の呼び出しの記録は残らないので、採点は会話の記録から作り直した（その後、入口は記録を50回ごとにも書くようにした）。
