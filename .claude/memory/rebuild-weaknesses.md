# 既存のプラグインを作り直すときに分かった弱いところ

既存のプラグイン coverity-triage（coverity-triage-agent）を、クリエイターで作り直した試験（2026年10月、クリエイター 0.1.0、対話のモデル Claude Opus 5.5。問いには開発者の代わりに Claude が元の資料をもとに答えた）で分かったこと。クリエイターを直すときの材料にする。

## 試験の途中で直したもの

- 試験の仕組みが、作り直しのために作業フォルダに写した元のプラグイン（直下に plugin.json がある）を、生成プラグインと取り違えた。始める前からあったプラグインを記録して除くようにした。
- 作る前の確認で、試験の入力に見本のリポジトリのフォルダを渡せてしまい、承認の後の組み立てで断られて先へ進めなくなった。確認のツールで、実物の入力はあるファイルの絶対パスだけを受け付けるようにした。
- 同じ実物のファイルを2つの試験課題で使うと、組み立てのスクリプトが片方の課題の置き場所しか引けず断った。課題ごとの置き場所を持つようにした。
- どれも、承認の後に初めて断られると、確認をやり直せずに止まる。確かめられることは、確認の時点で確かめる。

## 生成プラグインに残った問題（登録の前に手で直した）

- 流用した部品を、試験（1段目の構造の検査）に通すために作業エージェントが書き換えた。元のプラグインの設定（入口のスキルの `disable-model-invocation`・`allowed-tools`・`argument-hint`、内部のスキルとサブエージェントの `user-invocable: false`、サブエージェントの `models`・`modelPolicy`、サブエージェントの `skill` のツール）が消え、モデルの固定（ユーザーが確かめた決まり）も失われた。このうち `allowed-tools`、`models`、`modelPolicy`、サブエージェントの `user-invocable` は、1段目では警告だけで、消さなくてよかった。手順は「流用したファイルは書き換えない」と書いているが、試験の直しの段階で守られなかった。
- 作業の画面から動く作業エージェントには、プラグインの場所を知る手段がない。スキルの道具がなく、エクステンションの指示文にもプラグインの場所が入らないため、流用したスクリプト（ct.py）と手順書を見つけられなかった。Copilot CLI がプラグインの場所を渡すのは、stdio の MCP サーバー（`PLUGIN_ROOT`）だけである。今回は、流用した MCP サーバーに場所を返すツールを足して直した。ほかの生成プラグイン（embedded-debug-loop）のエージェントの本文にある `${PLUGIN_ROOT}` も、エージェントのコマンドで展開されるかは確かめていない。
- ひな形の汎用のエージェントの名前（`orchestrator`、`worker`、`verifier`）が、元のプラグインの「自分のエージェントを Copilot の設定のフォルダに写す」仕組みに拾われ、利用者の同じ名前のファイルを上書きするところだった。
- 人に質問できない作業エージェントに、元の手順の「続きから再開しますか？」と聞く決まりがそのまま渡った。作業の画面から動く役に渡す決まりは、人に聞く場面がないかを確かめる。
- 作業エージェントの指示に、ユーザーが確かめていない振る舞い（チャットの言い方を画面の設定より優先する）が入った。
