# アイデア創出（6つの柱）

開発者が示した、AI でアイデアを作るときの考え方（2026年10月）。アイデア創出スキル（make-idea）の中心である。

## 6つの柱

- アイデア創出の本質は、次の6つにまとめられる。開発者は「無限にある情報の中で、アイデア創出の本質はこの6個に絞られる。これが本質を見極めるということ」と言った。
  1. 制限の決定
  2. 徹底的な事前調査
  3. 本質の見極め（なぜなぜ分析）
  4. 本質の掛け合わせによるアイデア創出（壁打ち）
  5. アイデアの説明（第三者目線）
  6. 知識・経験の蓄積
- この6つを「6つの柱」と呼ぶ。名前・順番・中身は、開発者の承認なしに変えない。変えたほうがよいと考えたら、変えずに案を出す（憲章 第26条）。
- 調べた研究や公開の手法は、柱を実現するやり方と落とし穴の対策にだけ使う。7つ目の柱や別の枠組みを持ち込まない。

## 柱の中身で、開発者がはっきり言ったこと

- 本質は、たくさん用意してから選ぶ。掛け合わせるのは一度に2〜4個でよいが、その前の本質の見極めで2〜3個だけを作るのではない。
  - 例：本質の山から使えそうな3つを選んで掛け合わせ、壁打ちする。だめなら別の3つ、さらに別の3つ。それでもだめなら4つや2つにする。
- なぜなぜ分析、壁打ちの相手、説明を読む第三者は、どれも2者以上のエージェントで行う。壁打ちと説明は、作った本人ではない相手に見せる。
- 事前調査は、速くするために複数のエージェントで並列に行う。
- 柱の中の数は、すべてパラメーターにし、ファイルで変えられるようにする（憲章 第27条）。初期値は、事前調査100件以上、本質30個以上、なぜなぜ分析のエージェント2以上、掛け合わせる本質2〜4、壁打ちの相手2以上、説明の読み手2以上。

## 制限と良さ（2026-10-28 に開発者がはっきり言ったこと）

- 制限は、事前調査の範囲が無限に広がらないようにする「取っかかり」にすぎない。開発者の言葉：「制限は最初のきっかけを作るだけであって、結果的にその制限の範囲に収まってなくても全然いいです」「制限がないと事前調査の範囲が無限になってしまうから」。
- だから、壁打ちでも、説明するアイデアを選ぶときも、制限に合うかを判定に使わない。開発者の言葉：「壁打ちの段階で制限を満たすかなんていう観点ではいりません」「選ぶ基準にも制限に一番合うものなんか、そんなものはありません」。1回目の試行では、制限を判定に使ったせいで、案が制限の中に押し込められた（開発者：「制限のせいで逆にいいアイデアが生まれなくなってる」）。
- 良いアイデアとは、これまで誰にも発明されていない新しさがあり、誰かにとても役立ち、世の中を豊かにしたり社会を変えたりする価値があるものである。壁打ちは、この目線で「アイデアとして素晴らしいか」をひたすら確かめる場である。「両 CLI で動くか」「デバッグに効くか」のような観点は、良さの判定にならない。
- 事前調査のイメージは、各社の AI のディープリサーチである。8分で終わるような調べ方は「徹底的」ではない。集めた後に件数を決めて一部だけを掘り下げるやり方も、開発者は指示していない。
- なぜなぜ分析は、事前調査で集めた評価されている作品に「なぜ評価されているのか」を重ねて深掘りし、本質にたどり着くこと。道具の機能をなぞるだけでは、なぜなぜ分析ではない。
- 試験では、柱で示したプロセスどおりにアイデアが作られたか（件数や形式だけでなく中身も）と、できたアイデアが素晴らしいかの2つを確かめる。
- 柱の文は、手順へ写すときに縮めない。縮めて写したら「時間をかけて」が抜け、事前調査が8分で終わった。

## 誰にどんなメリットがあるか（2026-10-29 に開発者がはっきり言ったこと）

- 良いアイデアとは、世の中の誰かの生活や仕事が豊かになったり、便利になったりするものである。「誰にどんなメリットがあるか」という視点を持つ。手法の説明だけのアイデアは、どんな人にどんなメリットがあるかが分からない。
- この視点は、本質の時点から要る。2回目の試行の本質4つは、どれも誰にどんな恩恵があるかが抜けていた。開発者は、なぜなぜ分析で「なぜこれは評価されているのか」「誰にとってこれは恩恵があるのか」などの疑問をぶつけていないのではないかと指摘し、記録もそのとおりだった（「誰にとって恩恵があるのか」で始まる問いは、92の分析のファイルで1回だけ。答えは仕組みの原理へ掘り進んで止まっていた）。
- 本質、案、説明は、人間が理解できる日本語で書く。2回目の試行のアイデアの説明と本質は、作品の番号、英語の引用、略語、「→」でつないだ段で埋まり、開発者は「明らかに人間が理解できる日本語ではない」と言った。AI の読み手は、同じ説明を意図どおりに言い直せていた。AI の読み手が分かったことは、人に伝わることの裏づけにならない。

## 知識・経験の蓄積は、洗練して残す

- 優れた発明家は、事前調査の情報だけでなく、自分の過去の経験と知識からアイデアを作る。だから、作業を終えたら振り返り、知識・経験として残す。
- 残すのは、事前調査で学んだこと、気づいたこと、うまくいったこと、失敗したことなど、あらゆること。
- ただし、ログのように全部を残さない。本質を見極め、洗練した形で残す。大量にあっても洗練されていなければ、探すのに時間がかかるためである。
- 残した知識・経験は、次の回の6つの柱すべてで使う。
- 研究でも、記録を丸ごと足すより、要点を短くして出典を添えた方が効いた例が多い。一方で、全体を書き直すと細部が消える（ACE の context collapse）。項目の単位で足し・直し・消し、具体例と出典を添える。
