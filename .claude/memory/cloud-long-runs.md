# クラウドのセッションで長い試験を動かすときの注意

Claude Code のクラウドのセッションで、開発者が答える外側の EVAL（[試験の設計](../../docs/design/testing.md) 6.7）を動かして分かったこと（2026年10月）。

## 作業プロセスの再起動で、裏のプロセスも止まる

- このセッションでは、作業プロセス（セッションのワーカー）が何度も再起動した（1日に4回以上）。
- 再起動すると、`setsid` と `nohup` で切り離して動かしていた試験の仕組みのプロセスも止まった。スクラッチパッドのファイルは残った。
- Bash のツールで裏に動かしたコマンドも、最長2時間で止まる。
- 開発者が答える試験は、答えを待つ時間が長く、1回が数時間になる。止まるものとして作る。

## Bash の裏の実行は2時間で止まる

- coverity-triage の作り直しの試験（2026年10月）では、Bash のツールの裏の実行（`run_in_background`）で始めた外側の EVAL が、始めてからちょうど2時間で止まった（状態は `interrupted`）。開発者が答える試験は、答えを返す時間を入れると2時間を超えやすい。
- `setsid nohup <コマンド> &` で切り離して始めると、2時間では止まらなかった。ただし、作業プロセスの再起動では、切り離したプロセスも止まった（上の節と同じ）。
- 止まったら、`outer.mjs --human --resume` で続ける。試験の途中でクリエイターを直したときは、`--converted <前の置き換えた版>` を渡し、置き換えた版の中の直したファイルだけを差し替える。置き換え直すと、スキルのフォルダの場所が変わり、クリエイターが覚えている場所と合わなくなるためである。

## 止まっても続きから始められるように作る

- 状態は、すべてファイルに残す。メモリーにだけ持つ記録は、止まると消える。
- 外側の EVAL は、`outer.mjs --human --resume <実行のフォルダ>` で、クリエイターの同じセッションを続ける（Agent SDK の resume）。そのため、終わった後もセッションの記録（`agent-home/.claude`）を消さない。
- 止まったときに待っていた問いは、Claude Code が捨てることがある。続けるときの最初の発言に、問いの中身と答えを書いて渡す。
- 統括は、コンパクションの後や再起動の後に、試験の仕組みを動かし直さない。中継のフォルダの `status.json` と `wait` から続ける。

## Bash が使えないとき

- 自動の許可の判定が一時的に失敗して、Bash のコマンドが続けて断られたことがある。
- そのあいだも、ファイルを読むツールと書くツールは使えた。中継の答えのファイルは、書くツールで直接書いて続けた。
- 待つための仕組み（Bash の裏の実行）が使えないときは、`send_later` で数分後に自分に知らせて、状態を見に行った。

## Playwright のブラウザーの版が合わない

- この容器の `/opt/pw-browsers` には、Chromium の 1243 番の版だけが入っていた。試験の仕組みと生成プラグインが使う Playwright 1.56.1 は 1194 番の版を探すので、画面の写真（中継の問いの画像）も、生成プラグインの2段目も、「ブラウザーがない」で止まった（2026年10月）。
- 写真は、`/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` から 1243 番の `chrome-headless-shell` へシンボリックリンクを張ると撮れた。
- 生成プラグインの1・2段目は、クリエイターが試験の道具として入れた Chromium（実行のフォルダの `agent-home/.cache/ms-playwright`）を `PLAYWRIGHT_BROWSERS_PATH` に渡すと動いた。試験の仕組みが自分で動かす1・2段目は、この容器のブラウザーを探すので不合格になる。環境の不足であって、生成プラグインの不合格ではない。

## 試験の一時フォルダでディスクがあふれる

- 改善・設計変更の試験（2026年10月）で、ディスクの空きが 5MB まで減った。試験が OS の一時フォルダ（`/tmp`）に作った見本の生成プラグイン（1つ十数 MB）を消さずに残し、2,000 個あまり、約 24GB たまっていた。
- あふれると、生成プラグインの部品の試験が ENOSPC で70件あまり落ち、内側の EVAL では画面が起動しなかった（「Failed to fetch」）。どちらもプラグインの不具合ではなく、環境の失敗だった。原因に気づくまで、不具合として調べてしまった。
- 対策（実装済み）：試験の道具が作った一時フォルダは、試験のプロセスが終わるときに消す。外側・内側の EVAL は、始める前に空きを確かめ、2GB 未満なら始めない。ENOSPC と EIO だけで落ちた試験は、環境の失敗として点数に入れない。
- 長い試験の前には `df -h /` で空きを見る。おかしな落ち方をしたら、まずディスクの空きを疑う。
