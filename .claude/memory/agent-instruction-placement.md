# AI にチャットへ書かせるコツ

改善・設計変更の外側の EVAL（2026年10月、5回）で、クリエイターのメインのエージェント（Claude Opus 5.5 を Claude Code で動かしたもの）に、チャットへ決まった文を書かせようとして分かったこと。

## ツールの結果で頼むときは、書く文を先頭に置く

- 画面の URL：画面を開くツールの結果を「上の1行（plugin-creator の画面：…）だけを、ほかのツールを呼ぶ前に、そのままチャットの文に書いて、ユーザーに示してください。」の形（書く文が1行目、頼みが2行目）にすると、毎回書いた。
- これからの流れ：記録のツールの結果の終わりに、頼みの後に長い流れの文を置いた形では、5回とも書かず、すぐ次のツールを呼んだ。SKILL.md の手順で「書く」と決めていても、間に別のツールの手順（作業用の一時フォルダの確かめ）が挟まると飛ばした。
- 書かせたい文は、ツールの結果の先頭に置き、その直後に「ほかのツールを呼ぶ前に書く」と頼む。書く場面と次のツールの間に、ほかの手順を挟まない。流れの文を先頭に置き直した形（コミット dc565be）が効くかは、まだ確かめていない。

## 決まりより、手順の中の例の文が効く

- 「チャットの文は日本語で書く」という一般の決まり（SKILL.md の先頭）を足しても、ツールの前の進み具合の一言は英語のまま（「Now the list confirmation.」など。5回で 3〜12 件）だった。
- 効いたのは、その手順の文の中に置いた日本語の例（例：「今のプラグインと、教えてもらったファイルを読ませています。」）だけで、例を置いた場所の一言だけが日本語になった。ファイルの初めに置いた一般の例は効かなかった。
- 決まりを足すより、問題が起きる手順の文の中に、そのまま使える例の文を置く。
- 1回の結果で効いた・効かないを決めない。回ごとにぶれるので、3回以上の割合で見る。
