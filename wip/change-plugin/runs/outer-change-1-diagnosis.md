## 1. 落ちた観点と faults の原因

### 1.1 rules-list-once（REQ-054「決まりの一覧が1回の問いで示される」）

**採点のしかた**（`tests/dev-eval/runner/outer-grade-change.mjs` 226〜234行）：確認（最初に受け付けられた `plugin-creator_confirm`、[461]）より前の問いのまとまり（前の文＋見出し＋問い＋選択肢）ごとに、元の決まりの番号（K-01〜K-17）がいくつ出るかを数え、17件すべてが出る問いがあれば合格。結果は「多くて 0／17 件」。

**証拠**：

- 確認より前の 24 の問いのどれにも、K の番号が1つも出ない（seq 46〜430 をすべて見た）。番号が出たのは、確認の1つ目の前の文 [466]「引き継ぐ決まり（今のまま）：K-01〜K-14、K-16、K-17」だけで、ここも番号の範囲だけで、決まりの文はない。
- 段階「読む」の範囲の問い [161] は、できていたこと1〜9を示し、終わりに「違うところと足りないところ（ログ追加のルールや、画面の設定も KX-200 向けに変えたいかも含めて）を書いてください」と聞いた。決まりの一覧は示していない。
- ユーザー役の答え [162] の最後の行：「決まりの一覧（K-01〜K-17）で古くなったのは K-15 だけで、ほかは今もそのとおりです。」ユーザー役はこの一覧を見ていない。この文は、ナレッジ `k15-now`（`volunteer: true`）の fact「前に作ってもらったプラグインの決まりの一覧（K-01〜K-17）のうち、古くなったのは K-15 だけで、ほかは今もそのとおり」をほぼそのまま写したものである。
- クリエイターは [169] で、K-01〜K-14、K-16、K-17 の16件を、この1文を抜き書きにして「決まった」にした（K-15 は答えの中身で K-33 に付け直し）。その後、change-read.md の4の問いをせずに、[174] で段階を「前回の1回」に進めた。
- change-read.md の4（55行）：「一覧のすべての番号を1つの問いに入れ、今と違うものと、古くなったものを聞く（理解の確かめ）。分けて聞かない。」省いてよい場合は書いていない。

**分類**：

- クリエイター（主）：手順4を飛ばし、ユーザーが一度も見ていない決まりの文を「決まった」にした。結果として、ユーザーは引き継ぐ16件の文を、会話の中で一度も見ないまま承認した（確認の1つ目も番号の範囲だけ）。エクステンションも、抜き書きがユーザーの言葉にあるので受け付けた。
- 模擬ユーザー（従）：`k15-now` の fact に番号（K-01〜K-17、K-15）が入っているので、ユーザー役が見せられていない一覧の番号で話せた。本物の人は、一覧を見せられる前に番号では話さない。
- 試験の仕組み：誤りなし（採点は REQ-054 のとおり）。

### 1.2 unchanged-items（REQ-056「変えないので聞かない」）

**採点のしかた**（同ファイル 467〜475行）：記録の `items` に状態 `unchanged` の項目が1つ以上あり、かつ画面の3項目（`settings`、`running_view`、`result_view`）がすべて `unchanged` なら合格。結果は「画面の項目が「変えないので聞かない」になっていない：開始前に設定したいこと」。

**証拠**：

- [161] の括弧書き「（ログ追加のルールや、画面の設定も KX-200 向けに変えたいかも含めて）」が、画面の変更を誘った。頼み（[1]）には画面のことはない。
- [162] の答え「3. **画面の設定**: 機器の IP アドレスは 192.168.7.2 にしてください。deploy のスキルに既定として書いてある 192.168.7.20 は前のボードのアドレスで、直し忘れています。」（ナレッジ `dp-ip` は `volunteer: true`）
- [164] クリエイターは `plugin-creator_change` を呼び直し、変えたいことに「画面の機器の IP アドレスを 192.168.7.2 にする」を足した。
- [294] 段階「項目の点検」の初めに、作業の目的・頼む場面と言い方・合否の決め方・実行中に見たいこと・終わった後に見たい結果と見せ方の5つを「変えないので聞かない」にした。「開始前に設定したいこと」は外した。
- [415] 段階「画面」の問い：「…今回 IP アドレスの初めの値を 192.168.7.2 にします。KX-200 で使うにあたって、このほかに、始める前に毎回決めたいこと（足すもの）や、変えたい・消したい設定はありますか？」→ [416]「ない（IP の初めの値だけ変える）」→ [418] で「聞いた」。
- change-plugin の SKILL.md 72行：「画面を変えないときは、画面の3つの項目もそうする。」段階の表：「作業の画面の設定や表示を変えるとき…は画面」。今回は設定の初めの値を変えるので、クリエイターの扱いは SKILL.md どおりである。`no-screen-questions`（画面で何を設定したいかを広く聞く問いがない）も合格している。

**分類**：

- 試験の仕組み（主）：採点は「どの会話でも画面を変えない」を前提にしているが、模擬ユーザーの定義にも採点にも、ユーザーが設定の変更を頼んだときの扱いがない。今回の会話では、設定を聞いたのは正しい。
- 模擬ユーザー（従）：`dp-ip`（自分から話す）の正しいアドレスを、どこに入れたいか（ルールのスキルの既定か、画面の初めの値か）の立場がない。そのため、問いの書き方しだいで画面の変更になる。
- クリエイター（従）：[161] の括弧書きが、頼みにない変更（画面、ログ追加のルール）を誘った。change-read.md の3の例文にはない書き足しである。
