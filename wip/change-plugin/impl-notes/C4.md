## 2. 設計図からずらしたこと・足したこと（理由つき）

1. **`.github/plugin/marketplace.json` は変えていない**。説明（description）の欄がもともとない。欄を足すのは頼まれていない変更なので足さなかった（版も 0.1.0 のまま。D37）。
2. **make-plugin の start.md に、フォルダのまま直す頼みを change-plugin に回す1行を足した**（設計図は「作り直したい」だけの問いだけ）。REQ-052 の受け入れ基準「新しく作る対話と、新しいフォルダへの作り直しの対話は始まらない」を、make-plugin が呼ばれてしまったときにも守るため。
3. **「作り直したい」だけの問いのおすすめを「今のフォルダのまま直す」にした**。make-plugin の「決める」問いはおすすめが要る。設計図に決めがないので、skillflow 2.5 の例（git の履歴と今の入れ方がそのまま使え、変えないところに手を入れずに済む）に従った。統括が別の案にしたければ、start.md と change-start.md の2か所を直す。
4. **始まりの手番の順**：make-plugin の4節を最初に読み、その後にツールを確かめる。ツールがないときの手順（「始められないとき」）が、その4節の中にあるため。確かめるツールは `ask_user` と `plugin-creator_open` だけ（`plugin-creator_change` は同じエクステンションなので、open があればある）。
5. **今の版がないときの版の案は 0.1.0**。D16 は「形だけ見る」で、案の決め方がなかった。ひな形の版（0.1.0）にそろえた。
6. **できていたこと（「〇〇と頼むと〇〇をする」）はナレッジに記録しない**。記録すると、新しい番号の決まりとして knowledge.json に入り、REQ-058 の「足した決まり」に数えられるため。範囲の確かめの問い（問答の記録に残る）と `rebuild.keep` で引き継ぐ。
7. **`extract` は、`<W>/extract.json` がもうあれば動かし直さない**（コンパクションの後など）。動かし直すと draft と parts が作り直され、作業エージェント A の直しが消えるため。代わりに、change-start で新しく記録を作ったときに残っていた `<W>` を消す（古い下見を使わないため）。
8. **読ませ直し方**（REQ-060）：手元のフォルダのマーケットプレイスは `/restart` か新しいセッション（公式の cli-plugin-reference、2026-10-26 取得「Path-sourced plugins in a local (directory-source) marketplace load live … takes effect on `/restart` or in a new session」）。GitHub から入れたときは push の後に `copilot plugin uninstall` → `copilot plugin install <名前>@<マーケットプレイス>`。公式は `copilot plugin update` が push を拾うかを書いていないので、make-plugin の generate.md 5の4と仕様の例（入れ直す）に合わせた。
9. **ルールのスキルは「足す」だけでなく「今あるものを直す」も書いた**。embedded-debug-loop のように、すでに `cross-compile-rules` などがあるとき、示されたスキルの決まりは今のルールのスキルに入れるのが自然なため（どちらにするかは確認で示す）。
10. **作業エージェントへの差し込み口の頼みに、README・仕様書・設計書・要件のたどり方の差し込み口も入れるよう書いた**。REQ-059「プラグインの憲章・仕様書・設計書は、変えた内容に合わせて直す」と受け入れ基準「要件から…をたどれる」のため。
11. **組み立てが断ったときの作業エージェントへの頼みの名前は「直すプラグインの部品」**（generate.md の「生成プラグインの部品の直し」に当たる名前を新しく作らなかった）。C3 の worker.agent.md の仕事の名前が A〜D の5つで、D に直しの名前がないため。
12. **呼ばれ方の試験**：
    - クリエイターのエクステンションの代わりの MCP サーバーは読み込まない。最初に呼ぶスキルの選び方に要るのは、スキルの description だけのため（KISS）。
    - 「どれも呼ばない」の頼みは、クリエイターのスキルを最初に呼ばなければ合格（Claude Code に組み込みのスキルを呼んでもよい）。
    - `trigger.test.mjs` は、形と採点の関数に加えて、偽の query で `runCase` を2件試した（止め方と作業フォルダの置き方。モデルは呼ばない）。
    - 1件の上限は `maxTurns` 6、`maxBudgetUsd` 1。サンドボックスは既定で使う（`--no-sandbox` で外す）。
13. **README** に、直している間にできる `.plugin-creator-work/` の1行と、インストールした写し（`~/.copilot/installed-plugins/`）は直せない1行を足した。起動したフォルダがプラグインのフォルダのとき、git status に一時フォルダが出るため。
