# plugin-creator

plugin-creator は、GitHub Copilot CLI のプラグインです。あなたの仕事のやり方と決まりをチャットで聞き取り、その仕事を任せられる Copilot CLI のプラグインを作って、試験します。

## できること

任せたい仕事をチャットで伝えると、plugin-creator が次のことをします。

1. 質問して、あなたの仕事のやり方と決まりを聞き取ります。
2. 聞き取った内容を組み込んで、その仕事をする Copilot CLI のプラグインを作ります。
3. できたプラグインを試験して、結果を示します。

できあがるプラグインは、まとめ役・作業役・確認役の AI に分かれて作業します。設定・監視・結果の確認は、ブラウザーで開く作業の画面で行います。

手元にある既存のプラグインも、この作りのプラグインに作り直せます。そのプラグインのフォルダを示して頼みます。元のフォルダは変わりません。

### 例：週報のプラグイン

1. 「毎週の売上データ（CSV）から、部長に出す週報を作る作業を、Copilot CLI のプラグインにしたいです」と頼みます。
2. 質問に答えて、週報の決まりを伝えます。例：見出しは「■今週の売上」と「■来週の予定」の2つだけ。最後の行は「以上」。金額は万円の単位で、1万円未満は切り捨て。
3. 週報のプラグイン（`weekly-sales-report`）ができます。このプラグインに「sales.csv から週報を作って」と頼むと、決まりどおりの週報（`weekly_report.md`）を作ります。

この例の会話の全文は、[会話例](examples/weekly-report.md) にあります。AI が演じたユーザーとの会話です。何を伝えればよいかの参考にしてください。

## 使い方

初めて使う前に、下の「使うために要る準備」を1回行います。

1. できあがるプラグインを置きたいフォルダ（作業フォルダ）で、Copilot CLI を起動します。
2. チャットで頼みます。
   - 例：「〇〇の作業を自動化したい」「この仕事を AI に任せたい」
   - 既存のプラグインを作り直すときは、そのフォルダを示して頼みます。
   - `/plugin-creator:make-plugin` と打っても始められます。
3. チャットに plugin-creator の画面の URL が示されるので、ブラウザーで開きます。
   - 画面では、決まったことの一覧と、まだ聞いていないことが見られます。
   - 画面は見るだけです。答えや直しは、チャットで行います。
   - この URL は、Copilot CLI を動かしているマシンのブラウザーからだけ開けます。
4. チャットで、質問に答えていきます。最近実際にやった1回の流れや、いつも使っているファイルも聞かれます。
5. 作る前に、次のものが示されます。直したいところを伝え、よいと答えると、作り始めます。
   - 聞き取った内容のまとめ
   - 作業の画面の見本（ブラウザーで開きます）
   - 試しに動かして採点する試験で、プラグインにさせる作業と、その合格の条件
6. 作業フォルダの中の新しいフォルダに、プラグインが git のリポジトリとしてできます。
   - 試験の結果と、できたプラグインの使い方が、チャットに示されます。
   - できたプラグインの入れ方と使い方は、そのフォルダの `README.md` にあります。

### モデルの選び方

- 質問に答えて仕事のやり方や決まりを伝える対話には、思考力の高いモデルが向いています。
- モデルは `/model` で変えられます。対話と、作るときの判断は、選んだモデルで行います。
- できあがるプラグインのファイルを書く仕事は、選んだモデルによらず、費用の低いモデル（GPT-6 Luna。使えないときは Claude Haiku 5.5）で行います。
- ただし、モデルを Auto にしていると、ファイルを書く仕事も、Auto が選んだモデルで行います。

### 途中でやめて、後で続ける

お話は途中でやめられます。前のセッション（Copilot CLI の1つの会話）に戻ると、やめたところから続きを聞かれます。

- すぐに続けるとき：`copilot --continue`
- 間に別のセッションを使ったとき：`copilot --resume=<セッションの番号>`（番号は、やめるときにチャットに示されます）

`/clear` をした後や、新しいセッションで頼んだときは、最初から始まります。

### できたプラグインを試験する

作った直後に、plugin-creator がファイルの形の検査と動きの試験を行い、結果を示します。そのあと、次の2つの試験を行えます。プラグインを直した後も、同じように行えます。

- ファイルの形の検査と動きの試験：できたプラグインのフォルダで、次のコマンドを動かします。AI クレジットを使いません。plugin-creator を入れていなくても動きます。

  ```shell
  python3 tests/run.py
  ```

- 試しに動かして採点する試験：チャットで「作ったプラグインを試験して」と頼みます。
  - AI クレジットを使うので、始める前に、実行の回数と使う AI クレジットの見込みが示されます。よいと答えてから始まります。
  - 見込みを出せないときは、そのことと、使った分を終わった後に示すことが伝えられます。

試験に要る道具（Python、Playwright など）が足りないときは、足りない道具と、入れ方と、入れる場所が示されます。よいと答えると、plugin-creator が入れます。試しに動かして採点する試験の道具は、`<COPILOT_HOME>/plugin-data/plugin-creator/tools/` に入ります（`<COPILOT_HOME>` は、ふつうはホームフォルダの `.copilot` です）。

## 使うために要る準備

次の3つを、最初に1回行います。

### 1. インストールする

```shell
copilot plugin marketplace add xclang-brain/plugin-creator
copilot plugin install plugin-creator@plugin-creator
```

- 1行目で、このリポジトリをマーケットプレイス（プラグインの一覧を配る場所）として登録します。2行目で、plugin-creator を入れます。
- `plugin-creator@plugin-creator` は、@ の前がプラグインの名前、後ろがマーケットプレイスの名前です。
- Copilot CLI の中では、`/plugin marketplace add xclang-brain/plugin-creator` と `/plugin install plugin-creator@plugin-creator` でも入れられます。
- GitHub からダウンロードしたフォルダから入れるときは、1行目の `xclang-brain/plugin-creator` の代わりに、そのフォルダの絶対パス（`/` や `~` から始まる場所）を書きます。

### 2. 試験的機能を有効にする

plugin-creator の画面と記録は、プラグインの中の部品（エクステンション）が動かします。エクステンションは、Copilot CLI の試験的な機能です（Copilot CLI 1.0.102 の時点）。有効にしないと、plugin-creator は使えません。

初めて使うときは、次のように起動します。一度付けると設定に残るので、次からは付けなくても有効です。

```shell
copilot --experimental
```

すでに起動しているときは、チャットで次のように打ちます。

```text
/settings experimental on
```

- Copilot CLI が自動で再起動して、有効になります。今の会話は終わります。
- 再起動の後、まだ信頼していないフォルダでは、フォルダを信頼するかの確認が出ます。続けて、次の「3. 読み込むときの確認を許可する」の確認が出ます（続けて2回出ることがあります）。

### 3. 読み込むときの確認を許可する

plugin-creator を読み込むとき、Copilot CLI がチャットに次の確認を出します。許可してください。断ると plugin-creator が読み込まれず、お話を始められません。

- 題：`Extension "plugin:plugin-creator:plugin-creator" wants elevated permissions`
- 本文：

  ```text
  This extension wants to: skip tool permission prompts, register hooks.
  Denying will prevent this extension from loading.
  ```

許可を自動で判定する設定（Assisted の許可）を使っていても、この確認は自動では許可されず、必ずあなたに出ます（Copilot CLI 1.0.101 から）。

選び方は次のとおりです。

| 選択肢 | 意味 |
| --- | --- |
| Yes | 今回だけ許可します。Copilot CLI を起動するたびと、`/clear` のたびに、また確認が出ます |
| Yes, and always allow "plugin:plugin-creator:plugin-creator" in this directory（後ろにフォルダの場所が付きます。作業フォルダが Git のリポジトリのときは、`in this directory` の代わりに `in this repo` と出ます） | このフォルダでは常に許可します。このフォルダでは、次から確認が出ません（`/clear` の後も、起動し直しても）。ほかのフォルダでは、また出ます |
| Yes, and don't ask again for "plugin:plugin-creator:plugin-creator" this session | フォルダが分からないときに、上の選択肢の代わりに出ます。このセッションの間は、確認が出ません |
| No (Esc) | 断ります。plugin-creator は読み込まれません |

確認の意味は次のとおりです。

- `skip tool permission prompts`（ツールの許可の確認を省く）：次のツールは、確認なしで動きます。お話の途中で、毎回確認が出ないようにするためです。
  - plugin-creator の画面を開くツール
  - お話で決まったことを、手元の記録に書くツール
  - あなたが示した Word・Excel・PowerPoint の文書の文字を読むツール（Copilot CLI を起動したフォルダの外の文書も読めます）

  plugin-creator に改善の要望（Issue）を出すツールだけは、毎回確認が出ます。
- `register hooks`（プラグインの中の部品〔フック〕を登録する）：次の2つを行います。
  - お話の間、問いと答えを手元のファイルに記録します。
  - 会話の自動の要約の後に1回だけ、AI に手順を読み直すよう知らせます。長いお話の途中で、手順が抜けないようにするためです。

## 知っておくこと

### 質問に答えが来ないとき

plugin-creator は、あなたにしか分からないことを推測で埋めません。答えが来ないときは止まります。

- 質問を Ctrl+D で断ったとき、Esc で閉じたとき、autopilot で動かしているとき：何を聞きたかったかと、続け方を示して止まります。プラグインは作られません。
  - 続けるには、チャットに答えを書きます。autopilot のときは、Shift+Tab でモードを切り替えて、autopilot を切ります。
  - 答えていない問いは、続けるときにもう一度聞かれます。
- `-p` や `--no-ask-user` を付けて起動したとき：質問のツールがないので、お話を始めません。これらを付けずに、対話モードで起動し直すよう示します。
- 作った後の2つの問い（試験の道具を入れるか、改善の要望を出すか）に答えが来なかったとき：止まらずに、入れない・出さないとして進みます。試験をしなかったことは、できたことの説明で示されます。

### 質問の改善の要望（Issue）

plugin-creator は、作った後と、あなたが試験を頼んだ後に、自分の質問の足りなかったところを振り返ります。そして、plugin-creator の GitHub リポジトリに出す改善の要望（Issue）の案を示すことがあります。案には、あなたの仕事の中身は書かれません。

- 案ごとに、出してよいかが聞かれます。よいと答えた案だけが出されます。
- 出すときに、Copilot CLI がツールの許可の確認を出します。この確認が、出してよいかの最後の歯止めです。
  - 確認では、毎回、今回だけ許可する選択肢を選んでください。このセッションの間や、ずっと許可する選択肢は選ばないでください。
  - Issue を出すツールを、起動のときの `--allow-tool` などで前もって許可することもしないでください。
- 出すには、gh（GitHub の公式のコマンド）を入れて、`gh auth login` でログインしておきます。

### お話の記録の置き場所と消し方

お話の途中経過は、セッションごとに次の場所に残ります。手元にだけ置かれ、外には送られません。

```text
<COPILOT_HOME>/plugin-data/plugin-creator/hearings/<セッションの番号>/
```

- `<COPILOT_HOME>` は、ふつうはホームフォルダの `.copilot` です（例：`~/.copilot/plugin-data/plugin-creator/hearings/`）。
- 中には、決まったことの記録（`state.json`）と、問いと答えの記録（`qa.jsonl`）があります。あなたの仕事の中身が入っています。
- 記録は自動では消えません。要らなくなったら、セッションの番号のフォルダを消します。すべて消すときは、`hearings` のフォルダを消します。
- 記録を消したセッションは、`--continue` や `--resume` で戻っても、続きから聞けません。

## うまく始まらないとき

チャットで頼んでも plugin-creator の画面の URL が示されないときは、plugin-creator のエクステンションが読み込まれていません。次のどれかです。

- 試験的機能を有効にしていない：「2. 試験的機能を有効にする」のとおりに、`copilot --experimental` で起動するか、`/settings experimental on` と打ちます。
- 読み込むときの確認を断った：Copilot CLI を起動し直して、出た確認を許可します。選び方は「3. 読み込むときの確認を許可する」にあります。
- エクステンションを使わない設定（`/extensions mode` の Disabled）にしている：`/extensions mode` で Load & Augment か Load Only に戻します。Disabled は、次のセッションにも残ります。
