# plugin-creator

あなたの仕事のやり方を AI に任せられるようにする、GitHub Copilot CLI のプラグインです。

チャットで質問に答えていくと、あなたの仕事の手順や決まりを組み込んだ Copilot CLI のプラグインを作り、試験までします。

## できること

| あなたが渡すもの | できあがるもの |
| --- | --- |
| チャットでの質問への答え（仕事の流れ、決まり、いつも使うファイル） | あなたの仕事をこなす Copilot CLI のプラグイン |
| 手元の既存のプラグイン（作り直したいとき） | 同じ仕事をこなす、作り直したプラグイン |

できあがるプラグインは、次のように動きます。

- まとめ役・作業役・確認役の AI に分かれて作業します。
- ブラウザーで開く作業の画面で、設定、作業の様子の確認、作業の停止、結果の確認ができます。

どんなやり取りになるかは、[会話例](examples/weekly-report.md)（AI が演じたユーザーとの会話）で見られます。

## はじめかた

### 1. インストールする

```shell
copilot plugin marketplace add xclang-brain/plugin-creator
copilot plugin install plugin-creator@plugin-creator
```

### 2. 試験的機能を有効にして起動する

できあがるプラグインを置きたいフォルダで、次のように起動します。

```shell
copilot --experimental
```

`--experimental` は、初めて使うときだけ付けます。設定に残るので、次からは付けなくても有効です。

### 3. 読み込むときの確認を許可する

起動すると、チャットに次の確認が出ます。

```text
Extension "plugin:plugin-creator:plugin-creator" wants elevated permissions
```

`Yes, and always allow ... in this directory`（Git のリポジトリでは `in this repo`）を選びます。このフォルダでは、次から確認が出なくなります。断ると、plugin-creator は使えません。確認の意味は「[読み込むときの確認](#読み込むときの確認)」にあります。

### 4. チャットで頼む

チャットで、次のように頼みます。

```text
週報づくりを自動化したい
```

`/plugin-creator:make-plugin` と打っても始められます。

## 使い方

1. チャットで頼むと、plugin-creator の画面の URL が示されます。ブラウザーで開くと、決まったことの一覧と、まだ聞いていないことが見られます。画面は見るだけです。答えや直しは、チャットで伝えます。
2. 質問に答えていきます。最近実際にやった1回の流れや、いつも使っているファイルも聞かれます。
3. 作る前に、次のものが示されます。直したいところを伝え、よいと答えると、プラグインが作られます。
   - 決まったことのまとめ
   - 作業の画面の見本
   - 試験でプラグインにさせる作業と、その合格の条件
4. 作業フォルダの中に、新しいフォルダ（git のリポジトリ）としてプラグインができます。試験の結果と使い方が、チャットに示されます。

できたプラグインの入れ方と使い方は、そのフォルダの `README.md` にあります。

### 手元のプラグインを作り直すとき

チャットで、作り直したいプラグインのフォルダを示して頼みます。

### 途中でやめて、後で続けるとき

途中でやめられます。前のセッションに戻ると、やめたところから続きが聞かれます。

| 戻り方 | コマンド |
| --- | --- |
| すぐに続ける | `copilot --continue` |
| 間に別のセッションを使った | `copilot --resume=<セッションの番号>`（番号は、やめるときにチャットに示されます） |

`/clear` や新しいセッションでは、最初から始まります。

## モデルの選び方

- 質問に答えて仕事のやり方を決める対話には、思考力の高いモデルが向いています。モデルは `/model` で変えられます。
- プラグインのファイルを書く仕事は、選んだモデルによらず、費用の低いモデル（GPT-6 Luna。使えないときは Claude Haiku 5.5）で行います。
- ただし、モデルを Auto にしていると、ファイルを書く仕事も Auto が選んだモデルで行います。

## できたプラグインを試験する

| 試験 | やり方 | AI クレジット |
| --- | --- | --- |
| ファイルの形の検査と、動きの試験 | できたプラグインのフォルダで `python3 tests/run.py` | 使わない（plugin-creator がなくても動きます） |
| 試しに動かして採点する試験（EVAL） | チャットで「作ったプラグインを試験して」と頼む | 使う |

- EVAL は、始める前に、実行の回数と使う AI クレジットの見込みが示され、よいと答えてから始まります。見込みを出せないときは、そう示され、使った分が終わった後に示されます。
- プラグインを直した後も、同じように試験できます。
- 試験に要る道具（Python、Playwright など）が足りないときは、足りない道具と入れ方と入れる場所が示されます。よいと答えると、plugin-creator が入れます。EVAL の道具は `<COPILOT_HOME>/plugin-data/plugin-creator/tools/` に入ります。

## うまく始まらないとき

チャットで頼んでも画面の URL が示されないときは、次のどれかです。

| 原因 | 直し方 |
| --- | --- |
| 試験的機能を有効にしていない | `copilot --experimental` で起動し直すか、チャットで `/settings experimental on` と打つ |
| 読み込むときの確認を断った | Copilot CLI を起動し直して、出た確認を許可する |
| `/extensions mode` を Disabled にしている | `/extensions mode` で Load & Augment か Load Only に戻す（Disabled は次のセッションにも残ります） |

`/settings experimental on` と打つと、Copilot CLI が自動で再起動し、今の会話は終わります。再起動の後に、フォルダを信頼するかの確認と、読み込むときの確認（2回続けて出ることがあります）が出ます。

### 質問に答えないと止まります

plugin-creator は、あなたにしか分からないことを推測で埋めません。

| こんなとき | どうなるか |
| --- | --- |
| 質問を Ctrl+D で断った、Esc で閉じた、autopilot で動かしている | 何を聞きたかったかと続け方を示して止まります。チャットに答えを書くか、Shift+Tab で autopilot を切ってください。答えていない質問は、続けるときにもう一度聞かれます。それまでプラグインは作られません |
| `-p` や `--no-ask-user` を付けて起動した | 質問ができないので、始めません。これらを付けずに起動し直してください |

作った後の「試験の道具を入れるか」「改善の要望を出すか」の質問だけは、答えがなくても止まらず、入れない・出さないとして進みます。

## 詳しい説明

### インストールの補足

- `plugin-creator@plugin-creator` は、@ の前がプラグインの名前、後ろがマーケットプレイス（プラグインの一覧を配る場所）の名前です。
- Copilot CLI の中では、`/plugin marketplace add xclang-brain/plugin-creator` と `/plugin install plugin-creator@plugin-creator` でも入れられます。
- ダウンロードしたフォルダから入れるときは、`xclang-brain/plugin-creator` の代わりに、そのフォルダの絶対パス（`/` や `~` から始まる）を書きます。
- フォルダを直接指定する入れ方（`copilot plugin install ./フォルダ`）は、Copilot CLI 1.0.102 で「廃止予定」と表示されるため、マーケットプレイスを通しています。

### 読み込むときの確認

確認の本文は次のとおりです。許可自動判定の設定（Assisted の許可）を使っていても、この確認は必ずあなたに出ます（Copilot CLI 1.0.101 から）。

```text
This extension wants to: skip tool permission prompts, register hooks.
Denying will prevent this extension from loading.
```

| 本文 | 意味 |
| --- | --- |
| `skip tool permission prompts`（ツールの許可の確認を省く） | 画面を開くツール、決まったことを手元に記録するツール、あなたが示した Word・Excel・PowerPoint の文書を読むツールが、確認なしで動きます（起動したフォルダの外の文書も読めます）。対話の途中で毎回確認が出ないようにするためです。改善の要望（Issue）を出すツールだけは、毎回確認が出ます |
| `register hooks`（フックを登録する） | 質問と答えを手元のファイルに記録します。会話の自動の要約（コンパクション）の後に1回だけ、AI に手順を読み直させます。長い対話で手順が抜けないようにするためです |

選択肢は次のとおりです。

| 選択肢 | 意味 |
| --- | --- |
| Yes | 今回だけ許可します。起動のたびと `/clear` のたびに、また確認が出ます |
| Yes, and always allow ... in this directory（Git のリポジトリでは `in this repo`） | このフォルダでは常に許可します。ほかのフォルダでは、また出ます |
| Yes, and don't ask again ... this session | フォルダが分からないときに、上の代わりに出ます。このセッションの間は確認が出ません |
| No (Esc) | 断ります。plugin-creator は読み込まれません |

### 質問の改善の要望（Issue）

作った後と試験の後に、plugin-creator が自分の質問の足りなかったところを振り返り、plugin-creator のリポジトリに出す改善の要望（Issue）の案を示すことがあります。案には、あなたの仕事の中身は書かれません。

- 案ごとに、出してよいかが聞かれます。よいと答えた案だけが出されます。
- 出すときに、Copilot CLI がツールの許可の確認を出します。これが最後の歯止めなので、毎回「今回だけ許可する」選択肢を選んでください。セッションの間やずっと許可する選択肢、起動のときの `--allow-tool` などで前もって許可することは、しないでください。
- 出すには、gh（GitHub の公式のコマンド）を入れて、`gh auth login` でログインしておきます。

### 対話の記録の置き場所と消し方

対話の途中経過は、手元の次の場所に、セッションごとに残ります。外には送られません。

```text
<COPILOT_HOME>/plugin-data/plugin-creator/hearings/<セッションの番号>/
```

- `<COPILOT_HOME>` は、ふつうは `~/.copilot` です。
- 中には、決まったことの記録（`state.json`）と、質問と答えの記録（`qa.jsonl`）があり、あなたの仕事の中身が入っています。
- 記録は自動では消えません。要らなくなったら、セッションの番号のフォルダを消します。すべて消すときは、`hearings` のフォルダを消します。記録を消したセッションは、戻っても続きから始められません。
