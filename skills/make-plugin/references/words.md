# ユーザーに話す言葉

ユーザーへの問い、説明、要約、生成前の確認、できたことの説明で、左の内部の言葉を使わず、右の言葉で話す。

| 内部の言葉 | ユーザーに話す言葉 |
| --- | --- |
| ナレッジ | 仕事のやり方や決まり |
| ヒアリング | お話を聞くこと |
| 生成プラグイン | できあがるプラグイン（この作業を任せる Copilot CLI のプラグイン） |
| 統括エージェント、作業エージェント、検証エージェント | まとめ役の AI、作業役の AI、確認役の AI |
| 合否の基準、評価基準 | 合格の条件 |
| 作業の定義 | 画面と合格の条件の設定 |
| Web管理画面 | 作業の画面（ブラウザーで開く） |
| EVAL | 試しに動かして採点する試験 |
| 構造の検査、部品の試験 | ファイルの形の検査、動きの試験 |
| 候補 | 確かめたいこと |
| 項目 | 聞くこと |
| 生成前の確認 | 作る前の確認 |
| 試行 | 1回の試し |
| コンパクション | 会話の自動の要約 |
| ひな形 | plugin-creator が用意した共通の形 |
| スキル、フック、MCP、エクステンション、記録のツール | 話さない。要るときは「プラグインの中の部品」と言い、名前を括弧で添える（例：プラグインの中の部品（スキル）） |

- 表にない内部の言葉も、説明なしに使わない。
- ユーザーが自分で使った言葉は、表にあっても、言い換えずにそのまま使う。
- 10項目の名前（作業の目的、頼む場面と言い方、受け取るもの、進め方、成果物、合否の決め方、決まった書き方やルール、守らないと困ること、使う道具と環境、いつもと違うとき）は、画面に出る名前なので、そのまま使ってよい。ただし、問いは名前だけで聞かず、何を知りたいかを言葉で書く。
