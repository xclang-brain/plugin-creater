# 質問の改善案

目的：自分の質問の足りなかったところを洗い出し、plugin-creator の GitHub リポジトリに出す Issue（改善の要望）の案を示す。質問は、使った結果をもとに直し続けるためである。make-plugin（生成の後）、change-plugin（直した後。「生成の後」を使う）、test-plugin（頼まれた試験の後）で使う。

## 見るもの

| とき | 見るもの |
| --- | --- |
| 生成の後（直した後も） | 1. `plugin-creator_state` を「振り返りの材料」つきで呼び、返った「質問の改善案の対象の仕事のやり方や決まり」を見る（その項目を聞いた後にユーザーが自分から話したものと、生成前の確認で足したもの）。<br>2. 同じ返り値の問答の記録のすべてを読み、聞き直しが続いた問いと、「分からない」と答えた問いを探す。<br>3. 試験で不合格になった原因のうち、ナレッジが足りなかったもの（下の注意） |
| 頼まれた試験の後 | 次の2つだけで見る。<br>1. 試験で不合格になった原因のうち、ナレッジが足りなかったもの（試験の結果と、生成プラグインの `tests/knowledge.json` で見る）<br>2. ユーザーが生成プラグインを直した内容のうち、ヒアリングで聞いていれば入ったもの（`git -C <生成プラグインのフォルダ> diff <印のタグ> -- .` で見る。印のタグは、生成プラグインのフォルダが git のリポジトリの直下（`git -C <生成プラグインのフォルダ> rev-parse --show-prefix` が空）なら `plugin-creator-generated`、そうでなければ `plugin-creator-generated-<plugin.json の name>`。この印がなければ、`git -C <生成プラグインのフォルダ> log --diff-filter=A --format=%H -- plugin.json` の最後の行のコミットからの差分で見る） |

- ナレッジの番号が見つからないという不合格は、作業エージェントの書き漏れで、聞き方の足りなさではないので数えない。数えるのは、聞いていないことが原因で落ちたものだけである。

## 案の書き方

- 決まった言葉だけで書く。Issue は公開のリポジトリに載ることがあるためである。
  - 書くもの：段階と項目の名前、起きたことの種類、数、問いの形（選択肢か自由入力か）、plugin-creator の版、対話のモデル
  - 書かないもの：問いの文、答え、ナレッジの文、ファイル名。問いの文にも、仕事の分野の言葉が入りうるためである。
- 起きたことの種類は、次のどれかにする：「聞いた後にユーザーが自分から話した」「生成前の確認で足された」「聞き直しが続いた」「『分からない』と答えた」「試験の不合格の原因がナレッジの不足だった」「ユーザーの直しが、聞いていれば入るものだった」
- 1件の案には、項目を1つだけ書く。同じ項目で起きたことは、1件にまとめる。案は重要な順に並べる。
- plugin-creator の版は、plugin-creator の `plugin.json`（`skills` フォルダの1つ上）の version である。対話のモデルは、今の会話のモデルの名前である。
- 案の例：
  - 題：「項目の点検：合否の決め方で、聞いた後にユーザーが自分から話したナレッジが2件」
  - 本文：「段階：項目の点検／項目：合否の決め方／起きたこと：聞いた後にユーザーが自分から話した（2件）／問いの形：自由入力／plugin-creator の版：（版）／対話のモデル：（モデルの名前）」

## 示し方と起票

- 見つからなかったときは、質問の改善案がないことを1行で示して終える。
- 案はチャットで示す。題と本文は決まった言葉のまま示し、その前に、どの聞き方が足りなかったかと、ユーザーの仕事の中身は入っていないことを、`references/words.md` の言葉で1〜2文で伝える。
- 案ごとに、出してよいかを聞く（承認の問い。おすすめを付けない）。問いの例：「出すと、この案が plugin-creator の公開の GitHub リポジトリに載ります。この案を出してよいですか？」選択肢は「出さない」「出す」の順にする。
- 出すと答えた案だけ、`plugin-creator_issue` に題と本文を渡す。このとき Copilot CLI がツールの許可の確認を出すことと、その確認では今回だけ許可する選択肢を選び、このセッションの間や、ずっと許可する選択肢を選ばないことを、先に伝える。次の案の確認が、出してよいかの歯止めになるためである。
- 出さないと答えた案と、答えが来なかった案は、出さない。
- gh がない、またはログインしていないと返ったときは、返った入れ方とログインのしかたを示す。
- 最後の案に答えてもらったら、出した案と出さなかった案の数を1文で示して終える。できたことの説明は、繰り返さない（すでに示したため）。
