# 段階「前回の1回」

目的：最近実際にやった1回をたどってもらう。本人が当たり前だと思っている手順や決まりは、項目ごとの問いでは話されにくいためである。この段階の始めに `references/deepen.md` も読む。

## 進め方

1. 最近実際にやった1回をたどってもらう（聞き出す問い）。話の途中で口を挟まない。聞き方は、頼みの文に作業の流れが順を追って書かれているかで分ける。
   - 頼みの文に流れが書かれていないとき：最初から終わりまで順に話してもらう。
     - 問いの例：「AI は、あなたがふだん当たり前にしている手順を知りません。最近この作業を実際にした1回を思い出して、最初にしたことから終わるまでを、順に書いてください。」
     - まだやったことがない作業だと答えたら、想定の1回を順に話してもらう（問いの例：「まだやったことのない作業でも、順番が分からないと AI は進められません。初めてやるとしたら、最初に何をして、そのあと何をしますか？終わるまでを順に書いてください。」）。この後の進め方は同じである。
   - 頼みの文に流れが書かれているとき：最初から書いてもらわない。頼みの文から理解した流れを、番号付きで問いの文の中に入れ、最近の1回で実際にしたことのうち、その流れに書かれていないことを聞く。頼みの文に書いた流れを最初から書くよう聞くと、ユーザーは頼みの文が伝わっていないと受け取るためである。
     - 問いの例：「AI は、あなたがふだん当たり前にしている手順を知りません。あなたが最初に書いた流れは、次のように理解しました。1. 〇〇 2. 〇〇 … 最近この作業を実際にした1回で、あなたがしたことのうち、この流れに書かれていないことは何ですか？」
     - まだやったことがない作業だと答えたら、その流れのほかにすることを聞く（問いの例：「まだやったことのない作業でも、流れにない手順が分からないと AI は進められません。初めてやるとしたら、この流れのほかに何をしますか？」）。この後の進め方は同じである。
2. 話を番号付きの短い時系列にして示し、違うところと足りないところを聞く（理解の確かめ）。頼みの文の流れを示したときは、答えで足した段と変わった段を入れた時系列にする。足した段も変わった段もなければ、この問いは出さない。
3. 時系列の抜けと、判断が要った段だけを、`references/deepen.md` の型で聞く。
4. 段階「読む」の候補と食い違うところは、その場で聞く（問いの例：「ファイルと前回のやり方が違うと、AI はどちらに合わせればよいか分かりません。ファイルでは A、前回は B でした。普段はどちらですか？」）。
5. 話に出た手順や決まりのうち、まだ聞いていないものは、その場で聞く。
6. 最後に、初めての人が間違えそうなところを1回聞く（問いの例：「初めての人がつまずくところは、AI もつまずきやすいところです。初めての人がやると、どこで間違えそうですか？」）。
7. 記録した内容を短く要約して示し、違うところと足りないところを聞く（理解の確かめ）。推し量ったことは、推し量ったと書く。同じことを繰り返して書かない。

## 記録

- 分かった決まりは、そのつど `plugin-creator_record` でナレッジにする。状態は「決まった」、出どころは「ヒアリングの答え」（前回の1回をたどる問いへの答えなので）、項目は10項目のうち当てはまるもの。
- 10項目の状態は、この段階では変えない。段階「項目の点検」で、分かったことを示して確かめる。
- 1の答えを受けたら、`plugin-creator_progress` で項目「前回の1回」を「聞いた」にし、答えの抜き書きを添える。抜き書きは、答えの中の言葉をそのまま写す（手順をつないだ要約にしない）。問いに示した頼みの文の流れからは写さない。頼みの文はユーザーの答えに数えられず、記録のツールが断るためである。
- 話の中身は、試験の課題とその入力のファイルの元にもなる（`references/confirm.md`）。

## 次へ

- ファイルから読んだ候補を記録していれば、段階を「決まりの確かめ」に進め、`references/rules.md` を読む。
- そうでなければ、段階を「項目の点検」に進め、`references/items.md` を読む。
