# 段階「決まりの確かめ」

目的：ファイル（作り直しでは元のプラグイン）から読み取った決まりの候補を、1つずつ確かめる。文書に書かれた決まりと実際のやり方は違うことが多く、確かめていない決まりを入れると、AI が間違ったやり方で作業するためである。

## 確かめる候補

- `plugin-creator_state` の返り値の「確かめたいこと（仕事のやり方や決まりのうち、状態が「候補」のもの）」のうち、出どころが「ファイルから読んで確かめた」か「既存のプラグインから読んで確かめた」のもの。頼みの文から記録した候補は、段階「項目の点検」で確かめる。
- 一覧が「ほか〇件」で切れているときは、示された候補を確かめた後に `plugin-creator_state` を呼び直すと、残りが出る。
- 生成プラグインの振る舞いに効く順に、1つずつ聞く。

## 問い

- 問いは「〜という決まりですか？」のままにし、読み取った場所（ファイル名と箇所）を添える。
- 問いの例：「ファイルから読み取った決まりが実際と違うと、AI が間違ったやり方で作業します。『〇〇は△△にする』という決まりですか？（〇〇.docx の2ページ目より）」
- 答えは、次の4つの選択肢を、この順に並べる。おすすめを付けない。

| 選択肢（この順） | 記録 | 続けて聞くこと |
| --- | --- | --- |
| そうしないときもある | 候補を「決まった」にし、どんなときかを例外の欄に書く。種類が「合否の決め方」なら、文も、例外のときに何なら合格かを書いた形に直す（例：「〇〇は△△にする。ただし□□のときは◇◇でよい」）。合格の条件には文だけが渡るためである | どんなときに、そうしないか（自由入力） |
| 違う | 候補を「外した」にし、本当はどうかを新しいナレッジにする（出どころは「ヒアリングの答え」） | 本当はどうするか（自由入力） |
| 決まりではなく、たまたまそうなっていた | 候補を「外した」にする | なし |
| このとおり | 候補を「決まった」にする | なし |

- 続けて聞く問いは別の問いになるので、確かめた決まりの文を問いの中に書き直し、なぜ聞くかの1文と、それだけで答えられる疑問文で書く（例：「例外を知らないと、AI はいつも同じやり方をします。『〇〇は△△にする』をしないのは、どんなときですか？」「本当のやり方が分からないと、AI は間違ったやり方で作業します。『〇〇は△△にする』ではないなら、本当はどうしていますか？」）。
- 記録は `plugin-creator_record` で、候補の番号を渡して直す。
