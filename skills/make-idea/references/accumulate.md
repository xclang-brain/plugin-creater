# 柱6 知識・経験の蓄積

目的：一通りの作業を終えてアイデアを作った後に振り返り、事前調査で学んだこと、気づいたこと、うまくいったこと、失敗したことを、知識・経験として残す。ログのように全部を残さず、本質を見極めて洗練した形で残す。残したものは、次からのすべての柱で使う。

## 知識・経験のファイル

- 置き場所：`<データの置き場所>/knowledge/`。柱ごとに1つのファイルである。

  | 柱 | ファイル |
  | --- | --- |
  | 1. 制限の決定 | `1-restriction.md` |
  | 2. 徹底的な事前調査 | `2-research.md` |
  | 3. 本質の見極め | `3-essence.md` |
  | 4. 本質の掛け合わせ | `4-combine.md` |
  | 5. アイデアの説明 | `5-explain.md` |
  | 6. 知識・経験の蓄積 | `6-accumulate.md` |

- ファイルは、見出し「# <柱の名前>の知識・経験」の下に、項目を並べる。1つの項目は次の形である。

  ```markdown
  ## K<柱の番号>-<通し番号> <本質の1文>
  - 例：<裏づけの具体例1件>
  - 出典：runs/<回>/<ファイル>
  - 制限：分野を問わない | <得た制限の短い名前>
  - 得た日：<年-月-日>
  - 確かさ：ユーザーが確かめた | エージェントの判定だけ
  ```

- 本質の1文は、次の回にそのまま使える形（「〇〇のときは、〇〇する。〇〇だからである」）で書く。出来事の記録（「〇〇をした」）にしない。
- 具体例と出典を必ず添える。短くしすぎると、大事な細かいことが消えるためである。

## 手順

### 1. 振り返る

- `knowledge/6-accumulate.md` を読み、使う項目を決める。
- `plugin-creator:idea-thinker` を「振り返りのエージェントの数」だけ、1つの応答で同時に起動する。頼みの文には次を書く。
  - 役：振り返り
  - 読むファイル：`<回のフォルダ>/state.md`、`research/plan.md`、`research/index.md`、`research/overview.md`、`essence/index.md`、`combine/log.md`、`combine/ranked.md`、`selection.md`、`explain/*/reading-*.md`、`knowledge-used.md`、`<データの置き場所>/knowledge/*.md`（あるものすべての絶対パス）
  - やり方：柱ごとに「なぜうまくいったか」「なぜだめだったか」「次に何を変えるか」を問い、答えに「それはなぜか」を重ねて本質を見極める。ユーザーの選択と理由（`selection.md`）は、良いアイデアかを決める手がかりとして重く見る。今ある項目と同じことは、新しく書かずに「K… を裏づける」と書く。ほかの振り返りのエージェントの結果は見ない。
  - 書くファイル：`<回のフォルダ>/reflect/reflection-<a>.md`
  - 返事：見つけた本質の数だけ。

### 2. 候補を作る

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：知識・経験の候補を作る
  - 読むファイル：`<回のフォルダ>/reflect/reflection-*.md`（すべて）、`<データの置き場所>/knowledge/*.md`（あるもの）
  - 制限の短い名前（回のフォルダの制限のファイルの「短い名前」の行を、自分で読み、その文字だけを頼みの文に写す。ファイルの名前と場所は書かない）
  - やり方：振り返りを集め、今ある項目と比べて、操作を決める。
    - 足す：新しい本質。上の項目の形で書く。
    - 直す：今ある項目を、より良い1文、より良い例にする。番号は変えない。
    - まとめる：似た項目を1つにする。残す番号と消す番号を書く。
    - 消す：誤りと分かった項目、使われていない古い項目。
  - 良さの判定を、新しさ・役立つか・価値の3つのほかにする項目（例：制限に合うものが良い、手元ですぐ試せるものが良い、ユーザーは環境に合うかで選ぶ）は、候補にしない。今ある項目にそう読めるものがあれば、「消す」の候補にする。制限は事前調査の取っかかりにすぎず、良さの判定に使うと、案が制限の中に押し込められるためである。
  - 全体を書き直さず、項目の単位で決める。2つ以上の振り返りのエージェントが挙げた本質と、ユーザーの選択で裏づけた本質を優先する。ユーザーの選択で裏づけた本質の確かさは「ユーザーが確かめた」、ほかは「エージェントの判定だけ」にする。制限の分野に依らない本質の「制限」は「分野を問わない」、依るものは、頼みの文に写した制限の短い名前にする。
  - 社名、製品名、人の名前、数値などの具体は、一般的な言い方に直す（例：「A社の〇〇」→「ある社内ツール」）。直すと意味がなくなるものは、印「具体あり」を付ける。
  - 書くファイル：`<回のフォルダ>/reflect/candidates.md`。候補ごとに、見出し「## 候補<番号> <操作> 柱<番号>」（番号は1から）を置き、その下に項目の全文（足す・直すなら `## K…` の見出しを1段下げた `### K…` から）か、まとめる・消す番号を書く。
  - 返事：候補の数と、「番号. 操作 柱 1文」の一覧。

### 3. 確かめる

- 返事の一覧を問いの文の中に書き、残したくない候補の番号を自由入力で聞く。印「具体あり」の候補は、その印も示す。
  - 問いの例：「次の候補を知識・経験として残し、次の回のすべての柱で使います。誤っているもの、社外に出せない具体を含むものなど、残したくない候補の番号を書いてください。なければ『なし』と書いてください。（一覧）」
- 答えを、`reflect/candidates.md` の終わりに、次の形の1行で書く（外す番号がなければ「外した番号：なし」）。保存の後に、外した候補が残っていないかを確かめられるようにするためである。

  ```markdown
  外した番号：1、4
  ```

### 4. 保存する

- 外さなかった候補を、柱ごとのファイルに、項目の単位で反映する（足す・直す・まとめる・消す）。ファイルがなければ、見出しから作る。番号は、柱ごとの通し番号の続きにする。
- 反映した後、各ファイルの大きさを見る。「知識・経験のファイル1つの大きさの上限（バイト）」の「まとめ始める大きさの割合（%）」を超えたファイルがあれば、そのファイルの項目のうち、まとめる・消す候補を2と同じやり方で作り、3と同じやり方で確かめてから反映する。上限を超えたままにしない。

### 5. 終わり

- 保存した件数（柱ごと）と、知識・経験のファイルの場所をチャットに示す。
- できた説明のファイルの場所を、もう一度示す。
- 作ったアイデアでプラグインを作るときも、今あるプラグインに足すときも、`/clear` してから、自分の言葉で make-plugin・change-plugin に頼むよう示す。アイデア創出の会話が、プラグインを作る記録・直す記録に混ざらないようにするためである。
- `knowledge-used.md` の「## 柱6」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
- `state.md` を「状態：終わり」「今の柱：6 知識・経験の蓄積」「次にすること：なし」にする。
