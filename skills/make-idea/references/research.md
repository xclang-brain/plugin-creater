# 柱2 徹底的な事前調査

目的：制限の中の作品を、Web で幅広く集め、評価を受けているものを掘り下げる。アイデアは既にあるものの組み合わせから生まれるので、組み合わせる材料を集める。

作品とは、公開のプラグイン・スキル・エージェント、道具・製品・OSS、手法、事例、記事、研究など、世の中に既にあるものである。

## 手順

### 1. 承認（手番を終える）

- `knowledge/2-research.md` を読み、使う項目を決める。
- 次を文章でチャットに書き、「始めてよければ『続けて』と書いてください。数を変えるときは、params.json を書き換えてから『続けて』と書いてください」と書いて、手番を終える。`ask_user` は使わない。手番を区切ると、長い調査の途中で会話が要約されても、このスキルの本文が残るためである。
  - 集める作品の数、掘り下げる作品の数、同時に調べるエージェントの数
  - これから起動するサブエージェントの数の見込み（下の「起動の数の見込み」）
  - Web の検索と取得を使うこと。Copilot CLI では、新しいサイトから取得するたびに確認が出ること。このセッションの間の許可を選ぶと同じサイトでは出なくなり、起動のときの `--allow-all-urls` か `/allow-all` で出なくできること（`/allow-all` はほかのツールの確認もなくす）
  - Copilot CLI では `/usage` で使った量を見られ、`/limits` で上限を決められること
- `state.md` の次にすることを「事前調査の承認の答えを待つ」にする。
- 答えが「続けて」なら、`params.json` を読み直して確かめ（書き換えたときのため。`references/start.md` の「パラメーターの確かめ」）、2に進む。やめる答えなら、`state.md` を「状態：途中」のままにして、続け方（後で同じ頼みをすると続きから始められる）を示して終える。

### 2. 集める

- 調べる切り口を、制限から「同時に調べるエージェントの数」だけ決める。切り口は互いに重ならないようにし、制限に近い分野と遠い分野の両方を入れる。例：公開のプラグインとスキル、その分野の道具と製品、技術記事と事例、研究と手法、遠い分野で評価されている作品。
- 1体の目標の数は、集める作品の数を、同時に調べるエージェントの数で割って切り上げた数である。
- `plugin-creator:idea-researcher` を、切り口ごとに1体、1つの応答で同時に起動する。頼みの文には次を書く。
  - 役：集める
  - 制限の要点（目的、範囲、必ず満たす条件）と、自分の切り口
  - 目標の数
  - 書くファイル：`<回のフォルダ>/research/collect-<n>.md`（n はエージェントの番号）
  - 使う知識・経験の項目（役に立った情報源、調べ方）
- 返事（集めた数と短い要約）を `state.md` に書く。

### 3. 一覧を作り、掘り下げる作品を選ぶ

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：一覧を作る
  - 読むファイル：`<回のフォルダ>/research/collect-*.md`（すべての絶対パス）、`<回のフォルダ>/restriction.md`
  - URL が同じものを1つにまとめ、番号を振って一覧にする。評価の手がかり（スター数、ダウンロード数、採用例、受賞、レビュー、引用数）を見て、評価を受けている作品を「掘り下げる作品の数」だけ選ぶ。制限に近い分野だけでなく、遠い分野で評価されているものも入れる。
  - 書くファイル：`<回のフォルダ>/research/index.md`。1行に1つの作品で、番号、名前、URL、評価の手がかり（短く）、掘り下げるなら「掘り下げ：<理由を短く>」だけを書く。説明は `collect-*.md` に残す。
  - 返事：重なりを除いた作品の数と、掘り下げに選んだ数だけ。
- 重なりを除いた数が、集める作品の数より少なければ、足りない数を、切り口を足して2と同じやり方で集め直し、3をやり直す。集め直しは「集め直しの回数の上限」までにする。それでも足りなければ、数と理由を示し、`ask_user` で進め方を聞く（決める問い）。選択肢は「切り口を変えてもう一度集める（おすすめ）」「今の数で進む」。おすすめの理由は「作品が多いほど、組み合わせる材料が増える」。

### 4. 掘り下げる

- 掘り下げに選んだ作品を、「1体が掘り下げる作品の数」ずつの束に分ける。
- `plugin-creator:idea-researcher` を、束ごとに1体起動する。同時に起動するのは、同時に調べるエージェントの数までである。頼みの文には次を書く。
  - 役：掘り下げる
  - 掘り下げる作品の番号・名前・URL（`index.md` の行をそのまま写す）
  - 書くファイル：`<回のフォルダ>/research/deep-<n>.md`
- 返事（掘り下げた数）を `state.md` に書く。

### 5. 終わり

- 集めた作品の数、掘り下げた作品の数、`research/index.md` の場所をチャットに示す。
- `knowledge-used.md` の「## 柱2」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
- `state.md` を「今の柱：3 本質の見極め」にし、`references/essence.md` を読む。

## 起動の数の見込み

パラメーターから数えて示す。P は壁打ちの相手のエージェントの数、R は説明を読む第三者のエージェントの数、N は壁打ちの往復の数、F は説明を直す回数の上限である。

| 柱 | 数え方 |
| --- | --- |
| 徹底的な事前調査 | 同時に調べるエージェントの数 ＋ 1 ＋ 掘り下げる作品の数 ÷ 1体が掘り下げる作品の数（切り上げ） |
| 本質の見極め | なぜなぜ分析をするエージェントの数 ×（1 ＋ 2 × 意見を出し合う往復の数）＋ 1 |
| 本質の掛け合わせ | 壁打ちする案の総数 ÷ 1つの組から作る案の数（切り上げ）×（1 ＋ P ＋（N − 1）×（1 ＋ P）） |
| アイデアの説明 | 説明するアイデアの数の上限 ×（2 ＋ R ×（1 ＋ F）＋ F） |
| 知識・経験の蓄積 | 振り返りのエージェントの数 ＋ 1 |

- 集め直しや、組がだめで選び直すと、数が増えることも書く。
- AI クレジットの見込みは示さない。1回の起動の費用は、モデルとプランで変わるためである。
