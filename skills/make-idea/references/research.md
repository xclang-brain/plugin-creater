# 柱2 徹底的な事前調査

目的：制限の中で考えられる関連情報を、できる限り幅広く、時間をかけて調べる。世の中にある作品を集め、その中から評価を受けているものを掘り下げる。アイデアはゼロから生まれるのではなく、既にあるものの組み合わせから生まれると捉える。速くするため、複数のエージェントで並列に調べる。

作品とは、公開のプラグイン・スキル・エージェント、道具・製品・OSS、手法、事例、記事、研究など、世の中に既にあるものである。

調べ方は、ディープリサーチ（調べる計画を立て、多くの情報源を並列に検索して元のページを読み、足りないところを見つけて調べ直し、引用つきでまとめることを繰り返す調べ方）にする。急いで終えない。件数を決めて選ぶのではなく、評価を受けていると確かめた作品をすべて掘り下げる。

制限（`restriction.md`）を使うのは、この柱だけである。調べる範囲を決める取っかかりにする。

調査のエージェントが「検索の回数の上限で断られた」と返したら、それ以上起動せず、`state.md` を「状態：途中」のままにして止まる。続け方として、Claude Code なら環境変数 `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` を上げて起動し直し、同じ頼みをすると続きから始められることを示す。Claude Code の検索は、1つのセッションで200回までのためである。

## 手順

### 1. 承認（手番を終える）

- `knowledge/2-research.md` を読み、使う項目を決める。
- 次を文章でチャットに書き、「始めてよければ『続けて』と書いてください。数を変えるときは、params.json を書き換えてから『続けて』と書いてください」と書いて、手番を終える。`ask_user` は使わない。手番を区切ると、長い調査の途中で会話が要約されても、このスキルの本文が残るためである。
  - 集める作品の数、調べ直しの回数、掘り下げで1件に読む情報源の数、同時に調べるエージェントの数
  - 掘り下げる件数は決めず、評価を受けていると確かめた作品をすべて掘り下げること
  - これから起動するサブエージェントの数の見込み（下の「起動の数の見込み」）と、時間をかけて調べること
  - Web の検索と取得を使うこと。Copilot CLI では、新しいサイトから取得するたびに確認が出ること。このセッションの間の許可を選ぶと同じサイトでは出なくなり、起動のときの `--allow-all-urls` か `/allow-all` で出なくできること（`/allow-all` はほかのツールの確認もなくす）
  - Copilot CLI では `/usage` で使った量を見られ、`/limits` で上限を決められること
- `state.md` の次にすることを「事前調査の承認の答えを待つ」にする。
- 答えが「続けて」なら、`params.json` を読み直して確かめ（書き換えたときのため。`references/start.md` の「パラメーターの確かめ」）、2に進む。やめる答えなら、`state.md` を「状態：途中」のままにして、続け方（後で同じ頼みをすると続きから始められる）を示して終える。

### 2. 調べる計画を立てる

- シェルで今の時刻を出し、`state.md` に「柱2の始め：<時刻>」と書く。
- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：調べる計画を立てる
  - 読むファイル：`<回のフォルダ>/restriction.md`
  - やり方：制限の目的から、調べて答えたい問い（例：この範囲で評価を受けている作品は何か。使う人は何に困っているか。同じ困りごとを別の分野ではどう解いているか）を書く。調べる切り口を、「同時に調べるエージェントの数」以上、互いに重ならないように決める。切り口には、制限に近い分野と、遠い分野（同じ困りごとを別の分野でどう解いているか、別の分野で評価されている仕組み）の両方を入れる。切り口ごとに、日本語と英語の検索語を5つ以上と、当たる情報源（公式のマーケットプレイス、一覧、パッケージの登録所、論文の検索、利用者の議論の場など）を書く。作品の種類（OSS、製品、論文、手法、事例など）ごとに、何があれば「評価を受けている」とするか（例：OSS はスター数・ダウンロード数・採用例、論文は採択された場・引用数、製品はレビュー・受賞・利用者数、手法は採用した組織）を書く。
  - 使う知識・経験の項目（役に立った情報源、調べ方）
  - 書くファイル：`<回のフォルダ>/research/plan.md`
  - 返事：切り口の数だけ。

### 3. 集める（1回目）

- `plugin-creator:idea-researcher` を、切り口ごとに1体、1つの応答で同時に起動する（同時に調べるエージェントの数まで。切り口がそれより多ければ、終わるのを待って次を起動する）。頼みの文には次を書く。
  - 役：集める
  - 制限の要点（目的、範囲）
  - 読むファイル：`<回のフォルダ>/research/plan.md`（自分の切り口の番号を書く）
  - 目標の数：集める作品の数を、切り口の数で割って切り上げた数
  - 書くファイル：`<回のフォルダ>/research/collect-<n>-r0.md`（n は切り口の番号）
- 返事（集めた数、読んだページの数）を `state.md` に書く。

### 4. 調べ直す（調べ直しの回数だけ繰り返す）

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：足りないところを見つける
  - 読むファイル：`<回のフォルダ>/research/plan.md`、`<回のフォルダ>/research/collect-*.md`（すべて）
  - やり方：計画の問いのうち答えが薄いもの、作品が近い分野に偏っているところ、評価の手がかりが取れていない種類、まだ当たっていない情報源を見つける。それを埋める新しい切り口を「同時に調べるエージェントの数」だけ、日本語と英語の検索語つきで書く。
  - 書くファイル：`<回のフォルダ>/research/gaps-r<k>.md`（k は何回目の調べ直しか。1から）
  - 返事：新しい切り口の数だけ。
- 新しい切り口ごとに、3と同じやり方で `plugin-creator:idea-researcher` を同時に起動する。読むファイルは `gaps-r<k>.md`（切り口の番号を書く）、書くファイルは `collect-<n>-r<k>.md` である。すでに集めた作品と重ならないよう、`collect-*.md` の場所も渡す。
- 返事（集めた数、読んだページの数）を `state.md` に書く。

### 5. 一覧を作り、評価を確かめる

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：一覧を作る
  - 読むファイル：`<回のフォルダ>/research/plan.md`、`<回のフォルダ>/research/collect-*.md`（すべて）
  - やり方：URL が同じものを1つにまとめ、番号を振って一覧にする。計画の「評価を受けている」の基準と、集める役が元のページで確かめた評価の手がかりを比べ、作品ごとに評価を「あり」「未確認」「なし」のどれかにする。
  - 書くファイル：`<回のフォルダ>/research/index.md`（大きいときは `index-2.md`…）。1行に1つの作品で、`- <番号> | <名前> | <URL> | <種類> | 評価：<あり・未確認・なし> | <評価の手がかり（短く、出どころつき）>` の形だけを書く。番号は1からの整数。説明は `collect-*.md` に残す。
  - 返事：重なりを除いた作品の数と、評価が「あり」「未確認」「なし」の数だけ。
- 重なりを除いた数が、集める作品の数より少なければ、数と理由を示し、`ask_user` で進め方を聞く（決める問い）。選択肢は「切り口を足して調べ直す（おすすめ）」「今の数で進む」。おすすめの理由は「作品が多いほど、組み合わせる材料が増える」。調べ直すなら、4をもう1回行い、5をやり直す。
- 評価が「未確認」の作品を、「1体が掘り下げる作品の数」の2倍ずつの束に分け、`plugin-creator:idea-researcher` を束ごとに起動する（同時に調べるエージェントの数まで）。頼みの文には次を書く。
  - 役：評価を確かめる
  - 確かめる作品の行（`index.md` の行をそのまま写す）と、計画の「評価を受けている」の基準
  - 書くファイル：`<回のフォルダ>/research/eval-<n>.md`
- `plugin-creator:idea-thinker` を1体起動し、役「一覧を直す」として、`index.md` と `eval-*.md` を読ませ、評価の欄を書き直させる。返事は、評価が「あり」の数だけ。

### 6. 掘り下げる

- 評価が「あり」の作品をすべて、「1体が掘り下げる作品の数」ずつの束に分ける。件数を決めて選ばない。
- `plugin-creator:idea-researcher` を、束ごとに1体起動する。同時に起動するのは、同時に調べるエージェントの数までである。頼みの文には次を書く。
  - 役：掘り下げる
  - 掘り下げる作品の番号・名前・URL（`index.md` の行をそのまま写す）
  - 1件に読む情報源の数：掘り下げで1件に読む情報源の数
  - 書くファイル：`<回のフォルダ>/research/deep-<n>.md`
- 返事（掘り下げた数、読んだページの数）を `state.md` に書く。

### 7. まとめる

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：調査のまとめ
  - 読むファイル：`<回のフォルダ>/research/plan.md`、`index.md`、`deep-*.md`（すべて）
  - やり方：計画の問いごとに、分かったことを引用（作品の番号と URL）つきでまとめる。分野ごとに、評価を受けている作品と、評価された理由の傾向を書く。利用者の困りごとの声を、出どころつきで集める。調べきれなかったことも書く。
  - 書くファイル：`<回のフォルダ>/research/overview.md`（20,000 バイト未満）
  - 返事：問いの数だけ。

### 8. 終わり

- シェルで今の時刻を出し、`state.md` に「柱2の終わり：<時刻>」と、読んだページの数（返事の数の合計）を書く。
- 集めた作品の数、評価を確かめた作品の数（「あり」の数）、掘り下げた作品の数、読んだページの数、柱2にかかった時間、`research/index.md` と `research/overview.md` の場所をチャットに示す。
- `knowledge-used.md` の「## 柱2」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
- `state.md` を「今の柱：3 本質の見極め」にし、`references/essence.md` を読む。

## 起動の数の見込み

パラメーターから数えて示す。C は同時に調べるエージェントの数、K は調べ直しの回数、D は1体が掘り下げる作品の数、P は壁打ちの相手のエージェントの数、R は説明を読む第三者のエージェントの数、N は壁打ちの往復の上限、F は説明を直す回数の上限である。

| 柱 | 数え方 |
| --- | --- |
| 徹底的な事前調査 | 1 ＋ C ×（1 ＋ K）＋ K ＋ 2 ＋ 評価の確かめ（未確認の数 ÷ 2D の切り上げ）＋ 掘り下げ（評価ありの数 ÷ D の切り上げ。多くて 集める作品の数 ÷ D）＋ 1 |
| 本質の見極め | まとまりの数（掘り下げる作品の数 ÷ 1体が分析する作品の数 の切り上げ）× なぜなぜ分析をするエージェントの数 ×（1 ＋ 2 × 意見を出し合う往復の数）＋ 集約（出し直しのファイルの数 ÷ 1体が集約する出し直しのファイルの数 の切り上げ ＋ 1） |
| 本質の掛け合わせ | 組の数（壁打ちする案の総数 ÷ 1つの組から作る案の数 の切り上げ）×（2 ＋ P ＋（N − 1）×（2 ＋ P））まで ＋ 1 |
| アイデアの説明 | 説明するアイデアの数の上限 ×（2 ＋ R ×（1 ＋ F）＋ F） |
| 知識・経験の蓄積 | 振り返りのエージェントの数 ＋ 1 |

- 調べ直しや、組がだめで選び直すと、数が増えることも書く。
- AI クレジットの見込みは示さない。1回の起動の費用は、モデルとプランで変わるためである。
