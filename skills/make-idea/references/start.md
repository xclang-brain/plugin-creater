# 始まり

目的：データの置き場所とパラメーターを確かめ、続きか新しいかを決める。

## 読み直したとき

この会話で既に回を始めていて、コンパクションの後などに make-idea を読み直したときは、下の手順をしない。その回の `state.md` を読み、今の柱の「始めに読む」のファイルを読んで、次にすることから続ける。この会話の回のフォルダが分からないときだけ、下の手順で進める。

## 手順

1. `ask_user` があるかを確かめる（ツールを探すツールがあれば、それでも探す）。なければ、本文の「始められないとき・答えが来ないとき」のとおりにして止まる。
2. この会話で make-plugin・change-plugin・test-plugin のどれかを使っていたら、`/clear` してから頼み直すよう示して止まる。
3. データの置き場所を決める。
   - シェルで `echo $HOME` を動かし、ホームフォルダの絶対パスを知る（bash でも PowerShell でも同じコマンドで出る）。
   - データの置き場所は `<ホーム>/.plugin-creator/make-idea/` である。以下、ファイルはすべて絶対パスで扱う。
4. パラメーターを用意する。
   - `<データの置き場所>/params.json` がなければ、スキルのフォルダの `assets/params.json`（「Base directory for this skill」からの絶対パス）を読み、同じ中身で `<データの置き場所>/params.json` を作る。
   - `params.json` を読み、下の「パラメーターの確かめ」のとおりに確かめる。止まる値があれば、その項目と直し方を示して止まる。
5. 知識・経験の件数を数える。`<データの置き場所>/knowledge/` の各ファイルの中で、`## K` で始まる行を探して数える。ファイルがなければ0件とする。
6. 使う値を示す。次を文章でチャットに書く。
   - 使うパラメーターの値（柱ごとに、名前と値。既定の値と違うものには印を付ける）
   - 知識・経験の件数（柱ごと）
   - データの置き場所と、パラメーターを変えるときに書き換えるファイルの場所
   - データの置き場所は作業フォルダの外にあるので、Copilot CLI では、初めて読み書きするときにフォルダの使用の確認が出ること。確認でこのセッションの間の許可を選ぶか、前もって `/add-dir <データの置き場所>` を打てば、何度も出ないこと
   - これからの流れ（6つの柱の名前を順に）
7. 途中の回を探す。`<データの置き場所>/runs/*/state.md` のうち、「状態：途中」と書いてあるものを探す。
   - あれば、`ask_user` で、どの回を続けるか、新しく始めるかを聞く（決める問い。選択肢は、回のフォルダの名前と今の柱を書いたもの、「新しく始める」。おすすめは、いちばん新しい途中の回）。
   - 続けるなら、その回の `state.md` を読む。次にすることが柱1の中か、「事前調査の承認の答えを待つ」なら、今の柱の「始めに読む」のファイルを読んで、次にすることから続ける。それ以外なら、回のフォルダ、今の柱、次にすることを文章でチャットに書き、「続けるときは『続けて』と書いてください」と書いて、`ask_user` を使わずに手番を終える。答えが来たら、今の柱の「始めに読む」のファイルを読んで、次にすることから続ける。手番を区切ると、長い柱の途中で会話が要約されても、このスキルの本文が残るためである。下の8はしない。
8. 新しい回を始める。
   - 回のフォルダ `<データの置き場所>/runs/<年月日-時分>/` を作る（例：`20261027-1530`）。年月日と時分は、シェルの `date` などで今の日時を見て決める。
   - `state.md` を次の形で作る。

     ```markdown
     # 状態
     - 状態：途中
     - 今の柱：1 制限の決定
     - 次にすること：制限の候補を書き出す
     - 使うパラメーター：<データの置き場所>/params.json
     - 更新：<年-月-日 時:分>
     ```

   - `knowledge-used.md` を、見出し「# 使った知識・経験」だけで作る。
   - `references/restriction.md` を読み、柱1を始める。

## パラメーターの確かめ

`params.json` は、柱ごとの表に、名前と値を持つ。次のどれかに当たれば、使わずに止まる。

- JSON として読めない。柱の名前の値が、名前と値の表になっていない。
- 既定の `assets/params.json` にある名前がない。既定にない名前がある。
- 値が整数でない、または1より小さい。
- 「一度に掛け合わせる本質の数」の `最小` が2より小さい、または `最小` が `最大` より大きい。
- 「掛け合わせる数を変える順」の数のどれかが、`最小` から `最大` の外にある。
- エージェントの数（なぜなぜ分析をするエージェントの数、壁打ちの相手のエージェントの数、説明を読む第三者のエージェントの数、振り返りのエージェントの数）が2より小さい。2者以上で行うことが柱の中身だからである。
- 「本質の数」が、「一度に掛け合わせる本質の数」の `最大` より小さい。
- 「1体が掘り下げる作品の数」が20より大きい。1体が書くファイルが、読める大きさを超えるためである。
- 「選ぶ一覧で詳しく示す案の数」が「説明するアイデアの数の上限」より小さい。選べる案に、比べる材料がなくなるためである。
- 「まとめ始める大きさの割合（%）」が100より大きい。

件数や個数を既定より小さくしたものは、止めずにそのまま使い、6で印を付けて示す。
