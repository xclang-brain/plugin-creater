# 柱3 本質の見極め（なぜなぜ分析）

目的：集めた作品に対し、「なぜ評価されているのか」「なぜこの形なのか」と、できる限り多くの疑問を投げかける。なぜなぜ分析を重ね、表面的な特徴の奥にある本質を探る。一人で完結させず、複数のエージェントで互いの分析に意見を出し合って、本質を磨く。洗練された本質をたくさん用意する。

良いアイデアは、誰かの生活や仕事を豊かにしたり、便利にしたりする。だから、この柱から「誰にどんなメリットがあるか」を持つ。仕組みの原理だけにたどり着いた本質は、誰にどんなメリットがあるかが抜け、良いアイデアにつながらない。

この柱から後では、制限（`restriction.md`）を使わない。サブエージェントに場所も中身も渡さない（本文の先頭の決まり10）。

## なぜなぜ分析の形

- 作品ごとに、最初の問いを「なぜ評価されているのか」にする。答えは、柱2の掘り下げで集めた評価の材料（利用者の声、レビュー、論文の評価、採用の理由）の引用にもとづいて書く。
- どの作品にも、次の2つの問いを必ず投げる。答えは、利用者の声やレビューなど、恩恵を受けた人の言葉の引用にもとづいて書く。
  - 「誰にとって恩恵があるのか」：恩恵を受ける人を、「〈どの場面〉で〈何をする〉〈どんな立場〉の人」の形で、立場と場面が分かるように書く。「利用者」「開発者」だけで止めない。
  - 「その人の生活や仕事の何が、どう良くなったのか」：前と後で何が変わったかを書く（例：減った手間、防げた失敗、できるようになったこと）。
- 続けて「なぜこの形なのか」「なぜほかの作り方ではないのか」「なぜその人はそれを求めるのか」など、できる限り多くの疑問を投げかける。
- 答えに「それはなぜか」を重ねる。各段は、前の段の問いへの答えにする。各段に根拠（引用か作品の番号）を付け、根拠がない段には「仮説」と印を付ける。
- 止めるのは、段の数ではなく中身で決める。道具の機能を言い換えただけの段（「〇〇できるから」）や、仕組みの原理だけの段（「型が何を言うかを決めるから」）では止めない。「誰が、どんな場面で、何が良くなるか」に届いたら止める。段の数は、なぜを重ねる段の上限までにする。

  ```markdown
  ## <作品の番号> <作品の名前>
  - なぜ評価されているのか → <答え（引用）> → なぜか → <答え（根拠）> → なぜか → …
  - 誰にとって恩恵があるのか → <人（立場と場面。引用）>
  - その人の生活や仕事の何が、どう良くなったのか → <前と後の違い（引用）> → なぜか → <答え（根拠）> → …
  - なぜこの形なのか → …
  - たどり着いた本質：S<番号>（誰に：…。どんなメリットが：…）
  ```

## 本質の形

- 本質は、次の3つで書く。
  - 誰に：恩恵を受ける人（立場と場面が分かるように）
  - どんなメリットが：その人の生活や仕事の何が、どう良くなるか
  - なぜそうなるか：そのメリットを生む仕組み
- 3つは、専門外の人が一度読んで分かる日本語の1〜2文ずつで書く（下の「文の書き方」）。作品の番号、英語の引用、略語は入れない。
- たどり着いた「なぜ」の連なり（作品の番号と、段を「→」でつないだ短い形）を、別の行に添える。
- 裏づけの作品の番号と、引用（README、レビューなど）を、別の行に付ける。引用がないものは「仮説」と印を付ける。
- 誰にどんなメリットがあるかを書けないものは、本質にしない。使い心地のようなものも、「毎日使う人が、迷わずに済む」のように、誰にどんなメリットかで書く。
- ほかの本質の言い換えは、別の本質として数えない。1つの本質を細かく割って数を増やさない。作品の機能をそのまま言い換えたものは、本質として数えない。

## 文の書き方

本質の「誰に」「どんなメリットが」「なぜそうなるか」は、人が読んで分かる日本語で書く。

- 専門外の人が、一度読んで分かる文にする。1つの文に1つのことを書き、誰が（何が）を書く。
- 略語、専門用語、英語を使わない。どうしても要るときは、初めて出たところで言い換える。
- 作品の番号、引用、論文名、出典は入れず、「なぜ」と「裏づけ」の行に書く。
- 手法や仕組みから書き始めず、誰の生活や仕事の何が、どう良くなるかから書く。
- 「→」「／」などの記号で文をつながない。

## 手順

### 1. 分ける

- シェルで今の時刻を出し、`state.md` に「柱3の始め：<時刻>」と書く。
- `knowledge/3-essence.md` を読み、使う項目を決める。過去の本質は、今回の作品で裏づけられなくても候補にする。優れた発明家は、事前調査の情報だけでなく、自分の過去の経験と知識からアイデアを作るためである。
- 掘り下げた作品は多いので、まとまりに分けて分析する。`research/deep-*.md` の束（`deep-<n>.md` と、分けて書かれた `deep-<n>-2.md`…）を、番号の順に、1つのまとまりの作品の数が「1体が分析する作品の数」を超えないように分ける。まとまりの番号は c01、c02…とする。分け方（まとまりごとの束の番号）を `essence/chunks.md` に書く。1人のエージェントがすべての作品を読むと、読みきれないためである。
- 分析の観点を、「なぜなぜ分析をするエージェントの数」だけ決める。観点は互いに違うものにする。例：恩恵を受ける人と、その人の生活や仕事の変化、その形でなぜ恩恵が生まれるか、広まり方と使われ方。どの観点でも、作品ごとに「誰にとって恩恵があるのか」「その人の生活や仕事の何が、どう良くなったのか」を投げる。観点の番号は a1、a2…とする。

### 2. 独立の分析

- まとまりごとに、`plugin-creator:idea-thinker` を観点ごとに1体、1つの応答で同時に起動する。同時に起動できる数の上限で断られたら、終わるのを待ってから次のまとまりを起動する。頼みの文には次を書く。
  - 役：なぜなぜ分析
  - 自分の観点
  - 読むファイル：自分のまとまりの `<回のフォルダ>/research/deep-*.md`（分けて書かれたものも含めて、すべての絶対パス）、`<回のフォルダ>/research/overview.md`
  - やり方：上の「なぜなぜ分析の形」のとおりに、まとまりの作品をすべて分析する（全文を写して渡す）。たどり着いた本質を、上の「本質の形」と「文の書き方」で書く（どちらも全文を写して渡す）。
  - 使う知識・経験の項目（過去の本質の候補、役に立った問い方）。過去の本質は、今回の作品で裏づけられたら作品の番号を、裏づけられなければ「過去の本質（K…）」と出典を付けて出してよい。
  - 書くファイル：`<回のフォルダ>/essence/whys-<まとまり>-<観点>.md`（例：`whys-c01-a1.md`）。自分でファイルに書く。20,000 バイトを超えそうなら、`whys-c01-a1-2.md`、`whys-c01-a1-3.md` に分けて書く。
  - 返事：出した本質の数と、書いたファイルの名前だけ。
- このとき、ほかのエージェントのファイルの場所は渡さない。互いを見ずに分析させるためである。
- 返事が「ファイルに書けなかった」なら、自分で書き写さず、書けなかった理由を `state.md` に書き、もう一度同じ役を頼む。縮めて書き写すと、なぜの段が消えるためである。
- まとまりごとに、返事を `state.md` に書く。

### 3. 意見の出し合い（往復の数だけ繰り返す）

まとまりごとに、同じまとまりを分析したエージェントどうしで行う。

- 観点 a ごとに、`plugin-creator:idea-thinker` を1体ずつ、同時に起動する。頼みの文には次を書く。
  - 役：ほかの分析への意見
  - 読むファイル：同じまとまりの、自分（a）の前の版の分析と、ほかの観点の前の版の分析（1回目は `whys-<まとまり>-*.md`、2回目からは前の回の `final-<まとまり>-*.md`。分けて書かれたものもすべて）
  - やり方：ほかの分析の主な主張を、まずいちばん強い形で言い直す。そのあと、相手ごとに次を書く。
    - なぜの浅さ：機能の言い換えで止まっている段、前の段の問いの答えになっていない段、根拠のない段。どの作品のどの段かを示す。
    - 根拠の弱いところ、言い換えにすぎない本質、見落とした本質、抽象的すぎる本質（例：「便利にする」）。
    - 誰にどんなメリットがあるかが書かれていない本質、「誰にとって恩恵があるのか」を問うていない作品、仕組みの原理だけで止まっている連なり。
    - 人が読んで分からない文（上の「文の書き方」に合わないもの）。そのまま引用する。
  - 書くファイル：`<回のフォルダ>/essence/opinion-<まとまり>-<観点>-r<k>.md`（k は何回目か）
- 次に、観点 a ごとに、`plugin-creator:idea-thinker` を1体ずつ、同時に起動する。頼みの文には次を書く。
  - 役：本質の出し直し
  - 読むファイル：自分の前の版の分析、ほかのエージェントが書いた意見のファイル（同じまとまりの `opinion-<まとまり>-*-r<k>.md` のうち、自分あての部分）、自分のまとまりの `research/deep-*.md`
  - やり方：意見を受けて、浅い段を掘り直し、本質を直し、足し、外して出し直す。誰にどんなメリットがあるかが書かれていない本質は、作品に戻って「誰にとって恩恵があるのか」を問い直す。本質は「本質の形」と「文の書き方」で書く（全文を写して渡す）。本質ごとに「なぜ」の連なりを残す。ほかのエージェントの出し直しの結果は見ない。同調しないためである。
  - 書くファイル：`<回のフォルダ>/essence/final-<まとまり>-<観点>.md`（大きいときは `final-<まとまり>-<観点>-2.md`…）
  - 返事：出し直した本質の数だけ。

### 4. 集約

集約は2段で行う。出し直しのファイルが多く、1人では読みきれないためである。

- 1段目：`final-*.md` を、まとまりの順に、「1体が集約する出し直しのファイルの数」ずつの組に分ける（分けて書かれたものは、元のファイルと同じ組に入れる）。組ごとに `plugin-creator:idea-thinker` を1体起動する（同時に起動できる数の上限まで）。頼みの文には次を書く。
  - 役：本質の集約（1段目）
  - 読むファイル：組の `final-*.md`（すべての絶対パス）
  - やり方：言い換えを1つにまとめ、支持したエージェントの数を数える。議論の最後の合意ではなく、各エージェントが出し直した本質を集める。作品の機能をそのまま言い換えたもの、誰にどんなメリットがあるかを書けないものは外し、外した数を書く。本質ごとに「なぜ」の連なりを残す。「誰に」「どんなメリットが」「なぜそうなるか」は、「文の書き方」で書き直してよい（全文を写して渡す）。
  - 書くファイル：`<回のフォルダ>/essence/part-<組の番号>.md`（大きいときは `part-<組の番号>-2.md`…）。形は下の `index.md` と同じ。
  - 返事：本質の数と、外した数だけ。
- 2段目：`plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：本質の集約（2段目）
  - 読むファイル：`<回のフォルダ>/essence/part-*.md`（すべて）
  - やり方：組をまたいだ言い換えを1つにまとめ、支持の数を足す。本質ごとに「なぜ」の連なりを残す。「誰に」「どんなメリットが」「なぜそうなるか」は、「文の書き方」で書く（全文を写して渡す）。
  - 書くファイル：`<回のフォルダ>/essence/index.md`（大きいときは `index-2.md`…）。1つの本質を次の形で書く。

    ```markdown
    ## E<番号> <短い名前（人とメリットが分かる言葉）>
    - 誰に：<恩恵を受ける人>
    - どんなメリットが：<その人の生活や仕事の何が、どう良くなるか>
    - なぜそうなるか：<メリットを生む仕組み>
    - なぜ：<作品の番号> なぜ評価されているのか → <答え> → 誰にとって恩恵があるのか → <答え> …（たどり着いた連なりを1行で）
    - 裏づけ：<作品の番号か、過去の本質の K の番号と、引用>
    - 支持：<支持したエージェントの数>
    - 印：<仮説、過去の本質。なければ「なし」>
    ```

  - 返事：本質の数だけ。
- 本質の数が、パラメーターの本質の数より少なければ、`ask_user` で進め方を聞く（決める問い）。選択肢は「作品を足して続ける（おすすめ）」「今の数で進む」。おすすめの理由は「本質が多いほど、掛け合わせの組を選び直せる」。作品を足すときは、柱2の調べ直しと掘り下げを足りない分だけ行い、この柱の1からやり直す。

### 5. 終わり

- シェルで今の時刻を出し、`state.md` に「柱3の終わり：<時刻>」と書く。
- 本質の数、`essence/index.md` の場所、柱3にかかった時間をチャットに示す。`essence/index.md` から本質を2つ選び、「誰に」「どんなメリットが」「なぜそうなるか」を、そのまま写して示す。
- `knowledge-used.md` の「## 柱3」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
- `state.md` を「今の柱：4 本質の掛け合わせ」にし、`references/combine.md` を読む。
