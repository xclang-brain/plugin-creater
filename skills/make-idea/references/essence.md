# 柱3 本質の見極め（なぜなぜ分析）

目的：集めた作品に対し、「なぜ評価されているのか」「なぜこの形なのか」と、できる限り多くの疑問を投げかける。なぜなぜ分析を重ね、表面的な特徴の奥にある本質を探る。一人で完結させず、複数のエージェントで互いの分析に意見を出し合って、本質を磨く。洗練された本質をたくさん用意する。

この柱から後では、制限（`restriction.md`）を使わない。サブエージェントに場所も中身も渡さない（本文の先頭の決まり10）。

## なぜなぜ分析の形

- 作品ごとに、最初の問いを「なぜ評価されているのか」にする。答えは、柱2の掘り下げで集めた評価の材料（利用者の声、レビュー、論文の評価、採用の理由）の引用にもとづいて書く。
- 続けて「なぜこの形なのか」「なぜほかの作り方ではないのか」「なぜ使う人はそれを求めるのか」など、できる限り多くの疑問を投げかける。
- 答えに「それはなぜか」を重ねる。各段は、前の段の問いへの答えにする。各段に根拠（引用か作品の番号）を付け、根拠がない段には「仮説」と印を付ける。
- 止めるのは、段の数ではなく中身で決める。道具の機能を言い換えただけの段（「〇〇できるから」）では止めない。人の困りごと（誰が、何に、なぜ困るか）か、仕組みの原理（どの場面でも効く理由）に届いたら止める。段の数は、なぜを重ねる段の上限までにする。

  ```markdown
  ## <作品の番号> <作品の名前>
  - なぜ評価されているのか → <答え（引用）> → なぜか → <答え（根拠）> → なぜか → <人の困りごとか、仕組みの原理（根拠）>
  - なぜこの形なのか → …
  - たどり着いた本質：S<番号>
  ```

## 本質の形

- 本質は、目的（何のためか。誰の何の困りごとを解くか）と仕組み（どうやってそれを満たすか）で書く。
- たどり着いた「なぜ」の連なり（作品の番号と、段を「→」でつないだ短い形）を添える。
- 裏づけの作品の番号と、引用（README、レビューなど）を付ける。引用がないものは「仮説」と印を付ける。
- 目的と仕組みで書けないもの（例：使い心地）は、「形の外」と印を付けて残す。
- ほかの本質の言い換えは、別の本質として数えない。1つの本質を細かく割って数を増やさない。作品の機能をそのまま言い換えたものは、本質として数えない。

## 手順

### 1. 独立の分析

- シェルで今の時刻を出し、`state.md` に「柱3の始め：<時刻>」と書く。
- `knowledge/3-essence.md` を読み、使う項目を決める。過去の本質は、今回の作品で裏づけられなくても候補にする。優れた発明家は、事前調査の情報だけでなく、自分の過去の経験と知識からアイデアを作るためである。
- 分析の観点を、「なぜなぜ分析をするエージェントの数」だけ決める。観点は互いに違うものにする。例：使う人の困りごと、仕組みの原理、広まり方と使われ方。
- `plugin-creator:idea-thinker` を、観点ごとに1体、1つの応答で同時に起動する。頼みの文には次を書く。
  - 役：なぜなぜ分析
  - 自分の観点
  - 読むファイル：`<回のフォルダ>/research/deep-*.md`（すべて）、`<回のフォルダ>/research/index.md`、`<回のフォルダ>/research/overview.md`
  - やり方：上の「なぜなぜ分析の形」のとおりに、掘り下げた作品をすべて分析する（全文を写して渡す）。たどり着いた本質を、上の「本質の形」で書く。本質は、本質の数以上出す。
  - 使う知識・経験の項目（過去の本質の候補、役に立った問い方）。過去の本質は、今回の作品で裏づけられたら作品の番号を、裏づけられなければ「過去の本質（K…）」と出典を付けて出してよい。
  - 書くファイル：`<回のフォルダ>/essence/whys-<a>.md`（a はエージェントの番号）。自分でファイルに書く。20,000 バイトを超えそうなら、`whys-<a>-2.md`、`whys-<a>-3.md` に分けて書く。
  - 返事：出した本質の数と、書いたファイルの名前だけ。
- このとき、ほかのエージェントのファイルの場所は渡さない。互いを見ずに分析させるためである。
- 返事が「ファイルに書けなかった」なら、自分で書き写さず、書けなかった理由を `state.md` に書き、ファイルの名前を変えてもう一度同じ役を頼む。縮めて書き写すと、なぜの段が消えるためである。

### 2. 意見の出し合い（往復の数だけ繰り返す）

- 各エージェント a に、`plugin-creator:idea-thinker` を1体ずつ、同時に起動する。頼みの文には次を書く。
  - 役：ほかの分析への意見
  - 読むファイル：自分（a）の前の版の分析と、ほかのエージェントの前の版の分析（1回目は `whys-*.md`、2回目からは前の回の `final-*.md`。分けて書かれたものもすべて）
  - やり方：ほかの分析の主な主張を、まずいちばん強い形で言い直す。そのあと、相手ごとに次を書く。
    - なぜの浅さ：機能の言い換えで止まっている段、前の段の問いの答えになっていない段、根拠のない段。どの作品のどの段かを示す。
    - 根拠の弱いところ、言い換えにすぎない本質、見落とした本質、抽象的すぎる本質（例：「便利にする」）。
  - 書くファイル：`<回のフォルダ>/essence/opinion-<a>-r<k>.md`（k は何回目か）
- 次に、各エージェント a に、`plugin-creator:idea-thinker` を1体ずつ、同時に起動する。頼みの文には次を書く。
  - 役：本質の出し直し
  - 読むファイル：自分の前の版の分析、ほかのエージェントが書いた意見のファイル（`opinion-*-r<k>.md` のうち、自分あての部分）、`<回のフォルダ>/research/deep-*.md`（すべて）
  - やり方：意見を受けて、浅い段を掘り直し、本質を直し、足し、外して出し直す。本質ごとに「なぜ」の連なりを残す。ほかのエージェントの出し直しの結果は見ない。同調しないためである。
  - 書くファイル：`<回のフォルダ>/essence/final-<a>.md`（大きいときは `final-<a>-2.md`…）
  - 返事：出し直した本質の数だけ。

### 3. 集約

- `plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
  - 役：本質の集約
  - 読むファイル：`<回のフォルダ>/essence/final-*.md`（すべて）
  - やり方：言い換えを1つにまとめ、支持したエージェントの数を数える。議論の最後の合意ではなく、各エージェントが出し直した本質を集める。作品の機能をそのまま言い換えたものは外し、外した数を書く。
  - 書くファイル：`<回のフォルダ>/essence/index.md`（大きいときは `index-2.md`…）。1つの本質を次の形で書く。

    ```markdown
    ## E<番号> <短い名前>
    - 目的：
    - 仕組み：
    - なぜ：<作品の番号> なぜ評価されているのか → <答え> → <答え> …（たどり着いた連なりを1行で）
    - 裏づけ：<作品の番号か、過去の本質の K の番号>
    - 支持：<支持したエージェントの数>
    - 印：<仮説、形の外、過去の本質。なければ「なし」>
    ```
  - 返事：本質の数と、外した数だけ。
- 本質の数が、パラメーターの本質の数より少なければ、`ask_user` で進め方を聞く（決める問い）。選択肢は「作品を足して続ける（おすすめ）」「今の数で進む」。おすすめの理由は「本質が多いほど、掛け合わせの組を選び直せる」。作品を足すときは、柱2の調べ直しと掘り下げを足りない分だけ行い、この柱の1からやり直す。

### 4. 終わり

- シェルで今の時刻を出し、`state.md` に「柱3の終わり：<時刻>」と書く。
- 本質の数、`essence/index.md` の場所、柱3にかかった時間をチャットに示す。`essence/index.md` から本質を2つ選び、目的・仕組みと「なぜ」の連なりを、そのまま写して示す。
- `knowledge-used.md` の「## 柱3」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
- `state.md` を「今の柱：4 本質の掛け合わせ」にし、`references/combine.md` を読む。
