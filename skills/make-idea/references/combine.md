# 柱4 本質の掛け合わせによるアイデア創出（壁打ち）

目的：本質の中から使えそうな2〜4個を選んで掛け合わせ、新しいアイデアの案を作り、案を作ったエージェントとは別のエージェントに案をぶつけて磨く。評価されている作品をそのまま持ち寄るだけでは、新しいアイデアにはならない。本質を捉えていないものは、いくら組み合わせても良いアイデアにはならない。

## 言葉

- 組：一度に掛け合わせる本質の組み合わせ。
- 数：組に入れる本質の数。始めは「掛け合わせる数を変える順」の最初の数。
- だめな組：最後の判定で、通った案が1つもなかった組。

## 手順

1. `knowledge/4-combine.md` を読み、使う項目を決める（だめだった組の傾向、効いた組み方）。
2. `<回のフォルダ>/essence/index.md` を読む（本質の一覧だけを読む。作品の本文は読まない）。
3. 下の「1つの組」を、壁打ちした案の数が「壁打ちする案の総数」に届くまで、1つずつ繰り返す。組の番号は c01、c02…とする。
4. 組の結果ごとに、次の組の数を決める。
   - 通った案があれば、続けてだめな数を0に戻し、同じ数のまま次の組へ。
   - だめな組なら、続けてだめな数を1増やす。続けてだめな数が「同じ数で試す組の数」に届いたら、順の次の数にし、続けてだめな数を0に戻す。
   - 順の最後の数でも続けてだめな数が届いたら、`ask_user` で進め方を聞く（決める問い）。選択肢は「順の最初の数から組を選び直す（おすすめ）」「制限を見直す」「ここまでの通った案で説明に進む」。おすすめの理由は「本質の一覧にまだ試していない組が残っている」。
5. 止めたら、`<回のフォルダ>/combine/passed.md` を書く（通った案ごとに、番号、名前、1行の説明、組の番号、組の本質の番号）。通った案の一覧（番号、名前、1行）と、試した組の数、壁打ちした案の数、通った案の数をチャットに示す。
6. `knowledge-used.md` の「## 柱4」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
7. `state.md` を「今の柱：5 アイデアの説明」「次にすること：説明するアイデアを聞く」にし、`references/explain.md` を読む。

## 1つの組

1. 組を選ぶ：本質の一覧から、制限に効きそうで、互いに似ていない本質を、今の数だけ選ぶ。確かな本質（裏づけが多い）に、遠い分野の本質を1つ混ぜてよい。前に選んだ組と同じ組は選ばない。選んだ本質の番号と理由を `<回のフォルダ>/combine/log.md` に足す。
2. 案を作る：`plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
   - 役：案を作る
   - 読むファイル：`<回のフォルダ>/restriction.md`、`<回のフォルダ>/essence/index.md`
   - 組の本質の番号
   - やり方：組の本質を掛け合わせ、「1つの組から作る案の数」の案を作る。1つの本質だけで成り立つ案、作品をそのまま持ってきた案は作らない。案ごとに、番号（1から）、名前、誰が、どの場面で、何をするか、掛け合わせた本質がどう効くか、を同じ型と同じくらいの長さで書く。案ごとに違う使い手や制約を想定し、似た案を並べない。
   - 使う知識・経験の項目
   - 書くファイル：`<回のフォルダ>/combine/<組>/ideas-r0.md`
   - 返事：作った案の数だけ。
3. 壁打ち：`plugin-creator:idea-thinker` を「壁打ちの相手のエージェントの数」だけ、1つの応答で同時に起動する。案を作ったエージェントとは別の起動である。頼みの文には次を書く。
   - 役：壁打ちの相手
   - 読むファイル：今の版の案のファイル、`<回のフォルダ>/restriction.md`、`<回のフォルダ>/research/index.md`
   - やり方：案ごとに「通す」か「通さない」と、理由（どこが良いか、何が足りないか、どう直せばよいか）を書く。見る点は、必ず満たす条件を満たすか、良さを決める観点で良いか、作品の一覧に同じものが既にないか、1つの本質だけで成り立っていないか。ほかの相手の判定は見ない。誰が案を作ったかは考えない。
   - 書くファイル：`<回のフォルダ>/combine/<組>/judge-<p>-r<k>.md`（p は相手の番号、k は何回目の判定か。1から）
   - 返事：最後の1行に「通す：<番号をカンマで区切る>」だけを書く（なければ「通す：なし」）。
4. 直す（往復の数が2以上のとき）：判定が「壁打ちの往復の数」に届くまで、次を繰り返す。
   - `plugin-creator:idea-thinker` を1体起動し、役「案を直す」として、前の版の案と、その回のすべての判定のファイルを読ませ、指摘を受けて案を直させる。通した案も、良くできるなら直す。番号は変えない。書くファイルは `ideas-r<k>.md`（k は直した回数）。
   - 3と同じやり方で、相手（新しい起動）に直した案を判定させる。
5. 判定：最後の判定の返事の「通す：」の行から、案ごとに通した相手の数を数える。相手の数の半分より多くの相手が通した案を、通った案とする。
6. 記録：`combine/log.md` に、組の番号、数、本質の番号、作った案の数、通った案の番号を足す。壁打ちした案の数に、この組の案の数を足す。`state.md` に、組の番号、今の数、続けてだめな数、壁打ちした案の数を書く。

- 相手に、案を作ったエージェントのことや、直した案かどうかを伝えない。審査の偏りを減らすためである。
- 組は1つずつ試す。次の組の数が、前の組の結果で決まるためである。
