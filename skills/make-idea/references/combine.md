# 柱4 本質の掛け合わせによるアイデア創出（壁打ち）

目的：本質の中から使えそうな2〜4個を選んで掛け合わせ、新しいアイデアを作る。評価されている作品をそのまま持ち寄るだけでは、新しいアイデアにはならない。本質を捉えていないものは、いくら組み合わせても良いアイデアにはならない。できる限り多くの案を作り、案を作ったエージェントとは別のエージェントに案をぶつけて意見を受け取る。このやり取りを繰り返して洗練させる。壁打ちしてだめなら別の組を選び、それでもだめなら掛け合わせる数を変える。

この柱では、制限（`restriction.md`）を使わない。組の選び方にも、案作りにも、壁打ちにも使わない（本文の先頭の決まり10）。

## 言葉

- 組：一度に掛け合わせる本質の組み合わせ。
- 数：組に入れる本質の数。始めは「掛け合わせる数を変える順」の最初の数。
- だめな組：最後の判定で、通った案が1つもなかった組。
- 波：同時に試す組のまとまり。1つの波の組は、同じ数で選ぶ。組を1つずつ試すと、先行例の調べと壁打ちの往復で、1つの組に約50分かかり、10組で8時間を超えるためである。
- 先行例：案にいちばん近い既存のもの（製品、OSS、論文、特許など）。

## 壁打ちの3つの観点

壁打ちの相手は、案ごとに次の3つで判定する。3つともそろった案だけを通す。

| 観点 | 通すために示すこと |
| --- | --- |
| 新しさ | 先行例との違いが、案の価値の中心になっている。違いが細部の工夫だけなら通さない。先行例を使っている人が、この違いのために乗り換えるかで見る |
| 役立つか | 根拠のある困りごと（作品の利用者の声、レビュー、なぜなぜ分析でたどり着いた困りごとなど、出典のあるもの）に効く。出典のない場面・頻度・効果は「仮説」として扱い、それだけでは通さない |
| 価値 | その人や世の中にとっての大きさ（困っている人の多さ、困りごとの重さ、良くなる幅）に根拠がある |

## 手順

1. シェルで今の時刻を出し、`state.md` に「柱4の始め：<時刻>」と書く。`knowledge/4-combine.md` を読み、使う項目を決める（だめだった組の傾向、効いた組み方）。良さの判定を3つの観点のほかにする項目は使わない。
2. `<回のフォルダ>/essence/index.md`（分けて書かれたものもすべて）を読む（本質の一覧だけを読む。作品の本文は読まない）。
3. 波を、壁打ちした案の数が「壁打ちする案の総数」に届くまで繰り返す。1つの波では、「同時に試す組の数」だけ（総数に届くのに要る組の数がそれより少なければ、その数だけ）組を選び、下の「1つの組」を、組ごとの同じ段（案を作る、先行例を探す、壁打ち、直す）をそろえて進める。同じ段の起動は、波のすべての組の分を1つの応答で同時に行う。同時に起動できる数の上限で断られたら、終わるのを待ってから残りを起動する。組の番号は、波をまたいで c01、c02…と通しで振る。総数に届いても通った案が1つもなければ、止めずに4の決め方で組を選び直して続ける。説明する案がないと、柱5を行えないためである。
4. 波が終わったら、波の組の結果を組の番号の順にたどり、次の波の数を決める。
   - 通った案があれば、続けてだめな数を0に戻し、同じ数のまま次の組へ。
   - だめな組なら、続けてだめな数を1増やす。続けてだめな数が「同じ数で試す組の数」に届いたら、順の次の数にし、続けてだめな数を0に戻す。
   - 順の最後の数でも続けてだめな数が届いたら、それまでの結果（試した組の数、壁打ちした案の数、通った案の数、だめだった主な理由）を示し、`ask_user` で進め方を聞く（決める問い）。選択肢は「順の最初の数から組を選び直す（おすすめ）」「ここで止めて、後で続ける」と、通った案が1つ以上あるときだけ「ここまでの通った案で説明に進む」。おすすめの理由は「本質の一覧にまだ試していない組が残っている」。止めるなら、`state.md` を「状態：途中」のままにし、続け方（後で同じ頼みをすると続きから始められる）を示して終える。
5. 止めたら、`<回のフォルダ>/combine/passed.md` を書く（通った案ごとに、番号（組の番号と案の番号。例：c03-2）、名前、1行の説明、組の本質の番号）。最後の行に「通った案の数：<数>」と書く。
6. 比べる：`plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
   - 役：通った案を比べる
   - 読むファイル：`<回のフォルダ>/combine/passed.md`、通った案の組ごとの、いちばん新しい案（`combine/<組>/ideas.md`）、最後の判定（`judge-*-r<k>.md`）、最後の先行例（`prior-r<k>.md`）
   - やり方：組をまたいで重なる案（同じ困りごとに同じ仕組みで効くもの）をまとめる。上の3つの観点で比べ、良い順に並べる。上位「選ぶ一覧で詳しく示す案の数」までは、番号、名前、1行の説明、新しさ・役立つか・価値の要点（判定の根拠から1行ずつ）、いちばん近い先行例（名前と URL）を書く。ほかの案は、番号、名前、1行だけにする。
   - 書くファイル：`<回のフォルダ>/combine/ranked.md`
   - 返事：まとめた後の案の数だけ。
7. 試した組の数、壁打ちした案の数、通った案の数をチャットに示す。シェルで今の時刻を出し、`state.md` に「柱4の終わり：<時刻>」と書き、かかった時間も示す。
8. `knowledge-used.md` の「## 柱4」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
9. `state.md` を「今の柱：5 アイデアの説明」「次にすること：説明するアイデアを聞く」にし、`references/explain.md` を読む。

## 1つの組

1. 組を選ぶ：本質の一覧から、新しさと価値につながるように、今の数だけ選ぶ。同じ波の組どうしも、互いに似ていないものにする。例えば、根拠のある困りごとにたどり着いた本質と、別の分野の仕組みの原理の本質を組む。互いに似ていないものにする。確かな本質（裏づけが多い）に、遠い分野の本質や過去の本質を混ぜてよい。前に選んだ組と同じ組は選ばない。選んだら、案を作る前に、`combine/log.md` に組の行と「選んだ理由」の行を書く（下の6の形。通った案の欄は「（判定の前）」）。
2. 案を作る：`plugin-creator:idea-thinker` を1体起動する。頼みの文には次を書く。
   - 役：案を作る
   - 読むファイル：`<回のフォルダ>/essence/index.md`（分けて書かれたものもすべて）
   - 組の本質の番号
   - やり方：組の本質を掛け合わせ、「1つの組から作る案の数」の案を作る。1つの本質だけで成り立つ案、作品をそのまま持ってきた案は作らない。案ごとに、番号（1から）、名前、誰のどんな困りごとか（出典：本質の番号や作品の番号。出典がなければ「仮説」と書く）、どの場面で、何をするか、掛け合わせた本質がどう効くか、を同じ型と同じくらいの長さで書く。案ごとに違う使い手と困りごとを想定し、似た案を並べない。場面・頻度・数を、出典なしに作らない。
   - 使う知識・経験の項目
   - 書くファイル：`<回のフォルダ>/combine/<組>/ideas-r0.md` と、同じ中身の `<回のフォルダ>/combine/<組>/ideas.md`（壁打ちの相手が読む、いちばん新しい版）
   - 返事：作った案の数だけ。
3. 先行例を探す：`plugin-creator:idea-researcher` を1体起動する。案を作ったエージェントとも、壁打ちの相手とも別の起動である。頼みの文には次を書く。
   - 役：先行例を探す
   - 読むファイル：`<回のフォルダ>/combine/<組>/ideas.md`（直した回は、直した案の番号も書く）
   - やり方：案ごとに、いちばん近い既存のものを探す。案の仕組みを一般的な言葉に直した言い方、困りごとの言い方、英語と日本語など、少なくとも3つの言い方で探す。案ごとに、種類（製品、OSS、論文、特許）ごとに1行ずつ、使った検索語と結果を書く（特許は Google Patents などの特許の検索で探す）。見つけたものごとに、名前、URL、案と同じところ、違うところを、ページの事実で書く。見つからなかった種類も、検索語と「見つからなかった」を書く。案の良し悪しは書かない。
   - 書くファイル：`<回のフォルダ>/combine/<組>/prior-r<k>.md`（k は何回目の判定の前か。1から）
   - 返事：先行例を見つけた案の数だけ。
4. 壁打ち：`plugin-creator:idea-thinker` を「壁打ちの相手のエージェントの数」だけ、1つの応答で同時に起動する。案を作ったエージェントとは別の起動である。頼みの文には次を書く。
   - 役：壁打ちの相手（1番の相手は「だめな理由をいちばん強く示す相手」）
   - 読むファイル：`<回のフォルダ>/combine/<組>/ideas.md`、`<回のフォルダ>/combine/<組>/prior-r<k>.md`
   - やり方：上の「壁打ちの3つの観点」の表（全文を写して渡す）で、案ごとに新しさ・役立つか・価値を、根拠つきで1つずつ判定し、「通す」か「通さない」と、直し方を書く。3つともそろった案だけを通す。先行例の検索語が少ない案は、新しさを認めない。1番の相手は、案ごとに、だめな理由をいちばん強い形で先に書き、それに答えられる案だけを通す。ほかの相手の判定は見ない。誰が案を作ったかは考えない。
   - 書くファイル：`<回のフォルダ>/combine/<組>/judge-<p>-r<k>.md`（p は相手の番号、k は何回目の判定か。1から）
   - 返事：最後の1行に「通す：<番号をカンマで区切る>」だけを書く（なければ「通す：なし」）。
5. 直す：どの案も過半数の相手が通したか、判定の数が「壁打ちの往復の上限」に届くまで、次を繰り返す。波の中で、直し終えた組は待たずに抜けてよい。
   - `plugin-creator:idea-thinker` を1体起動し、役「案を直す」として、前の版の案と、その回のすべての判定のファイルと、先行例のファイルを読ませ、指摘を受けて案を直させる。先行例との違いを価値の中心にし、出典のない困りごとは出典を足すか、根拠のある困りごとに置き換える。通した案も、良くできるなら直す。番号は変えない。書くファイルは `ideas-r<k>.md`（k は直した回数）と、同じ中身の `ideas.md`（上書き）。返事は、直した案の番号だけ。
   - 3と同じやり方で、直した案の先行例を探し直す（`prior-r<k+1>.md`。直していない案の行は前の版から写すよう頼む）。
   - 4と同じやり方で、相手（新しい起動）に直した案を判定させる。
6. 判定：最後の判定の返事の「通す：」の行から、案ごとに通した相手の数を数える。相手の数の半分より多くの相手が通した案を、通った案とする。
7. 記録：`combine/log.md` の組の行の「通った案」を書き直す。壁打ちした案の数に、この組の案の数を足す。`state.md` に、組の番号、今の数、続けてだめな数、壁打ちした案の数を書く。

   ```markdown
   - c01｜波 1｜数 3｜E2、E7、E15｜作った案 10｜通った案：1、4、7
     - 選んだ理由：…
   ```

   通った案がなければ「通った案：なし」と書く。

- 相手に、案を作ったエージェントのことや、直した案かどうかを伝えない。相手に読ませるのは、いつも `ideas.md` と、その回の先行例である。審査の偏りを減らすためである。
- 次の波の数は、前の波の組の結果で決まる。波の中では数を変えない。
