# 柱1 制限の決定

目的：何のために、どの範囲でアイデアを考えるかを、ユーザーと決める。制限のない状態で、ただアイデアを出そうとしない。

## 決める項目

| 項目 | 中身 |
| --- | --- |
| 目的 | 何に困っていて、アイデアで何を良くしたいか |
| 範囲 | 対象の仕事、使う道具、環境（OS、エディター、CLI など） |
| 必ず満たす条件 | 満たさないアイデアは使えない、という条件 |
| あれば望ましい条件 | 満たすと良いが、なくても使える条件 |
| 良さを決める観点 | 何が減れば・増えればうれしいか。何があれば使わないか |

## 手順

1. `<データの置き場所>/knowledge/1-restriction.md` を読み、使う項目を決める（本文の「柱の一覧」のとおり）。
2. 候補を書き出す。頼みの文と、前の回の `restriction.md`（あれば、いちばん新しい回のもの）から分かることを、上の項目ごとに書き出す。頼みの文に書いてある言葉は、言い換えずにそのまま使う。
3. 足りない項目を聞く。候補で埋まらない項目だけを、1問ずつ自由入力で聞く。
   - 問いの例：「アイデアを使う場面が分からないと、関係のない分野まで調べてしまいます。アイデアを、どの仕事の、どんな場面で使いたいですか？」
   - 前の回の制限があるときは、初めに「前の回の制限（要点）を、今回も使いますか？違うところがあれば書いてください」と聞く。
   - 知識・経験の項目（例：範囲が広すぎて案がぼやけた）があれば、問いの文に活かす。決めるのはユーザーである。
4. 一覧で確かめる。決めた制限を、項目ごとに問いの文の中に書き、違うところと足りないところを自由入力で聞く（「上の」と指さない）。直しがあれば直して、もう一度確かめる。ユーザーが「このとおり」「よい」と答えたら決まりとする。
   - ユーザーが「決まっていない」「特にない」と答えた項目は、「決まっていない」と書く。推し量って埋めない。
5. 回のフォルダに `restriction.md` を書く。

   ```markdown
   # 制限
   - 短い名前：<知識・経験の「制限」に書く、10字ほどの名前>
   ## 目的
   ## 範囲
   ## 必ず満たす条件
   ## あれば望ましい条件
   ## 良さを決める観点
   ```

6. `knowledge-used.md` の「## 柱1」に、使った項目の番号と変えた判断を書く（なければ「なし」）。
7. `state.md` を「今の柱：2 徹底的な事前調査」「次にすること：事前調査の承認を聞く」にし、`references/research.md` を読む。
