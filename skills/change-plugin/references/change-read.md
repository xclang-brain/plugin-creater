# 段階「読む」（直すとき）

目的：元のプラグインと、ユーザーが示したスキルやファイルを読み取り役に読ませ、返ったものを記録する。そのうえで、引き継ぐことと変えるところ（範囲）と、今の決まりの一覧を確かめる。

`<make-plugin>/references/read.md` の「読ませ方」と「返ったものの記録」を使い、このファイルの手順を足す。read.md の「次へ」と、作り直しのための文は使わない。

## 1. 読み取り役に頼む

`task` ツールで `plugin-creator:reader` に、次の2つを並べて頼む（示されたスキルやファイルがなければ、1つ目だけ）。頼みの初めに、1つ目は「今のプラグインを直すときの読み取り」、2つ目は「組み込みたいスキルとファイルの読み取り」と書く。読み取り役は渡した文しか見えないので、次をすべて書く。

元のプラグインの頼み：

- `<P>` の絶対パスと、変えたいこと（記録の「変えたいこと」）
- 探すもの：
  - できていたこと（「〇〇と頼むと、〇〇をする」の形で、1つずつ）
  - 構成：スキル、エージェント、スクリプト、MCP サーバー、作業の画面の設定と表示の項目、試験の課題（`tests/eval/` の課題と、元からあるほかのテスト）
  - 決まりの候補（項目つき）と、人に聞く場面（AI が人に確かめたり、人の判断を待ったりするところ）
  - 流用できる部品と、読めなかったファイル
- plugin-creator が作ったプラグインのとき：決まりの一覧（下の4の一覧と同じ、番号と文）を頼みに書き、この一覧のどれにも当たらない決まりだけを、決まりの候補として返すよう書く。読むところは、作業ごとに違う部分（エージェントの定義の「作業ごとの指示」、入口のスキルの作業の節、README の「できること」と「使い方」、仕様書の作業ごとの要件、設計書の作業ごとの設計、ほかのスキル、スクリプト、作業の定義の task.json）に絞らせる。どのプラグインにも共通する文を、書き足された決まりと取り違えないためである。
- plugin-creator が作ったプラグインのとき：ひな形のフォルダ（`<スキルのフォルダ>/../../template/` の `..` を畳んだ絶対パス）も渡し、次の文は決まりの候補にさせない。候補にさせるのは、どちらにも当たらない、作業に固有の文（ユーザーが書き足したと見えるもの）だけである。plugin-creator が書いた文をユーザーの決まりかと聞いても、ユーザーには答えられないためである。
  - ひな形にある文（名前などが入っただけのものも）。ひな形のフォルダは、すべて読ませず、候補にする文があるかを検索させるだけにする（大きいため）
  - 一覧の決まりを言い換えた文と、一覧の決まりから出てくる文（例：役割を分ける決まりから来る、ある役がしないこと）

示されたスキルとファイルの頼み：

- 示されたフォルダとファイルの絶対パスと、変えたいこと
- 探すもの：
  - スキルごとに、`SKILL.md` のあるフォルダの絶対パスと、`name` と `description`
  - 決まりの候補（項目つき。出どころには、ファイルと節を書く）と、人に聞く場面
  - 資産の候補（スクリプトなど。絶対パスつき）と、前回の1回の手がかり
  - スクリプトごとの使い方（`--help` に出ること。引数、終了コード、出力の形など）。資産の候補のそのスクリプトの行の「何に使えそうか」に書かせ、決まりの候補にはさせない。スクリプトがそのとおりに動き、違えば断るので、ユーザーが決めることではないためである
  - ただし、スキルの文が守ることや既定として求めていることは、`--help` に出ていても、スクリプトがそうしていても、決まりの候補にさせる。今もそうしているかは、ユーザーにしか分からないためである
  - 読めなかったファイル

## 2. 返ったものの記録

read.md の表のとおりに記録し、次を足す。

| 返ったもの | 記録のしかた |
| --- | --- |
| 元のプラグインの決まりの候補 | 出どころは「既存のプラグインから読んで確かめた」、状態は「候補」。ひな形の文と、一覧の決まりから来る文は記録しない（1） |
| 示されたスキルとファイルの決まりの候補 | 出どころは「ファイルから読んで確かめた」、状態は「候補」 |
| 人に聞く場面 | 決まりの候補にする（文は「〇〇のときは、人に確かめてから進める」の形）。確かめで正しいと答えたものだけを、直す前の確認の振る舞いの案で、人に聞く場面にする |
| 示されたスキル | スキルごとに、`SKILL.md` のあるフォルダ（返った `SKILL.md` の絶対パスのフォルダ）の絶対パスを、`plugin-creator_record` の流用する資産の候補（名前はスキルの `name`）として記録する。スクリプトなどのファイルだけを記録しない。組み立てのスクリプトが、この記録で、示されたスキルと直した後のプラグインのスキルの名前が重ならないかを確かめるためである |
| スクリプトの使い方 | `--help` に出るだけのものは、読み取り役が決まりの候補として返しても、決まりの候補にしない。そのスキルの資産の候補の説明に、要点を書く。直す段階で、ルールのスキルに書かせる。スキルの文が守ることや既定として求めていることは、決まりの候補にする（1） |
| できていたことと構成 | ナレッジにしない（決まりの一覧に入れないため）。3の範囲の確かめの問いと、直す前の確認で使う |

- コンパクションの後に、できていたことが要るときは、`plugin-creator_state` を「振り返りの材料」つきで呼び、3の問いの文を問答の記録から拾う。

## 3. 範囲の確かめ（1つの問い）

できていたことと、今回変えるところを示し、違うところと足りないところを聞く（理解の確かめ）。機能ごとに要るかは聞かない。消すのは、ユーザーが消したいと頼んだ機能だけである。

- 問いの例：「直した後のプラグインは、今できていることをすべて引き継ぎます。引き継ぐことと変えるところが違っていると、要らないところまで直したり、直すべきところが抜けたりします。今のプラグインは、次のことができます。1. 〇〇と頼むと、〇〇をする 2. … 今回は、〇〇を足します（変える・消すものがあれば、それも書く）。ほかは今のまま引き継ぎ、お話を聞き直しません。違うところと足りないところを書いてください。なければ「ない」と書いてください。」
- 問いには、頼みと読み取りから分かる変えるところだけを書く。変えるかもしれないこと（画面の設定、ほかのルールなど）を、例として書き足さない。頼みにない変更を誘うためである。
- 答えに、元のプラグインや示されたスキルに書かれた決まり（書き足した決まりなど）が出ても、この答えで「決まった」にしない。一覧の決まりは4で、一覧にない決まりは段階「決まりの確かめ」で、1件ずつ確かめる。
- 答えで変えたいことが変わったら、`plugin-creator_change` を同じフォルダで呼び直し、変えたいことを置き換える（決まりは取り込み直されない）。
- この答えは、段階「項目の点検」で、「変えないので聞かない」にする項目の抜き書きに使う。

## 4. 決まりの一覧の確かめ（plugin-creator が作ったプラグインのときだけ。1つの問い）

- 一覧は、`<state.json>` の `knowledge` のうち、`carried` が true の行すべての番号と文である。`plugin-creator_state` の一覧は長い文と20件より後を切るので、使わない。
- 一覧のすべての番号と文を1つの問いの文の中に入れ（問いの前のチャットの文だけに書かない）、今と違うものと、古くなったものを聞く（理解の確かめ）。分けて聞かない。
- 範囲の確かめの答えで、番号や「ほかはそのとおり」と言われても、この問いは省かない。ユーザーは一覧の文をまだ見ていないので、その答えは一覧を確かめたことにならない。記録のツールも、一覧の番号を示した問いへの答えでないと、引き継いだ決まりを「決まった」にする記録を断る。
- 問いの例：「今と違う決まりや古くなった決まりが残っていると、AI が古いやり方で作業します。今のプラグインの決まりは次のとおりです。K-01 〇〇 K-02 〇〇 … K-17 〇〇。この中で、今と違うものと、古くなったものの番号を書いてください。なければ「ない」と書いてください。」
- 記録：
  - 違う・古いと答えなかった決まりは、`plugin-creator_record` で、番号を渡して状態を「決まった」にする。抜き書きは、この答えの言葉にする。まとめて1回で渡してよい。
  - 違う・古いと答えた決まりは、1件ずつ、今はどうかを聞く（聞き出す問い。例：「今のやり方が分からないと、AI は古い決まりのまま作業します。『K-05 〇〇』は、今はどうしていますか？決まりでなくなったなら、そう書いてください。」）。範囲の確かめの答えに今のやり方がもう書かれていれば、聞き直さず、その答えの言葉で記録する。
    - 今のやり方を答えたら、その番号を渡し、文（要れば項目・例・例外も）を答えのとおりに直して、状態を「決まった」、出どころを「ヒアリングの答え」にする。記録のツールが元の番号を外し、新しい番号を付ける（返り値に出る）。
    - 決まりでなくなった、決まっていないと答えたら、状態を「外した」にする。代わりの決まりの案を作らない。
  - 「ない」と答えても、決まりを足したことにはならない。
