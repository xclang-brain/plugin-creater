# 段階「始まり」（直すとき）

目的：直すフォルダと変えたいことを決め、フォルダを確かめてから、直すお話の記録を作る。ここに来るのは、本文の「始まりの手番」で、このセッションの記録がなかったときと、記録の段階が「始まり」のときである。記録にあること（直すフォルダ、変えたいこと）は、記録し直さない。記録を作る前に止まったときは、記録もフォルダの中身も変えない。

## 手順

1. 直すフォルダを決める。
   - 頼みが、手元にないプラグインを新しく作る頼み（例：「週報をプラグインにしたい」）なら、記録を作らずに、`skill` ツールで make-plugin を読み、そのとおりに進める。
   - 頼みや会話から分からなければ、自由入力の欄で聞く（問いの例：「直すプラグインのフォルダが分からないと、どのファイルを直すか決められません。直したいプラグインのフォルダの場所はどこですか？」）。
   - GitHub の URL を示されたときは、手元のフォルダを聞く（問いの例：「プラグインは、手元のフォルダのまま直します。まだ手元にないときは、git clone で手元に取ってきてください。そのフォルダの場所はどこですか？」）。
   - 元のプラグインのファイルの中身は、自分で読まない。読むのは読み取り役である。
2. フォルダを示して「作り直したい」とだけ頼まれ、元のフォルダを直すか、新しいフォルダに作るかの答えが会話にまだないときは、記録を作る前に、決める問いで聞く。記録を作ると、もう一方のお話を同じセッションで始められないためである。
   - 問いの例：「元のフォルダを直すか、新しいフォルダに作るかで、今のフォルダが変わるかどうかが決まります。どちらにしますか？」
   - 選択肢（この順）：「今のフォルダのまま直す（おすすめ）」「新しいフォルダに作り直す（今のフォルダは変えない）」。理由の例：git の履歴と今の入れ方がそのまま使え、変えないところに手を入れずに済むため。
   - 新しいフォルダと答えたら、記録を作らずに、`skill` ツールで make-plugin を読み、そのとおりに進める。
3. 何を変えるかが分からなければ（`/plugin-creator:change-plugin` だけで始めたときなど）、自由入力の欄で聞く（問いの例：「何を変えるかが分からないと、お話を聞くところを絞れません。このプラグインに足したいこと、変えたいこと、消したいことは何ですか？」）。
4. 受け付けない頼みを見分ける。
   - 受け付けるのは次の3つである。今使っているスキルを組み込むのは、スキルを足すことに入る。
     - スキルと、作業の画面の設定・表示を、足したり変えたりする
     - AI の組み方を変える（作業役の AI を足す、役割を分け直す）
     - ユーザーが要らないと言った機能を消す
   - 次の頼みは受け付けず、理由を示す。
     - まとめ役・作業役・確認役の AI に分ける形や、作業の画面など、plugin-creator が直したプラグインが守る形をなくす頼み（例：確認役の AI をなくす）。理由：作業役の AI が自分の成果物の合否を決めないよう、確認役の AI が別に判定する形を守るため。
     - どのプラグインにも共通する部分を、このプラグインだけ変える頼み（例：作業の画面の共通部分の配色）。理由：共通の部分は、どのプラグインでも同じ品質で動くよう、plugin-creator が用意しているため。表示の頼みなら、`<make-plugin>/references/screen.md` の部品の表から、近い部品を示す。
   - 頼みのすべてが受け付けられないときは、理由を示して止まる（記録を作らない）。一部だけなら、受け付けないものとその理由を示し、受け付けたものだけで進むと伝える。
5. フォルダを確かめる（読むだけで、何も変えない）。
   - 次を動かす：`python3 <S> change-check --plugin <フォルダ> --cwd <作業フォルダ>`
   - `"ok": false` なら、返った `problems` の文を、そのまま示して止まる。文には、直し方（実際のコマンド）が入っている。記録は作らない。直したら、もう一度頼むよう伝える。
   - `"ok": true` なら、返った `plugin`（フォルダの絶対パス）を `<P>` とする。
6. `plugin-creator_change` を呼ぶ。`folder` は `<P>`、`wants` は変えたいことの一覧（頼みの要約。1件に1つ）。
   - 記録が段階「始まり」で作られる。返り値で、引き継いだ決まりの数と、新しい決まりの番号がどこから付くかが分かる。「plugin-creator が作っていないプラグイン」と返ったら、以後は、作っていないプラグインのときの手順にする。
   - 断られたら、返った理由を示して止まる。
   - 新しく記録を作ったとき（「直すプラグインとして記録しました」と返ったとき）に `<W>` が残っていれば、前に途中で止まった直しの残りなので、消す。古い下見を使わないためである。
7. これからの流れを、words.md の言葉で短く示す。9で段階を進める前に、チャットの文に書く。画面の URL をまだチャットに書いていなければ、返り値から写して一緒に書く（ツールの返り値はユーザーに見えない）。
   - 示す例：「これから、次の順に進めます。今使っているスキルやファイルを教えてもらう → プラグインを読み、引き継ぐことと変えるところを確かめる → 今の決まりの一覧を確かめる → 変えるところを最近やった1回の流れを聞く → 読み取った決まりを確かめる → 聞き漏らしがないかを見る → 使っている道具（作業の画面を変えるときは、画面で見たいことも）→ 直す前に、まとめを確かめてもらう。そのあと、プラグインのフォルダを直して試験し、コミットします。push はしません。」
   - ユーザーが「スキル」と言っていないときは、「今使っているスキルやファイル」を「今使っているファイル」と言う（words.md）。
   - 作っていないプラグインでは、「今の決まりの一覧を確かめる」を除き、「最近やった1回の流れ」は作業の最初から最後まで聞くこと、作業の画面で見たいことも聞くことを示す。
8. 頼みの文から分かること（変えたいこと）は、仕事のやり方や決まりの候補にしない。変える範囲は、段階「読む」の範囲の確かめで、ユーザーの答えとして受け取る。頼みの文はユーザーの答えに数えられず、抜き書きに使えないためである。
9. `plugin-creator_progress` で段階を「実物を受け取る」に進め、`<make-plugin>/references/receive.md` を読む。
