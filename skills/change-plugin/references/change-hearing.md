# 段階ごとの違い（直すとき）

段階「実物を受け取る」から「生成前の確認」まで、`<make-plugin>/references/` のその段階のファイルに、ここに書いた違いを足して使う。違うところは、こちらを先にする。進む先は、本文の段階の表の「次へ」で決める。どの段階でも、本文の先頭の決まり2のとおり、頼みの文、それまでの答え、確かめた決まり、読んだファイルで分かること（構成、できていたこと、使い方と説明。読み取った決まりの候補は入らない）は聞き直さない。聞かなかったことは、直す前の確認で示して直してもらう。

## 実物を受け取る

- 元のプラグインのフォルダは受け取り済みである。頼みの文にある場所（組み込みたいスキル、ファイル）も受け取り済みとし、聞き直さない。その場所を、receive.md の「受け取り方」のとおり、流用する資産の候補として記録する（作業フォルダからの相対の場所は、絶対パスにする）。場所が見つからないときだけ、その場所を聞く。
- 聞くかどうかは、頼みの文と変更の種類だけで決める。この段階では、まだ何も読んでいないためである。問いは、次のどちらかのときだけ、receive.md の形で1つ出す。頼みにある場所は、問いに入れない。
  - 組み込むスキルや足す作業が受け取るデータのファイルの場所が、頼みの文にないとき（例：売上を集計するスキルを週報に組み込む頼みに、売上のデータの場所がない）。聞くのは、その作業で受け取るファイルと作るファイルである。試験の課題の入力になるためである。今使っているスキルは、問いに入れない。頼みにあるスキルの場所を聞き直す問いになるためである。
  - plugin-creator が作っていないプラグインのとき。変えるところの作業のファイルと、ほかに今使っているスキル（Copilot CLI や Claude Code のスキルのフォルダ）やプラグインのうち頼みにないものを、同じ問いで聞く。元のプラグインの外で使っているものは、読んでも分からないためである。
- ほかのとき（plugin-creator が作ったプラグインでの、役割の分け直し、機能を消す、画面だけの変更、受け取るファイルの場所が頼みにあるときなど）は、問わずに段階「読む」に進む。問わないことの説明は書かない。足す課題の入力は、直す前の確認の2つ目で仮のファイルとして示す。

## 前回の1回

- 聞くのは、変えるところに関わる作業の、最近の1回である（例：週報の書き方のスキルを組み込むなら、最近週報を書いた1回）。plugin-creator が作っていないプラグインでも同じで、作業の最初から最後までは聞かない。変えないところは、元のプラグインから読み取ったものを、直す前の確認で示す。
- last-time.md の進め方のうち、次の3つを使う。
  - 1：たどる問い。頼みの文に流れが書かれていれば、それを示して、書かれていないことだけを聞く。
  - 3：深掘り。聞くのは、時系列の抜け、判断が要った段、話に出たが中身の分からない手順だけである。deepen.md で「決まっていない」「知らない・思い出せない」として扱った点は、聞き直さない。
  - 6：初めての人が間違えそうなところ（1回。問いの言い方は変えない）。
- 次の問いは出さない。
  - 2の時系列の確かめと、7の要約。新しいことを示さず、決めることもないためである。記録したことは、直す前の確認の1つ目で示す。
  - 4の、読み取った候補と食い違うところをその場で聞く問い。決まりの確かめで、その候補の問いに「前回は〇〇でした」と添える。同じ点を2回聞かないためである。
- 5（話に出た手順や決まりを、その場で聞く）は、次のとおりにする。
  - 聞くのは、中身の分からない手順だけで、上の3の深掘りで聞く。ほかは聞かずに、last-time.md の「記録」のとおりに記録する。
  - ただし、話に出た手順や決まりが、読み取った候補と同じことなら、新しいナレッジにせず、その候補を `references/change-read.md` の2のとおりに扱う。ふだんのやり方を今の形で述べたもの（「いつも〜している」「必ず」など）は、決まりの確かめの始めに聞かずに「決まった」にし（作った後に書き足された決まりは、いつも聞く）、この1回にしたこととして話しただけのもの（「前回は〜した」、たどる中でだけ話した手順）は、決まりの確かめで4つの答えで聞く。たまたまのやり方を、決まりとして入れないためである。

## 決まりの確かめ

- 確かめるのは、状態が「候補」で、出どころが「ファイルから読んで確かめた」か「既存のプラグインから読んで確かめた」のものである。
  - plugin-creator が作ったプラグインから読んだ候補（作った後に書き足された行から来た決まりと人に聞く場面）は、いつも1件ずつ確かめる。頼みの文や答えに同じ中身があっても確かめ、「このとおり」か「そうしないときもある」と答えたら、頼みの文から記録した同じ中身の決まりを外す（`references/change-read.md` の2）。K の番号の付いた決まりや plugin-creator が書いた文から来る場面は、候補にしていないので聞かない。
  - 示されたスキルと、作っていないプラグインから読んだ候補は、始めに `references/change-read.md` の2のとおり、ユーザーが決まりとして述べたものを聞かずに「決まった」にする（違う今のやり方を述べたものは「外した」）。残りを1件ずつ確かめる。
- 決まりの一覧の決まりは、段階「読む」で確かめ終えている。書き足された文の候補は、一覧の決まりと同じ中身でも、1件ずつ確かめる。
- 前回の1回の話と食い違う候補は、問いに「前回は〇〇でした」と添える（問いの例：「ファイルから読み取った決まりが実際と違うと、AI が間違ったやり方で作業します。『〇〇は△△にする』という決まりですか？（〇〇.md の「ビルド」の節より。前回は□□でした）」）。
- 元のプラグインから読んだ候補に「違う」と答えたら、外す記録の抜き書きは、読み取った場所のままにする（答えは、本当のやり方の新しい決まりに残る）。その場所の文を、直す段階で消すためである。
- 4つの選択肢のどれでもない答え（「特に決まっていない」など）は、deepen.md の「決まっていない」の行より、次を先にする。
  - 自分でどれかに決めて記録せず、その答えの言葉を添えて、同じ4つの選択肢のどれに当たるかを1回だけ聞き直す。
  - 聞き直しても4つのどれでもなければ、正しいと答えていないので入れない（状態「外した」、抜き書きはその答え）。直す前の確認の1つ目で、確かめても決まらなかったので入れない決まりとして、文を示す。入れたいと答えたら、その番号を「決まった」にする。

## 項目の点検

items.md の進め方のうち、記録にあることを示して確かめ直す問い（1つ目の点）と、区切りの要約は使わない。確かめたことは、直す前の確認の1つ目で示す。plugin-creator が作ったプラグインでも、作っていないプラグインでも、次のとおりにする。

1. `plugin-creator_state` を呼び、10項目を、変えるところに関わる項目と、関わらない項目に分ける。変更の種類ごとの目安は次のとおりで、目安にない項目は、頼みの文か答えにその項目の変更が出たときだけ、関わる項目にする。
   - 今ある作業にスキルを組み込む：その部分の受け取るもの、進め方、成果物、合否の決め方、決まった書き方やルール、使う道具と環境
   - 新しい作業を足す：上の6つと、作業の目的、頼む場面と言い方、守らないと困ること
   - 役割の分け直し：進め方と受け取るもの（役の間の受け渡し）だけ
   - 機能を消す、画面だけを変える：なし（画面は、10項目と別の3つの項目である）
   - どの変更でも：作業のやり方の決まりのうち、決まりとして述べたので4つの答えで確かめなかったもの（頼みの文から記録したもの、聞かずに「決まった」にした候補）が1つでもあれば、項目「いつもと違うとき」は関わる項目に入れる。4つの答えの「そうしないときもある」で、例外を拾う機会がなかったためである。変える中身の決定（役割の分け方、足す表の列など）だけなら、入れない。
2. 関わらない項目は、聞かずに、`plugin-creator_progress` で「変えないので聞かない」にする。抜き書きは、頼みの文か、段階「読む」の問い（決まりの一覧の確かめか、範囲の確かめ）の答えから写す。
3. 画面の3つの項目は、plugin-creator が作ったプラグインで作業の画面を変えないときは「変えないので聞かない」に、作っていないプラグインでは「聞かずに案で示す」にする（下の「画面」）。抜き書きは、2と同じところから写す。
4. 関わる項目のうち、変える作業についての中身がもう分かっているものは、示さずに「聞いた」にする。分かっているとは、頼みの文、答え、確かめた候補、決まりの一覧の直し、記録した資産（示されたスキル、受け取ったファイル、使い方と説明）、読み取った構成のどれかで、その中身が分かることである。ナレッジとして記録したものに限らない（例：スキルを組み込む頼みなら、使う道具と環境はそのスキルである。実物の問いでデータの場所を答えていれば、受け取るものはそのデータである。頼みに表の列が書かれていれば、成果物はその表である）。ただし、5の1つ目に挙げた5つの項目は、読み取っただけでは「聞いた」にしない。
   - 抜き書きは、中身を示した頼みの文か答えから写す。読み取っただけで分かったもの（頼みにも答えにも中身がないもの）は、そのファイルやフォルダを示した頼みの文か答えから写し、読み取った中身を、直す前の確認の1つ目で「読み取ったこと」として示す。
   - 決まりの一覧で今のままと確かめた決まりは、新しい作業の項目を「聞いた」にする理由にしない。変える作業のことを言っていないためである。
5. 中身がまだ分からない関わる項目だけを、items.md の問いの例で、1項目ずつ聞く。
   - 目的、合否の決め方、守らないと困ること、いつもと違うとき、好みを推し量れても聞くのは、AI が推し量っただけのときである。ファイルから読み取っただけのときも、推し量りである。ユーザーが述べたことは、推し量りではない。
   - 合否の決め方は、変えるところで成果物が新しくなるか変わるときだけ聞く。成果物が変わらないとき（役割の分け直しなど）は、聞かずに「変えないので聞かない」にし、直す前の確認の2つ目で、決めた AI が動いたかを見る基準の案を示す（change-confirm.md の2）。
   - 作っていないプラグインで、元のプラグインに試験の課題がなく、作業全体の合否の決め方が、読み取ったものにも答えにもないときは、それを聞く。作業全体を試す課題の基準になるためである（change-confirm.md の2）。

## 資産と公開のプラグイン

- 資産：
  - ユーザーが示したもの（示されたスキルとそのスクリプトなど、頼みの文や答えにあるファイル）と、元のプラグインの部品は、聞かずに、`plugin-creator_record` で「流用する」にする。
  - assets.md の1の問いは、資産の候補に、ユーザーが示していないもの（前回の1回の話に出た道具やファイルなど）があるときだけ出す。一覧に入れるのは、そのものだけである。
  - 問いを出さないときは、項目「資産」を、場所を示した頼みの文か答えの抜き書きで「聞いた」にする。ユーザーが何も示していないとき（元のプラグインの部品だけのときなど）は、「聞かずに案で示す」にする（抜き書きは頼みの文）。
- 標準機能と公開のプラグイン：足す機能と変える機能について、assets.md の2のとおり調べる。
  - 使えるものが見つかったときだけ、assets.md の2の決める問いで聞く。
  - 見つからなかったときは聞かない（assets.md の2の、見つからなかったときの問いは使わない）。項目を「聞かずに案で示す」にする（抜き書きは頼みの文）。

## 画面

- plugin-creator が作ったプラグインで、作業の画面の設定や表示を変えるとき：今の設定と表示は引き継ぐ。screen.md の「最初からあるもの」の説明は省き、足すもの・変えるもの・消すものだけを聞く。3つの項目のうち変えないものは、「変えないので聞かない」にする。
- 作業の画面を変えないとき：この段階は使わない。3つの項目は、項目の点検で「変えないので聞かない」にしてある。
- plugin-creator が作っていないプラグイン：この段階は使わず、画面の設定と表示は聞かない。直した後のプラグインに足す作業の画面は、作業エージェント（plugin-creator:worker）が、元のプラグインから読み取ったことと頼みの文と答えから作業の定義の案を書き（change-confirm.md の2）、直す前の確認の3つ目で見本を示して直してもらう。3つの項目は、項目の点検で「聞かずに案で示す」にしてある。

## 生成前の確認

- 決まりの文の直し（change-confirm.md の2。`plugin-creator_confirm` を呼ぶ前）：
  - 決まったナレッジの文に、作り手への頼み（「〜と書いてください」など）や、どこに書くか（スキルか画面か）が入っていれば、作業する AI が従う決まりの形に直して記録する（番号を渡して直す）。作業エージェントは文を言い換えずに書くためである。
  - 決まりの文が、作業の画面の設定と同じものの値を固定で決めているとき（例：送り先を決まった値にする）は、その文を「頼みや画面に〇〇がなければ（決まりの値）」の形に直して記録し（番号を渡して直す）、振る舞いの案にも同じ使い方を書いて示す。決まりの文はそのままスキルや合格の条件に入り、案だけでは食い違うためである。
- change-confirm.md の3の1つ目に、次も示す。聞かなかったことを、ここで直してもらうためである。
  - ユーザーが頼みの文や答えで決まりとして述べたので、4つの答えで確かめなかった決まり：ほかの決まりと分けて、番号とユーザーの言葉の文で示し、例外（そうしないとき）があれば書き足せることを添える。
  - できていたこと（「〇〇と頼むと、〇〇をする」の一覧。引き継ぐことに入れるもの）。plugin-creator が作ったプラグインでは、ここで初めて一覧で示す。
  - 読み取ったこと：項目の点検で、読み取っただけで分かったので聞かずに「聞いた」にした項目と、その中身。
  - 流用する資産と、標準機能と公開のプラグインを調べた結果（見つからなかったときも、そのこと）。
  - AI が推し量ったことと、聞かずに案を作ったこと。決まりと分けて、そうと分かるように示す。
- confirm.md の1の2（「ほかにありますか？」）は、直すときも1回聞く。
